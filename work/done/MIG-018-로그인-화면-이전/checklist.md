### AC-3만 자동 검증이 없다

라우트의 `beforeLoad`는 현재 테스트 방식(최소 라우트 트리 + `createRoute`)으로 덮이지 않는다.
파일 라우트의 `Route` 객체를 그대로 끌어오려면 생성된 라우트 트리가 필요하고, 그러면 앱 전체가
딸려온다. 구현 자체는 legacy와 같은 형태(`beforeLoad`에서 토큰 확인 후 `redirect`)다.

**수동 스모크로 확인했다(§6).** 다만 회귀를 잡아 줄 자동 검증이 없다는 사실은 남는다 —
같은 공백이 MIG-005 Issue 4에도 그대로 적용된다(§5-③).

## 5. 중간에 막혔던 지점 — 스킬에 반영할 것

### ① 레포 밖에서 prettier를 돌리면 설정이 안 먹는다

포맷 실패의 원인을 가리려고 파일을 스크래치패드에 복사해 검사했다가 **기존 실패로 오판**했다.
prettier는 파일 위치를 기준으로 설정을 찾으므로, 레포 밖 사본은 항상 기본값으로 검사된다.

→ **`ai-validate`에 「기존 실패인지 확인할 때는 레포 경로에 옛 버전을 되돌려 놓고 검사한다」를
넣을 만하다.** `git show <커밋>:<경로> > <같은 경로>` 후 검사, 원본 복원이 정확한 방법이다.

### ② Changelog 한 칸에 문단을 쓰면 표 전체가 재정렬된다

markdown 표는 열 폭이 가장 긴 셀을 따라간다. 사유를 길게 쓰면 그 파일의 표 전체가 다시 정렬돼
**변경과 무관한 줄까지 diff에 들어온다.**

→ **`work-management.md`의 Changelog 규칙에 「사유는 한 문장. 긴 배경은 본문에」를 넣을 만하다.**

### ③ 라우트 `beforeLoad`는 현재 테스트 방식으로 덮이지 않는다

`ai-orchestrate` §5의 최소 라우트 트리 방식은 컴포넌트를 직접 붙이므로 파일 라우트의
`beforeLoad`가 실행되지 않는다. AC-3이 자동 검증에서 빠진 이유다.

→ 라우트 가드를 AC로 가지는 작업이 앞으로도 나온다(MIG-005 Issue 4가 그렇다).
**가드 검증 방법을 하네스 차원에서 정하는 게 좋다.** 후보는 생성된 라우트 트리를 쓰는 통합
테스트, 또는 판정 로직을 순수 함수로 분리해 단위 테스트하는 것이다.

### ④ Tailwind v4의 동적 spacing이 실제로 생성되는지 확인했다

`mt-13` `pt-22` `px-18` `w-18` 같은 값이 스케일에 정의돼 있지 않아 조용히 빠질 위험이 있었다.
빌드 산출 CSS에서 클래스 존재를 직접 확인했다(전부 생성됨).

→ **토큰이 아닌 수치를 처음 쓸 때는 `dist`의 CSS에서 클래스 생성을 확인하는 게 싸다.**
`className-convention.md`가 경고하는 "조용히 사라지는" 부류와 같은 성격이다.
