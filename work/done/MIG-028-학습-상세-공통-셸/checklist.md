### 타입 검사 실패 원인

루트 타입 검사는 이번 작업에 포함되지 않은 미추적 `apps/native/api/`에서 실패했습니다.

- `api/auth.ts`: 매개변수 `onResponse`의 암시적 `any`
- `api/index.ts`: 선언되지 않은 `onResponse`, 매개변수 `result`의 암시적 `any`, 문자열 인덱싱과
  `layout` 속성 오류

해당 파일은 수정하거나 스테이징하지 않았습니다. MIG-028이 변경한 웹 패키지는
`pnpm --filter @repo/web check-types`로 별도 확인해 통과했습니다.

### 경고

- 테스트의 `Window.scrollTo()` 미구현 메시지는 기존 jsdom 경고이며 테스트 결과에는 영향을 주지
  않았습니다.
- 빌드는 라우트 폴더의 기존 테스트 파일 2개와 500 kB 초과 청크를 경고했지만 정상 완료됐습니다.

### 의도적으로 바꾼 것

| 항목                                   | 이유                                                                     |
| -------------------------------------- | ------------------------------------------------------------------------ |
| 현재 항목에 `aria-current="page"` 추가 | 현재 위치를 보조 기술에도 전달하는 AC-2를 충족합니다.                    |
| 탐색 영역 이름을 「현재 위치」로 변경  | 영문 구현 이름 대신 사용자에게 의미 있는 한국어 이름을 제공합니다.       |
| `LinkProps`로 목적지 타입 확장         | 라우트 패턴과 `params`를 함께 받아 경로 변경을 타입 검사에서 발견합니다. |
| `PageHeading` 제목을 `h1`으로 제공     | 페이지의 주 제목이라는 의미를 코드에 반영합니다.                         |
| `PageTitleBar`에 `px-5` 적용           | Figma의 좌우 여백 20px을 반영한 시안 대조 수정입니다.                    |

legacy 원본은 후속 화면 이전이 끝날 때까지 참조 기준으로 남겨 둡니다.

### 중간에 막혔던 지점 — 스킬에 반영할 것

작업 범위 밖의 미추적 native 파일도 Turborepo 타입 검사에 포함되어 루트 검사가 실패했습니다.
전체 실패를 통과로 바꾸지 않고, 변경 패키지의 검사를 별도로 실행해 작업 영향과 사용자 변경을
구분했습니다. 여러 작업이 같은 워크트리를 공유할 때는 루트 검사 결과와 대상 패키지 결과를 함께
기록해야 합니다.
