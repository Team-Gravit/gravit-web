# REF-062 — 로그인 화면 진입 때 첫 화면 데이터와 코드를 미리 받기

GitHub Issue: #313

## 배경 · 목표

로그인한 사용자가 `/main` · `/learning`을 새로고침하면 아래 순서가 한 줄로 이어진다.

```text
앱 부팅 → 세션 복원(/auth/reissue) → 사용자 조회(/users) → 화면 코드 청크 → 첫 렌더 → 화면 데이터(useQuery) → 이미지
```

라우터는 모든 `beforeLoad`가 끝난 뒤에야 `loader`와 화면 코드 청크를 받는다(`router-core` 1.171 `load-client.js`).
`_authenticated`의 `beforeLoad`가 세션 복원과 사용자 조회를 기다리고, 화면 데이터는 컴포넌트가 그려진 뒤 `useQuery`가 요청한다.

`/main` 모바일 한 회차 (`local-docs/performance/records/2026-11-09-after-feat080.md`):

| 구간                 | 시각            |
| -------------------- | --------------- |
| `/auth/reissue`      | 2.33 – 2.56s    |
| `/users`             | 2.61 – 3.57s    |
| 화면 코드 청크 17개  | 3.62 – 5.25s    |
| 화면 데이터 7개 출발 | 6.59s           |
| FCP · LCP            | 7.67s · 약 8.0s |

**목표**: 화면 데이터와 화면 코드를 기다리는 구간과 겹치게 출발시켜 LCP를 줄인다. FCP는 나빠지지 않아야 하고, 화면이 보여 주는 상태는
그대로 둔다.

| 화면 (5회 중앙값)  | FCP   | LCP   | LCP 요소              | LCP가 기다리는 것          |
| ------------------ | ----- | ----- | --------------------- | -------------------------- |
| `/learning` 모바일 | 7.32s | 8.54s | 챕터 카드 장식 이미지 | 챕터 목록 응답 → 카드 렌더 |
| `/main` 모바일     | 7.72s | 7.98s | 히어로 장식 이미지    | 첫 렌더 (데이터와 무관)    |
| `/main` 데스크톱   | 7.87s | 8.16s | 우주 배너 이미지      | 첫 렌더 (데이터와 무관)    |

측정 조건: 목 API 빌드 · `vite preview` · 캐시 끔 · Fast 4G 근사 · CPU 4배 · 5회 중앙값. 절대값보다 같은 조건의 전후 비교에 쓴다.

## 범위

| 실행 이슈   | 내용                                                                                                                                               | 기대 효과                       |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| **Issue 1** | `/main` · `/learning` 라우트 `loader`에서 첫 화면 쿼리를 기다리지 않고 미리 요청한다. 훅과 `loader`가 같은 쿼리 옵션을 쓰도록 entity에 옵션을 둔다 | `/learning` LCP                 |

Issue 2는 인증 게이트를 건드리므로 Issue 1을 측정한 뒤 진행 여부를 정한다 (확인 필요 1).

## 용어 정의

| 용어         | 정의                                                                                  |
| ------------ | ------------------------------------------------------------------------------------- |
| 미리 요청    | `loader`에서 쿼리를 시작만 하고 기다리지 않는 것. 라우트 전환과 첫 렌더를 막지 않는다 |
| 첫 화면 쿼리 | 해당 라우트의 스크롤 전 화면에 보이는 위젯이 쓰는 쿼리                                |
| 쿼리 옵션    | 쿼리 키 + 조회 함수. 훅과 미리 요청이 같은 캐시 항목을 쓰려면 둘이 같아야 한다        |
| 인증 게이트  | `_authenticated` 레이아웃 라우트. 세션 확인 · 사용자 조회 · 온보딩 판정을 한다        |

## 현행 동작 기준선 (2026-11-09 코드)

### 첫 화면 쿼리

| 라우트      | 위젯 · 훅                                   | 정의 위치                                      | 조회 방식                    |
| ----------- | ------------------------------------------- | ---------------------------------------------- | ---------------------------- |
| `/learning` | `chapter-grid` · `useChapters`              | `entities/learning/api/use-chapters.ts`        | 생성 훅 + `select`           |
| `/main`     | `hero-greeting` · `useUserProfile`          | `entities/user/api/use-user-profile.ts`        | 생성 훅 + `select`           |
| `/main`     | `hero-greeting` · `useLeagueSummary`        | `entities/league/api/use-league-summary.ts`    | 생성 훅 재노출               |
| `/main`     | `learning-streak` · `useWeeklyRecord`       | `entities/learning/api/use-weekly-record.ts`   | 직접 조회 함수, 404 → `null` |
| `/main`     | `daily-mission` · `useDailyMission`         | `entities/mission/api/use-daily-mission.ts`    | 생성 훅 + `select`           |
| `/main`     | `recommended-units` · `useRecommendedUnits` | `entities/learning/api/index.ts`               | 생성 훅 재노출               |
| `/main`     | `continue-learning` · `useRecentLearning`   | `entities/learning/api/use-recent-learning.ts` | 직접 조회 함수, 404 → `null` |

404를 `null`로 바꾸는 두 훅은 생성 옵션과 같은 키에 다른 조회 함수를 쓴다. 미리 요청이 생성 옵션을 그대로 쓰면 같은 키에 다른 결과가
캐시되므로, 조회 함수까지 entity 한 곳에서 내보내야 한다.

### 인증 게이트 (`app/routes/_authenticated/route.tsx`)

`beforeLoad`: 세션 복원을 기다린다 → `failed`면 「다시 시도」 화면 → 토큰이 없으면 `/` → 사용자 조회(`staleTime: 'static'`) →
`USER_4041`이면 세션 삭제 후 `/` → 온보딩 판정에 따라 이동. 사용자 조회의 일시 장애는 「다시 시도」 화면이다.
`pendingComponent`는 `SessionCheckPending`, `pendingMs`는 300이다.

### 상태 (보존 대상)

로딩 = 위젯별 스켈레톤 · 오류 = `CardRetryStatus` · 빈 상태 = `CardStatus` · 성공 = 내용. 미리 요청은 요청 시점만 바꾼다.
데이터가 첫 렌더보다 먼저 도착하면 스켈레톤 없이 내용이 바로 보일 수 있다. 지금도 응답이 빠르면 같은 일이 일어난다.

### 고정하는 테스트

`pages/main/ui/main-page.test.tsx`, 위젯 테스트(`chapter-grid` · `learning-streak` · `daily-mission` · `recommended-units` ·
`continue-learning-card`), `app/routes/_authenticated/route.test.tsx`(인증 게이트 분기 전부).
