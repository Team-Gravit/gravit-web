# MIG-029 — 챕터 유닛 목록 이전

## 배경 · 목표

`/learning/chapters/$chapterId`는 현재 `component: () => null`인 자리 라우트다. `MIG-027`에서
챕터 카드의 목적지만 먼저 만들어 두고 화면 본체를 미뤘기 때문에, **학습 홈에서 챕터를 누르면
빈 화면이 나온다.**

legacy `/learning/$chapterId`의 관찰 가능한 동작을 기준선으로 삼아 `apps/web`에 옮기고
Figma `LRN-02`와 대조해 맞춘다. 상단 셸은 `MIG-028`이 이미 만들어 둔 것을 쓴다.

## 범위

| 레이어   | 산출물                                   | 내용                                      |
| -------- | ---------------------------------------- | ----------------------------------------- |
| entities | `model/chapter-unit.ts`                  | 응답 → 화면 모델. 순번 부여 · 진행률 보정 |
| entities | `api/use-units-in-chapter.ts`            | `getAllUnitInChapter` 래퍼                |
| entities | `ui/unit-list-item.tsx`                  | 리스트 행 (제목 · 설명 · 진행바 · 셰브론) |
| widgets  | `unit-list/`                             | 목록 조회 + 로딩 · 빈 · 에러              |
| pages    | `learning-chapter/`                      | 좁은 화면 · 넓은 화면 분기                |
| app      | `learning.chapters.$chapterId.index.tsx` | 자리 라우트를 페이지로 교체               |

## Out of Scope

- **유닛 상세(`/learning/units/$unitId`)** — `MIG-030`. 이번엔 링크 목적지로만 쓴다
- **공통 셸 수정** — `Breadcrumb` · `PageHeading` · `PageTitleBar`는 `MIG-028` 산출물을 그대로 쓴다
- **레이아웃 라우트 추출** — 세 화면이 실제로 같은지는 `MIG-030`까지 끝나야 확인된다 (별도 `REF-`)

### ③ 상태 커버리지

시안에 로딩·빈·에러 프레임이 **없다.** legacy에도 없다(L7). `MIG-027`이 학습 홈에서 정한 것과
같은 형태로 만든다 — 문구는 그 화면과 짝이 맞게 「유닛」으로 바꾼다.

| 상태 | 처리                                                          |
| ---- | ------------------------------------------------------------- |
| 로딩 | 행 모양 스켈레톤 (`aria-busy`)                                |
| 빈   | `role="status"` 「유닛이 없습니다.」                          |
| 에러 | `role="alert"` 「유닛 목록을 불러오지 못했어요.」 + 다시 시도 |

### ④ 배경·정렬 — 2026-09-17 추가 대조

최초 대조(2026-09-16)에서 **빠졌던 축**이다. `design-diff` §4의 6축(토큰·공용 컴포넌트·구조·
상태·문구·수치)은 배경 레이어를 요소로 세지 않아 목록에 오르지 않았다. `MIG-030`이 같은 누락을
겪고 공용 배경을 만들어 둔 것을 확인하면서 이 화면에도 적용했다.

| #   | 항목                | 구현 (대조 전)        | 시안                                            | 판정                                             |
| --- | ------------------- | --------------------- | ----------------------------------------------- | ------------------------------------------------ |
| B1  | 넓은 화면 배경      | `bg-bg-2` 단색        | 별·행성 일러스트 (`배경` 프레임 1920×2582)      | **고침 — `SpaceBackground variant="starfield"`** |
| B2  | 좁은 화면 배경      | `bg-bg-1` 단색        | 360폭 전용 `배경` 프레임 (`13750:50970`)        | **보류 — 확인 필요 2**                           |
| B3  | 넓은 화면 제목 좌표 | `px-22.5` (90px 고정) | x=90 (GNB 로고 92와 같은 선). 카드 컬럼은 x=360 | **고침 — 본문 컬럼으로. 확인 필요 3**            |
| B4  | 좁은 화면 제목 좌표 | `px-4` (16px)         | x=16. 목록과 같은 선                            | 유지 — 일치                                      |

B1의 크기 규칙: 내려받은 배경은 **알파 최댓값 0.2의 옅은 오버레이**로, 바탕색이 들어 있지 않다
(바탕은 시안 실측 `#F2F2F2` = `bg-bg-2`). 위를 기준으로 너비에 맞춰야 시안의 구도가 제자리에 오고,
이미지 아래쪽이 큰 장식으로 끝나 페이지가 더 길면 잘린 자국이 보인다. `bg-cover bg-top`은 화면이
이미지보다 낮은 동안 너비에 맞추고(= `100% auto`와 동일), 더 길어질 때만 확대해 채운다.
확대 구간에서는 좌우가 잘려 우측 장식이 화면 밖으로 나간다 — 폭 1440에서 유닛 약 9개, 1920에서
약 13개를 넘을 때부터다.

B3의 근거: 시안의 90px은 **고정값**이라 뷰포트 1384px 아래에서 제목이 목록보다 **오른쪽으로**
들어가 관계가 뒤집힌다(768px에서 제목 90 vs 목록 20). `MIG-030`(유닛 상세)이 같은 이유로 제목을
본문 컬럼 안에 두었으므로 학습 상세 두 화면의 판단을 맞춘다. 전 화면 여백선 정리는 `FIX-034`.

## 확정 명세 · 검증 기준

      Then 에러 문구가 사라지고 목록이 뜨며 요청이 정확히 2회 나간다

## 확인 필요 — 해결됨

1. **좁은 화면 `h1` 중복** (`MIG-028` §확인 필요 1에서 넘어옴) — **해결. `PageHeading`에
   `headingLevel` prop을 추가했다** (2026-09-16). 좁은 화면은 `PageTitleBar`가 `h1`을 갖고
   `PageHeading`은 `headingLevel={2}`로 낮춘다. 넓은 화면은 상단 바가 없어 `h1`을 유지한다.
   `PageTitleBar`를 `p`로 낮추는 대안은 학습 홈(좁은 화면)에서 `h1`이 사라지므로 택하지 않았다

## 확인 필요 — 미해결

2. **좁은 화면 배경** (B2) — `LRN-02-MOB`에는 360폭 전용 `배경` 프레임(`13750:50970`)이 있으나
   보유한 에셋 `starfield.webp`는 WEB 프레임(1920×2561, 2x 내보내기) 기준이라 360px에 깔면
   크게 확대된다. `MIG-030`도 같은 이유로 좁은 화면은 단색으로 두었다. **모바일 스케일 에셋을
   Figma에서 별도로 내보내야** 시안대로 맞출 수 있다. 그때까지 `bg-bg-1`을 유지한다.

3. **넓은 화면 제목 좌표** (B3) — 시안(1920)에서 벗어나는 판정이다. 시안은 제목을 GNB 로고와
   같은 선(90/92px)에 두고 카드 컬럼(360px)과 분리하지만, 두 값이 모두 고정이라 좁은 폭에서
   역전된다. `MIG-030`의 선례를 따라 본문 컬럼에 맞췄다. **두 선 체계를 유지할지는 `FIX-034`에서
   전 화면과 함께 판정한다** — 그쪽 결론에 따라 이 화면도 되돌릴 수 있다.

4. **유닛 순번 출처 변경** (2026-09-17) — `chore(web): Orval API 클라이언트 재생성 (#147)`
   (`06b47b6`)으로 `UnitSummaryResponse`에 `displayOrder`(「챕터 안에서의 유닛 순서 (1부터 시작)」)가
   들어왔다. 목록 위치에서 번호를 만들던 것을 서버 값으로 바꿨고, 계약 K1의 사유와 AC-2를 함께
   고쳤다. **`MIG-030`이 기다리던 필드가 이것이다** — 유닛 상세의 제목도 유닛명 대신 순번을 쓸 수
   있게 됐으므로 그쪽 「확인 필요 1」의 잠정 결정을 다시 볼 수 있다.
