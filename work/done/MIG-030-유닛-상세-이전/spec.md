# MIG-030 — 유닛 상세 이전 (레슨 목록)

## 배경 · 목표

`/learning/units/$unitId` 를 구현한다. `MIG-028`(학습 상세 공통 셸)이 만든 `PageHeading` 위에
레슨 목록과 목적지 진입 카드를 얹는다. 라우트 스텁은 이미 `develop` 에 있다
(`component: () => null`, 주석 "LRN-03(레슨 목록)을 이전할 때까지 유닛 카드의 목적지만 제공한다").

이 화면은 학습 흐름의 분기점이라, **레슨 풀이 · 북마크 문제 · 오답 문제 · 개념노트 네 목적지로
나가는 유일한 진입점**이다. 화면 자체보다 목적지 네 곳의 경로 계약을 먼저 확정해야
후속 이전 작업이 서로 어긋나지 않는다.

Figma 시안: [LRN-03 (node 13758-85559)](https://www.figma.com/design/hu4c6qCEMB62qHXk2v8Gsl/-New-Gravit?node-id=13758-85559)

## 범위

- 유닛 상세 화면 본체 — `pages/unit-detail/`
- 레슨 표시 컴포넌트와 조회 어댑터 — `entities/learning/` 에 추가
- `Chip` — `shared/ui/chip/` **신설**. 시안 3 variant 를 모두 정의하되 이번에 쓰는 것은 2종
- 목적지 4종의 **경로 계약 확정과 빈 라우트** — 경로·파라미터·레이아웃 그룹만 맞추고 본체는 비운다

## Out of Scope

- **문제 풀이 화면 3종의 내부 구현** (레슨 · 북마크 · 오답). legacy 기준 quiz feature +
  learning-widget 합계 약 1,500줄의 별도 서브시스템이며 각각 독립 `MIG-` 작업이다
- **개념노트 화면 내부 구현** — 마찬가지로 빈 라우트까지만
- **유닛 순번(`Unit01`) 확정** — 아래 확인 필요 1. 사용자가 서버 쪽을 확인 중이다
- **`학습 중` 칩 3종화** — API 에 데이터가 없다. 확인 필요 2
- **토큰 신설·정정** — 확인 필요 5. 이번에는 기존 토큰만 쓴다
- **에러 화면** — 전 화면 공통 관심사다. 확인 필요 4

## 용어 정의 (Ubiquitous Language)

| 용어       | 정의                                                                          |
| ---------- | ----------------------------------------------------------------------------- |
| 챕터       | 유닛의 상위 묶음. `chapterId` 로 식별                                         |
| 유닛       | 레슨의 상위 묶음. `unitId` 로 식별. **이 화면의 주인공**                      |
| 레슨       | 문제 묶음 하나. `lessonId` 로 식별. 풀이의 최소 단위                          |
| 유닛 순번  | 화면에 보이는 `Unit01` 의 `01`. **챕터 안에서의 순서**이지 `unitId` 가 아니다 |
| 목적지 4종 | 레슨 풀이 · 북마크 문제 · 오답 문제 · 개념노트                                |
| 풀이 화면  | 문제를 실제로 푸는 화면 3종. 개념노트는 풀이가 아니다                         |

## 라우트 계약 (이번에 확정한다)

`develop` 은 `/learning/chapters/{chapterId}` · `/learning/units/{unitId}` 처럼
**리소스 컬렉션 + 단일 ID** 형태로 통일했다. 목적지 4종도 같은 형태로 맞춘다.

`chapterId` 를 경로에 남기지 않아도 된다 — **`GET /api/v1/lessons/{unitId}` 응답이
`chapterSummary: { chapterId, title }` 을 함께 준다.** 경로 표시의 챕터명과 복귀 링크를
유닛 하나로 만들 수 있다.

| 목적지      | 제안 경로                                     | 파라미터   | 레이아웃 그룹 |
| ----------- | --------------------------------------------- | ---------- | ------------- |
| 유닛 상세   | `/learning/units/$unitId`                     | `unitId`   | `_app-shell`  |
| 개념노트    | `/learning/units/$unitId/concept-note`        | `unitId`   | `_app-shell`  |
| 레슨 풀이   | `/learning/lessons/$lessonId`                 | `lessonId` | `_focus`      |
| 북마크 문제 | `/learning/units/$unitId/bookmarked-problems` | `unitId`   | `_focus`      |
| 오답 문제   | `/learning/units/$unitId/incorrect-problems`  | `unitId`   | `_focus`      |

**레슨 풀이가 `/learning/lessons/$lessonId` 인 근거** — legacy 도 `lessonId` 만 쓴다(C1).
단일 ID 통일 방침과 일치하고, 레슨은 유닛과 독립적으로 식별된다.

**`_focus` 그룹** — `fsd-pages.md` §6-1 이 "인증 + 크롬 없음(전체화면)"에 대해
`_app-shell/` 밖 형제로 `_focus/` 를 두고 `createFileRoute` 경로로 URL 을 유지하라고 규정한다.
K1 을 구조로 강제한다.

## 확인 필요

> 기획 · Figma · 라우트 · API 계약이 서로 어긋나 **임의로 결정하면 안 되는 것**만 적는다.

1. **유닛 순번(`Unit01`) — 해소됨 (2026-09-18).**

   `GET /api/v1/lessons/{unitId}` 응답에 챕터 내 순번이 없어 유닛명을 제목으로 쓰기로 잠정
   결정했었다. `develop`(#235) 이 Orval 을 재생성하면서 `UnitSummaryResponse.displayOrder`
   (「챕터 안에서의 유닛 순서, 1부터」)가 생겨 전제가 사라졌다.

   **확정** — `toUnitLabel()` 이 `Unit${formatUnitNumber(displayOrder)}` 를 반환한다. 챕터 유닛
   목록(`UnitListItem`)이 쓰는 규칙과 같으므로 목록과 상세의 유닛 번호가 일치한다.

   **`unitId` 를 순번 자리에 쓰지 않는다**는 판단은 그대로다. `unitId` 는 챕터 내 순번이 아니라서
   화면에 **틀린 숫자**가 뜬다. `UnitCard` 는 아직 `Lesson {formatUnitNumber(unitId)}` 라서
   **같은 규칙으로 맞춰야 한다** (K3 — 이 작업 범위 밖).

2. **`학습 중` 칩 (D3·D6).** `LessonSummaryResponse` 는 `isSolved: boolean` 하나뿐이라 3번째 상태를
   만들 수 없다. 이번에는 2종만 쓰고 `Chip` 에 variant 3개를 정의해 둔다 —
   API 가 필드를 주면 **매핑 한 줄만 바꾸면 된다.**

3. **`bookmarkAccessible` · `wrongAnsweredNoteAccessible` 반영 여부 (D7·D8).** API 는 값을 주는데
   시안에 비활성 프레임이 없다. 지금은 풀 문제가 0건이어도 카드를 눌러 빈 풀이 화면으로 들어가는
   경로가 열려 있다. 레슨 0건 빈 상태도 시안에 정의가 없다.

4. **에러 표시 (D10).** TanStack Router 의 `errorComponent` 는 `__root` 와 라우트 레벨에 걸리는
   전 화면 공통 관심사다. 이 화면 전용 에러 UI 를 만들면 다음 화면이 또 자기 것을 만든다.
   별도 작업으로 다루되, 공통 에러 시안이 있는지 먼저 확인이 필요하다.

5. **토큰 (D11~D14).** `main-2` 값 불일치 · `bg-0` 부재 · shadow 토큰 부재 ·
   `--color-3` 이 정리 대상 대장에 "미사용"으로 잘못 분류돼 있는 것.
   `FIX-007`(색 토큰 5건 — 디자이너 확인 대기)과 **함께 묻는다.** 따로 두 번 묻지 않는다.

6. **화면 ID 매핑.** 이 프레임 이름은 `LRN-03` 인데 `docs/implementation-status.md` 는
   `L.1`~`L.10` 로 관리한다. `INFRA-031-학습-화면-명세-승격` 이 이미 to-do 에 있으므로
   거기서 함께 정리한다. 추측해 연결하지 않는다.

> **1~6 중 구현을 막는 것은 1번뿐이다.** 2·3 은 legacy 동작을 유지하면 되고, 4·5·6 은 별도 작업이다.

## 동일성 확인 방법

- **라우트 진입** — `/learning/units/{unitId}` 를 직접 열어 제목과 `문제 리스트` 섹션이 보이는지
- **이동 4종** — 네 카드/항목을 눌러 위 라우트 계약표의 URL 로 바뀌는지. 뒤로가기로 돌아오는지
- **셸 유무** — 풀이 화면 3종에서 헤더와 하단 탭바가 **보이지 않는지** (K1)
- **레슨 칩** — 이미 푼 레슨과 안 푼 레슨의 칩이 구분되는지 (K4)
- **경로 복귀** — 경로 표시의 챕터 항목이 `/learning/chapters/{chapterId}` 로 가는지 (K5)
- **반응형** — 좁은 화면에서 경로 표시가 사라지고 북마크·오답이 가로 2열이 되는지
- **기존 테스트** — legacy 에 이 화면 테스트는 없다
