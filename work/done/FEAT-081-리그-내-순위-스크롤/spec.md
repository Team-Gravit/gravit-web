# FEAT-081 — 리그 진입 시 내 순위로 센터링 + 양방향 무한스크롤

## 배경 · 목표

현재 리그 페이지는 랭킹을 1페이지부터 보여줄 뿐, **사용자 본인이 몇 위인지**를 바로 알려주지 않는다.
진입 시 내 순위 행이 리스트 중앙에 오도록 스크롤하고, 거기서 위(상위 등수)·아래(하위 등수)로
자유롭게 더 볼 수 있게 한다. 내 등수는 이미 `useMyLeagueProfile().rank`로 알 수 있다.

## 범위

- `entities/league` — 앵커 페이지 계산, 양방향 무한쿼리(내 티어 랭킹)
- `widgets/league-arena` — 랭킹 리스트 상/하단 센티넬, 초기 센터링, prepend 스크롤 보정, 내 행 강조
- `shared/lib/use-infinite-scroll` — 양방향(이전 페이지) 지원 (필요 시)

## Out of Scope

- **다른 티어(내 티어 아님)를 선택했을 때는 센터링하지 않는다.** 그때는 내 순위가 없으므로 기존대로
  1페이지부터 단방향으로 본다.
- around-me 등 신규 백엔드 엔드포인트 (기존 `/page/{n}`으로 충분)
- 랭킹 행 응답 타입 확정 — 그건 `INFRA-024`의 몫. 이 작업은 현재 `LeagueRankRow`에 의존한다
- 카운트업·파티클 등 화려한 연출 (아래 `확인 필요` 참고)

## 용어 정의 (Ubiquitous Language)

| 용어         | 정의                                                             |
| ------------ | ---------------------------------------------------------------- |
| 앵커 페이지  | 내 순위가 속한 0-based 페이지. `floor((rank - 1) / PAGE_SIZE)`   |
| 센터링       | 내 순위 행을 스크롤 컨테이너 세로 중앙에 위치시키는 것           |
| prepend 보정 | 상단에 페이지가 삽입될 때 보이는 위치가 튀지 않게 scrollTop 조정 |

## 기술 결정 (ADR)

### 데이터 확보 — 기존 page 엔드포인트 + 양방향 무한쿼리

**Context** — 내 순위가 깊어도(예: 92등, 347등) 그 행을 중앙에 띄워야 한다. 현재 API는
`/ranking/leagues/{id}/page/{n}`으로 `pageNum`만 받고 `size`·offset·around-me가 없다.

**Decision** — 페이지 크기 10이 고정이고 내 등수를 이미 아니까, 앵커 페이지를 클라에서 계산한다
(`floor((rank-1)/10)`). 양방향 무한쿼리로 `initialPageParam=앵커`, `getPreviousPageParam`(위)·
`getNextPageParam`(아래)을 둔다. 앵커±1을 선로딩해 어느 위치든 중앙 정렬, 최상/최하단은 끝 정렬.

**Alternatives**

| 안                           | 거부 이유                                                    |
| ---------------------------- | ------------------------------------------------------------ |
| A. 1페이지부터 순차 로딩     | 깊은 등수에서 요청 waterfall(1000등=100req). 느리고 janky    |
| B. around-me 신규 엔드포인트 | 백엔드 변경 필요. page size 기지라 클라 계산으로 충분해 과함 |

**Consequences** — 백엔드 손 안 대고 지금 구현 가능. **단** page size 10을 클라가 가정하므로,
서버 default가 바뀌면 앵커 계산이 조용히 틀어진다(아래 확인 필요 4). 또 양방향·prepend 보정으로
리스트 로직 복잡도가 올라간다.

### 스크롤 튐 처리 — 수동 보정 1차

초기 센터링은 완성된 리스트에서 1회 위치 지정이라 튐 없음. **사용자가 위로 스크롤해 이전 페이지가
prepend될 때만** `useLayoutEffect`에서 `scrollTop += (늘어난 scrollHeight)` 보정. `overflow-anchor`는
`scrollbar-hide`와의 상호작용이 불확실해 수동 보정을 1차로 둔다.

## 확인 필요 (⏸ 게이트 판정 결과)

1. **Figma 시안** — ✅ 판정: **시안 없음(2026-11-09 확인).** `design-source-policy §7`대로 동작만
   구현하고 개선 판단을 하지 않는다. 나중에 시안이 생기면 별도 작업에서 대조한다.
2. **애니메이션 범위** — ✅ 판정: **smooth 스크롤만.** `scrollIntoView({ behavior: 'smooth',
block: 'center' })`. 카운트업 등 연출은 범위 밖.
3. **내 행 강조** — ✅ 판정: **강조 안 함.** 내 행은 센터링 대상(ref)일 뿐, 시각적으로는 다른 행과
   동일. `user-rank-row.tsx` 수정 없음.
4. **페이지 크기 10 고정 계약 (병행)** — `size` 쿼리가 없어 클라에서 핀할 수단이 없다. `PAGE_SIZE`
   상수 1곳으로 관리하되, 백엔드에 default 고정 확약 또는 응답에 size 포함을 **요청해 둔다.**
5. **`INFRA-024`와의 순서 (병행)** — 랭킹 행 타입 미확정. FEAT-081은 현 `LeagueRankRow` 위에
   올리고, 교체 지점을 주석으로 표시한다.

## 확정 명세 · 검증 기준

> 위 `확인 필요`가 판정된 뒤 확정한다. 아래는 현재 가정 기준 초안.

- [ ] **AC-1** (단위) Given `rank=1`→앵커 `0`, `rank=10`→`0`, `rank=11`→`1`, `rank=92`→`9`,
      `rank=100`→`9`, `rank=101`→`10` When `getAnchorPage(rank)` Then 각 좌변 값을 반환한다
- [ ] **AC-2** (통합) Given 내 티어·`rank=92` When 리그 진입 Then 92위 행이 스크롤 컨테이너
      중앙 부근에 오고, 그 위에 80위대·아래에 100위대 행이 존재한다
- [ ] **AC-3** (통합) Given 센터링 완료 상태 When 위로 스크롤해 상단 센티넬 교차 Then 이전 페이지가
      로드되고 **보이는 행의 화면상 위치가 유지된다**(튀지 않는다)
- [ ] **AC-4** (통합) Given 내 티어가 아닌 다른 티어 선택 When 리스트 표시 Then 센터링 없이 0페이지부터
      단방향으로 보인다(기존 동작)
