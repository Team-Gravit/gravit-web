# FIX-020 구현 계획

> `spec.md`에 배경·현재 상태·범위·Out of Scope·AC가 있다. 여기서는 영향 분석 · 판정 · 구현
> 순서 · 리스크만 적는다.

## 1. 브랜치

`feat/#203/login-screen`에서 분기했다. 두 페이지 자체는 `develop`에 있지만
**`shared/ui/layout/page-header.tsx`가 `#203`에만 있다.** 사용자가 그 `PageHeader`를 쓰라고
지정했으므로 `#203` 위에서 작업한다. FIX-019와는 형제 브랜치이고 서로 의존하지 않는다.

## 2. 사용자가 준 설계 지침 (2026-09-10)

게이트에서 판정이 필요했던 항목을 사용자가 직접 정해 주었다.

| 항목             | 판정                                                                      |
| ---------------- | ------------------------------------------------------------------------- |
| 좁은 화면 여백   | `px-4` · `py-5`                                                           |
| 상단바           | 로그인에서 만든 **`PageHeader`**를 쓴다. `TopAppBar`를 새로 만들지 않는다 |
| 상단바 좌측 슬롯 | `chevron-left` 아이콘, 크기 **24**                                        |
| 넓은 화면        | 좁은 화면과 **디자인이 달라야 한다**                                      |

넓은 화면은 현행(워드마크 로고 헤더 + `max-w-[800px]` 본문)을 유지한다. 시안이 없어
`design-source-policy.md` §7에 따라 새 판단을 하지 않는다.

## 3. 현재 상태 실측

```
terms-page.tsx    className 40개
privacy-page.tsx  className 66개  ← 표·링크가 더 있다
```

`spec.md`의 현재 상태 표에 **없던 것이 privacy에서 더 나왔다.**

| 추가 발견                              | 개수 | 문제                      |
| -------------------------------------- | ---: | ------------------------- |
| `text-blue-600 hover:underline` (링크) |    6 | 토큰 아님 (Tailwind 기본) |
| `border-gray-300` (표 테두리 · 구분선) |    9 | 〃                        |
| `bg-gray-100` (표 헤더)                |    1 | 〃                        |
| `text-lg font-semibold` (h3)           |    2 | 타이포 토큰 아님          |

AC-1이 금지어로 `font-semibold`를 포함하므로 **강조 문단 9개도 토큰으로 바꿔야 한다.**

## 4. 공통화 판정 — 추출한다

`spec.md`가 "두 화면이 같은 구조를 반복하므로 공통 문서 레이아웃 추출 여부를 착수 시 판단"
하라고 남겼다. `refactor-checklist.md`의 공통화 판단을 적용한다.

| 확인 항목 | terms ↔ privacy                          |
| --------- | ----------------------------------------- |
| 개념      | 같다 — 긴 본문 하나짜리 고지 문서         |
| 입력      | 같다 — 제목 + 산문 블록                   |
| 변경 이유 | 같다 — 디자인 시스템이 바뀌면 함께 바뀐다 |
| 수명      | 같다 — 둘 다 서비스가 사는 동안 유지된다  |

네 가지가 모두 일치한다. "2번 등장은 인라인" 휴리스틱보다 이 확인이 우선이다.
추출하지 않으면 **반응형 헤더 분기와 여백 규칙이 두 파일에 복제**되어 한쪽만 고쳐진다.

**새 슬라이스를 만들지 않는다.** 기존 `shared/ui/layout` 슬라이스에 파일 하나를 더한다
(현재 `page-header.tsx` · `space-background.tsx`가 있다).

### `Footer`는 넣지 않는다

`widgets/footer`를 `shared`가 import하면 상향 참조라 훅이 차단한다. 페이지가 조립한다.

## 5. 타이포 매핑

좁은 화면 기준으로 정하고 `md:`로 넓은 화면을 올린다.

| 요소             | 좁은 화면                     | 넓은 화면                        | 색            |
| ---------------- | ----------------------------- | -------------------------------- | ------------- |
| `h1` 문서 제목   | `text-title3` (24)            | `md:text-title1` (32)            | `text-text-1` |
| `h2` 절 제목     | `text-heading2` (20)          | `md:text-heading1` (22)          | `text-text-1` |
| `h3` 하위 제목   | `text-headline2` (17)         | `md:text-headline1` (18)         | `text-text-1` |
| `p` · `li` 본문  | `text-body2-reading` (15/1.6) | `md:text-body1-reading` (16/1.6) | `text-text-2` |
| 강조 문단        | `text-headline2`              | `md:text-headline1`              | `text-text-1` |
| 링크             | `text-main`                   | —                                | —             |
| 표 테두리·구분선 | `border-divider-1`            | —                                | —             |
| 표 헤더 배경     | `bg-bg-2`                     | —                                | —             |

**`reading` 계열을 쓰는 이유** — 줄 높이가 1.6이다. 긴 법적 문서라 `normal`(1.5)보다 읽기 쉽다.

## 6. 구현 방식 — 컨테이너 descendant 선택자

요소마다 클래스를 붙이면 `h2` 22개 · `p` 20개에 같은 문자열이 반복된다. 대신 컨테이너에
`[&_h2]:...` 형태로 한 번만 선언한다. `shared/ui/button`이 이미 `[&_svg]:...`로 쓰는 방식이라
새 패턴이 아니다.

여백(`mt-8 mb-3` 등)은 **기존 값을 그대로 인라인에 남긴다.** 이번 작업은 타이포·색 정합이지
여백 재설계가 아니다. 진짜 바뀌는 건 컨테이너의 좁은 화면 패딩뿐이다.

## 9. `h1` 중복 처리

`PageHeader`는 `title`을 `h1`으로 렌더한다(로그인 좁은 화면의 문서 제목이었다).
여기서는 본문에 이미 「서비스 이용약관」 `h1`이 있어 그대로 두면 `h1`이 둘이 된다.

→ **`PageHeader`를 고치지 않는다.** 대신 본문 제목을 좁은 화면에서 숨기고(`md:` 이상에서만
표시) 상단바 제목이 그 역할을 하게 한다. 넓은 화면에는 상단바가 없으므로 본문 `h1`이 산다.
어느 화면에서도 `h1`은 정확히 하나다.
