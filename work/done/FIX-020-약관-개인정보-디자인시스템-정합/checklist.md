## 4. 무엇이 바뀌었나

### 4-1. 공통 레이아웃 추출

`shared/ui/layout/document-layout.tsx` 신규. **새 슬라이스가 아니라 기존 슬라이스에 파일 추가**다
(`page-header.tsx` · `space-background.tsx` 옆).

`refactor-checklist.md`의 공통화 판단 4항목(개념·입력·변경 이유·수명)이 두 화면에서 모두
일치해 추출했다. "2번 등장은 인라인" 휴리스틱보다 이 확인이 우선한다.

`Footer`는 넣지 않았다 — `shared`가 `widgets`를 import하면 상향 참조다. 페이지가 조립한다.

### 4-2. 타이포·색 토큰화

| 대상                 | 전                             | 후                                                             |
| -------------------- | ------------------------------ | -------------------------------------------------------------- |
| 문서 제목            | `text-2xl font-bold`           | `text-title3 md:text-title1`                                   |
| 절·조 제목 (22개)    | `text-xl font-semibold`        | `text-heading2 md:text-heading1`                               |
| 하위 제목 (2개)      | `text-lg font-semibold`        | `text-headline2 md:text-headline1`                             |
| 본문 `p` · `li`      | 지정 없음(브라우저 기본)       | 컨테이너에서 상속 — `text-body2-reading md:text-body1-reading` |
| 강조 문단 (5개)      | `<p class="font-semibold">`    | `<h4>` — 목록 앞 소제목이라 의미도 맞다                        |
| 인라인 강조 (2개)    | `<span class="font-semibold">` | `<strong>`                                                     |
| 날짜·메타 (5개)      | `font-semibold`                | `text-label1 text-text-3`                                      |
| 표 테두리·구분선 (9) | `border-gray-300`              | `border-divider-1`                                             |
| 표 헤더 배경         | `bg-gray-100`                  | `bg-bg-2`                                                      |
| 본문 링크 (6개)      | `text-blue-600`                | `text-main` (컨테이너의 `[&_a]`)                               |

**여백은 손대지 않았다.** `mt-8 mb-3` 같은 값은 그대로다. 이번 작업은 타이포·색 정합이지
여백 재설계가 아니다.

### 4-3. 하위 선택자 대신 상속을 쓴 이유

처음엔 `[&_p]:text-body2-reading`처럼 하위 선택자로 본문을 지정하려 했다. **그러면 자식에
직접 붙인 클래스가 안 먹는다** — `[&_p]:...`는 특이도가 (0,1,1)이고 자식의 클래스는 (0,1,0)이라
하위 선택자가 이긴다. 강조 문단 같은 예외를 만들 수 없다.

컨테이너에 본문 타이포를 두고 **상속**시키면 자식 클래스가 언제나 이긴다.
제목만 하위 선택자로 지정한다 — preflight가 `h1`~`h6`의 크기·굵기를 지워서 상속으로는
살아나지 않기 때문이다.

## 5. `h1`이 둘이 되는 문제

`PageHeader`는 `title`을 `h1`으로 렌더한다. 본문에도 문서 제목 `h1`이 있어 좁은 화면에서
`h1`이 둘이 될 뻔했다.

→ **제목 렌더를 `DocumentLayout`이 가져갔다.** 좁은 화면은 상단바가, 넓은 화면은 본문
머리글이 `h1`이 된다. 어느 쪽에서도 정확히 하나다. `PageHeader`는 고치지 않았다.

## 6. 기존 테스트를 고친 것 — 명세 변경이라 함께 바꿨다

「헤더 로고 링크가 홈으로 향한다」가 좁은 화면에서 깨진다. 좁은 화면에는 로고 헤더가 없고
뒤로 가기 버튼이 대신 오기 때문이다. **사용자가 지시한 설계 변경의 직접적 결과**이므로
`test-policy.md` §6에 따라 테스트를 지우지 않고 **넓은 화면 조건으로 한정**한 뒤,
좁은 화면용 검증을 새로 추가했다.

jsdom에는 `matchMedia`가 없어 `useIsWideViewport()`가 항상 `false`를 반환한다.
그래서 두 테스트 모두 `stubViewport()`로 폭을 고정한다 — `login-page.test.tsx`와 같은 방식이다.

## 6-1. 푸터를 좁은 화면에서 뺐다

사용자가 확인 중 **푸터가 폭과 무관하게 뜬다**고 지적해 추가로 고쳤다. 확인해 보니 이전부터 그랬고
(MIG-004 기준선 6번이 조건 없이 "하단에 Footer 표시") 이번 작업이 만든 회귀는 아니다.

그런데 `widgets/footer`는 **넓은 화면 전용 레이아웃**이다.

```
footer  pt-[50px] pb-[100px]
  div   px-[150px]        ← 좌우 합 300px. 360px 화면이면 내용에 60px 남는다
```

→ **넓은 화면에서만 마운트한다**로 확정(사용자 판정).

### 별도 레이아웃 vs 조건부 — 조건부로 간다

| 방식                                    | 판단                                                                               |
| --------------------------------------- | ---------------------------------------------------------------------------------- |
| 화면을 wide/narrow 둘로 분리 (로그인식) | ❌ 본문 230줄이 **양쪽 동일**하다. 로그인은 배경·구조·문구가 달라서 나눴다         |
| 껍데기만 둘로 분리                      | ❌ 다른 건 헤더·푸터 2개뿐인데 `main` 컨테이너와 타이포 규칙이 복제된다            |
| CSS로만 (`hidden md:block`)             | ❌ 헤더 2개·`h1` 2개가 DOM에 남고, jsdom은 CSS를 안 봐서 **테스트가 구분 못 한다** |
| **한 레이아웃 + 최소 분기**             | ✅ 채택                                                                            |

**JS는 CSS로 표현이 안 되는 두 가지만 가른다** — 어느 헤더를 쓸지, 푸터를 마운트할지.
여백·타이포처럼 연속적으로 변하는 값은 계속 `md:` 클래스가 처리한다.

`hidden`이 아니라 **마운트를 안 하는** 이유: 푸터에 `logo-appcenter.png`가 있어 숨기기만
하면 좁은 화면에서도 이미지를 내려받는다.

`shared`가 `widgets`를 import할 수 없으므로 `DocumentLayout`은 `footer`를 **노드로 받는다.**
무엇을 넣을지는 화면이 정하고, 언제 보일지는 레이아웃이 정한다.

테스트로 고정했다 — 두 화면 각각 「푸터는 넓은 화면에만 렌더된다」(`contentinfo` 역할).

> ⚠️ 이 지적은 작업 폴더를 `done/`으로 옮긴 뒤에 들어왔다. `work-management.md` §5는 done
> 폴더를 고치지 말라고 하지만, **PR도 만들기 전의 같은 브랜치 연속 작업**이라 새 ID를 따지 않고
> 여기에 덧붙였다. 지운 내용은 없다. 커밋은 `git-workflow.md` §2-1에 따라 한 개로 합쳤다.

| 좁은 화면 여백 | 768px 미만에서 `px-4 py-5`가 실제로 적용되는지           | ⬜   |
| 상단바         | 제목과 뒤로 가기 chevron 크기(24)가 시안 감각에 맞는지   | ⬜   |
| 뒤로 가기 동작 | 눌렀을 때 `/`로 이동하는지                               | ⬜   |
| 넓은 화면 회귀 | 로고 헤더·본문 폭·타이포가 이전과 크게 달라지지 않았는지 | ⬜   |
| 표 (privacy)   | 좁은 화면에서 가로 스크롤이 동작하는지                   | ⬜   |
| 푸터           | 넓은 화면에만 보이고 좁은 화면에서는 안 보이는지         | ⬜   |

**시안이 없는 화면이다.** `design-source-policy.md` §7에 따라 개선 판단을 하지 않고
기존 토큰 안에서 가장 가까운 값을 골랐다. 눈으로 보고 조정이 필요하면 알려 주면 된다.

## 8. 확인 필요 — 사용자 판정 대기

1. **본문 최대 폭 `800px`** — `spec.md`가 남긴 미결이다. 토큰이 아니라 임의값인데
   **그대로 유지했다.** 읽기 좋은 줄 길이라 근거가 있고, 바꿀 근거(시안)가 없다.
   토큰으로 승격할지, 다른 값으로 바꿀지는 판정이 필요하다.
2. **본문 링크가 색으로만 구분된다** — `text-main` + `hover:underline`이라 마우스를
   올리기 전에는 밑줄이 없다. 색만으로 링크를 구분하면 WCAG 1.4.1에 걸린다.
   항상 밑줄로 바꾸는 게 맞지만 **개선 판단이라 이번 범위에서 손대지 않았다.**
3. **`z-[110]` 제거됨** — 옛 헤더에 있던 값인데 근거를 찾지 못했다(겹치는 요소가 없다).
   `DocumentLayout`에는 넣지 않았다. 필요했던 이유가 있으면 알려 주면 되돌린다.
