## 중간에 막혔던 지점 — 스킬에 반영할 것

- **상태 표시줄 0으로만 재서 앱 실기기 선을 놓쳤다.** #358 이음새 측정이 `--safe-area-top` 0 조건뿐이라 아이폰(47px)에서 히어로가 그림보다 길어져 생긴 선을 출시 후 제보로 알았다. `box-content` + `pt-(--safe-area-top)` 화면의 배경을 바꾸면 `--safe-area-top`을 0 · 24 · 47 · 59px로 바꿔 캡처한다 → 이미지 · 배경 변경 검증 절차(`image-convention.md` §6)에 넣을 만하다
- **계획의 「같은 장식」 전제가 시안 확인 없이 적혀 있었다.** Issue 4는 착수 직전 시안을 열어 보고 범위를 다시 잡았다. 노드 이름(`lesson-result-bg-mobile`)을 리그 모바일로 잘못 적은 것도 그때 드러났다. 시안 노드는 계획에 적을 때 이름 · 크기까지 한 번 확인한다
- **목업에 없는 응답은 측정 빌드에서 막힌다.** `/learning` 챕터 목록은 MSW가 통과시켜 실제 서버로 나가 실패했다. 서비스 워커 · 페이지 단 가로채기는 둘 다 안 잡혔고, 측정 빌드만 `VITE_API_BASE_URL`을 로컬 고정 응답 서버로 바꿔 해결했다(기준 · 변경 같은 조건)
- **헤더가 카드를 덮어 픽셀 비교가 95%로 나왔다.** 고정 헤더 아래 요소를 캡처할 때는 먼저 화면 가운데로 스크롤한다
- **개발 서버에서 페이지를 오갔다 돌아오면 장식이 1초 늦게 뜬다 — 빌드에서는 없다.** `vite-imagetools`는 개발 서버에서 `/@imagetools/…`를 요청마다 다시 변환(약 1초)하고 캐시 헤더 없이 준다. 그래서 다시 마운트되면 브라우저가 새로 요청해 그라데이션만 보이다가 장식이 얹힌다(5180 재현: 글자 126ms · 장식 1,226ms). 빌드 결과물은 서비스 워커 유무 · 배포와 같은 `max-age=0, must-revalidate` 모두 돌아올 때 요청 0건, 글자와 장식이 같은 프레임이었다. `decoding="sync"`로 고치려다 효과가 없어 되돌렸다 → 이미지 로딩 체감은 빌드(`vite preview`)로 확인한다
