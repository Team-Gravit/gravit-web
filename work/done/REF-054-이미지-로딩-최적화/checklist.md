- 형식 · 린트 · 타입은 verify가 테스트 단계까지 갔으므로 통과

## 중간에 막혔던 지점 — 스킬에 반영할 것

- **「기존 테스트 통과」로 적은 AC가 실제로는 테스트가 없었다.** #350 AC-1(리그 `<source media>` · 덮개)과 #353 AC-2(온보딩 완료 마스코트 `alt=""`)는 이슈를 쓸 때 기존 테스트가 이 단언을 한다고 가정했는데, 검증 때 보니 해당 파일이 그 내용을 보지 않아 검증 단계에서 테스트를 추가했다. → `refactor-planner` §5에 「AC에 기존 테스트를 근거로 적을 때는 그 테스트의 `it` 이름까지 적는다」를 넣는 게 좋겠다
- **픽셀 비교 기준을 처음부터 너무 빡빡하게 잡았다.** 「최대 n/255」는 압축 · 경로 재작성이 들어가면 테두리 몇 픽셀 때문에 거의 항상 깨진다. 두 번(#355 · #356) 기준을 바꿨다. → 이미지 형식 변경 AC는 처음부터 「8/255 넘는 픽셀 비율」로 쓴다. FIX-073 확인 필요 4로 이미 넘김
- **이슈 전제가 계산 한 번으로 무너지는 경우가 두 번 있었다.** #352(애니메이션 webp는 이미 프레임 차이 압축) · #360(배너가 항상 높이 기준 cover). 둘 다 이슈를 쪼개기 전에 「표시 크기 · 파일 구조」를 먼저 계산했다면 이슈로 만들지 않았을 것이다. → 이미지 작업은 이슈 분해 전에 cover 기준 축과 애니메이션 구조를 먼저 확인한다
- **Git Bash에서 `/learning` 같은 인자가 Windows 경로로 바뀐다.** 측정 스크립트가 invalid URL로 실패했다. `MSYS_NO_PATHCONV=1`로 해결(측정 도구 README에 기록)
