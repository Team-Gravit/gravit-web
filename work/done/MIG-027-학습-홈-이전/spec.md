# MIG-027 — 학습 홈 이전

## 배경 · 목표

`apps/web`의 `/learning`은 「학습 화면 준비 중」만 띄우는 스텁이다
(`pages/learning/ui/learning-page.tsx`).

그런데 도달 경로는 이미 세 곳에서 살아 있다 — 바텀탭 「학습」, 메인 「이어서 학습하기」의
빈 상태 CTA(`continue-learning-card.tsx:43`), 메인 「연속 학습일」의 빈 상태
CTA(`learning-streak.tsx:37`), 메인 「새 주제 시작하기」의 「전체보기」(`recommended-units.tsx:46`).
**즉 MIG-025로 메인을 살린 결과, 사용자가 학습을 시작하려고 누르는 링크가 전부 막다른 길이다.**

legacy `/learning`의 관찰 가능한 동작을 기준선으로 삼아 `apps/web`에 FSD 구조로 옮기고,
Figma `LRN-01`과 대조해 어긋난 부분을 맞춘다.

## 범위

| 대상             | 내용                                                       |
| ---------------- | ---------------------------------------------------------- |
| 챕터 목록        | `GET /api/v1/chapters` 조회 · 카드 그리드 · 로딩/빈/에러   |
| 챕터 카드        | 제목 · 진행률 게이지 · 행성 이미지 · 설명 툴팁 · 카드 링크 |
| 탭               | 「개념학습」·「면접대비」 (§시안 대조에서 동작 여부 판정)  |
| 좁은 화면 헤더   | 「학습」 제목 바                                           |
| 넓은 화면 히어로 | 인사말 히어로 (`widgets/hero-greeting` 재사용 여부 판단)   |
| 라우트           | `learning.index.tsx`의 스텁 교체 · 학습 하위 URL 평탄화    |

넓은 화면(WEB 시안)과 좁은 화면(MOB 시안) 양쪽을 구현한다. `MIG-025`와 같은 구조다.

### 확정된 학습 링크

- 메인 「전체 학습화면 보기」와 챕터 카드 → `/learning/chapters/$chapterId`(유닛 목록)
- 「N강 이어서 학습하기」와 유닛 카드 → `/learning/units/$unitId`(레슨 목록)

「전체 학습화면 보기」도 다음 유닛으로 보내던 `MIG-025` AC-14는 링크 문구와 목적지를 맞추기 위해
위 기준으로 대체한다(2026-09-16 사용자 판정).

## Out of Scope

- **`/learning/chapters/$chapterId` (LRN-02 유닛 목록)** — 카드 목적지. 이번엔 자리 라우트만 두고
  화면 본체는 다음 작업에서 만든다 (2026-09-16 사용자 결정)
- **`/learning/units/$unitId` 이하 전부** — LRN-03·04, QUIZ-01~08, 오답노트, 북마크
- **인증 게이트** — `MIG-005`. `_authenticated`의 `beforeLoad`는 그쪽 범위
- **면접대비 콘텐츠** — legacy에 화면이 없다. 탭 UI의 존치 여부만 이번에 판정하고,
  콘텐츠는 `/interview`와 함께 별도 `FEAT-`로 다룬다
- **헤더 · 바텀탭 위젯 자체** — `FEAT-026`에서 이미 만들었다. 이번엔 사용만 한다

## 동일성 확인 방법

- **목록 렌더** — `/learning` 진입 후 카드 개수가 `GET /api/v1/chapters` 응답 길이와 같고, 제목 순서가 응답 순서와 같은지
- **진행률** — 같은 챕터에 대해 메인 「이어서 학습하기」의 진행률과 학습 홈 카드의 「{n}%」가 일치하는지
- **이동** — 카드를 눌렀을 때 주소창이 `/learning/chapters/{그 카드의 chapterId}`가 되는지
- **로딩** — 응답을 지연시켰을 때 스켈레톤 카드가 6장 뜨는지
- **빈 상태** — 빈 배열 응답에서 「챕터가 없습니다.」 계열 문구가 뜨는지 (문구는 시안 대조 후 확정)
- **에러 · 재시도** — 500 응답에서 `role="alert"`가 뜨고, 「다시 시도」를 누르면 요청이 한 번 더 나가는지 (MSW로 요청 횟수 검증)
- **기존 테스트** — legacy에는 이 화면의 테스트가 없다. `apps/web` 쪽도 현재 스텁이라 없다

## 기준선을 쓰면서 발견한 것

> 현행 동작이 아니라 **관찰**이다. 판정은 시안 대조와 게이트에서 한다.

1. **「면접대비」 탭이 죽어 있다.** 클릭 대상이 `<li>`이고 핸들러가 없다. 탭처럼 보이지만 탭이 아니다.
   시안에 면접대비 상태가 있는지에 따라 「구현 누락」인지 「시안에 없는 장식」인지가 갈린다 (§확인 필요 1)
2. **`border-text-main`은 존재하지 않는 토큰이다.** 활성 탭 밑줄에 쓰였는데 `--color-text-main`이
   양쪽 앱 어디에도 없다. 같은 요소의 `text-main` 덕분에 글자색이 상속돼 **우연히** 보라 밑줄이 되고 있다.
   레포 전체에서 이 한 곳만 쓴다
3. **`getPlanetImage`가 `chapterId === 9`에서 깨진다.** `isPlanetId`는 1~9를 통과시키는데
   `PLANET_IMAGES`에는 8개뿐이라 9번은 `undefined`가 되어 `<img src={undefined}>`가 된다.
   `apps/web`의 대응물(`entities/learning/ui/planet-images.ts`)은 `undefined`를 반환하고
   `UnitCard`가 `planet ? … : null`로 막아 이미 더 안전하다. 현재 챕터가 몇 개인지는 확인하지 못했다
4. **`ChapterCard`의 `status` prop(`available`·`completed`·`locked`)을 이 화면은 한 번도 넘기지 않는다.**
   항상 `available`이라 「완료」·「잠김」 표현은 실행되지 않는 코드다. 시안에 잠금 상태가 있는지 확인이 필요하다 (§확인 필요 2)
5. **카드 하나가 망가지면 목록 전체가 사라진다** (C6). `mapToChapter`가 항목 단위로 throw하는데
   그게 `queryFn` 안이라 쿼리 전체가 에러가 된다. 서버 계약상 세 필드는 non-null이므로 실제로 발생할지는 별개다
6. **`apps/web`에 재사용할 대응물이 이미 상당히 있다** — `shared/ui/card`, `shared/ui/progress-bar`
   (`LabeledProgressBar`), `shared/ui/skeleton`, `entities/learning/ui/planet-images.ts`,
   `widgets/hero-greeting`. legacy의 `BgCard`·`HeroSection`·`MainSectionError`를 그대로 옮길 필요는 없어 보인다
7. **legacy 히어로가 학습 홈과 메인에서 같은 컴포넌트다.** `apps/web`에서는 `widgets/hero-greeting`이
   메인 전용으로 만들어져 있다. 학습 홈이 이걸 그대로 쓸 수 있는지는 시안의 히어로 유무에 달렸다

### 확인 필요

**3건 모두 2026-09-16에 판정됐다.** 상세는 아래 「시안 대조 결과」.

1. ~~**「면접대비」 탭**~~ → **판정: 탭 행 전체를 제거한다.** 시안 WEB에는 비활성 탭으로 존재하지만
   동작하지 않고, MOB 시안에는 탭 행 자체가 없다. WEB에서만 탭 행이 차지하던 68px을 여백으로 남긴다
   (S1 · S2). 면접대비 콘텐츠는 `/interview`와 함께 별도 `FEAT-`로 다룬다
2. ~~**챕터 잠금 상태**~~ → **판정: 없다.** 시안에 잠금·완료 표현이 없으므로 `status` 개념을

1. **진행바가 WEB·MOB에서 다른 것이 의도인가 (T8).** 단색 16px vs 그라데이션 8px다. 의도가 아니라면

### 자동 테스트로 덮지 않은 것 — 수동 확인 대상

시각 스타일은 테스트하지 않는다 (`test-policy.md` §1). 아래는 사람이 본다.

- 넓은 화면: 히어로(274px) → 68px 여백 → 4열 그리드(최대 1200px, gap 24)
- 좁은 화면: 상단 「학습」 바(48px) → 2열 그리드(gap 12, 좌우 16)
- 넓은 화면 진행바가 16px 단색, 좁은 화면이 8px 그라데이션
- 카드에 딤이 상시 깔리고, 마우스를 올리면 행성이 기울며 커진다
- 헤더가 히어로 위에 겹쳐 뜬다 (`overlay`)
