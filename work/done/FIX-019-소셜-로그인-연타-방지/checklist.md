## 4. 착수 시 판정한 것 — 로딩 표현

`spec.md`가 "비활성만 걸지, 로딩 표현까지 넣을지"를 착수 시 판정하라고 남겼다.
**`Button`의 기존 관용구를 재사용하는 쪽으로 정했다** (`plan.md` §4).

- 시안에 로딩 상태 프레임이 없어 **새 디자인을 만들지 않았다**
- 대신 이 레포에 이미 있는 표현을 그대로 썼다 — 레이블 자리를 남기고 `Spinner`를 겹치고
  `aria-busy`로 알린다. `shared/ui/button/button.tsx`와 같은 방식이다
- 비활성만 걸면 브랜드색 버튼에 `disabled:` 색이 없어 **눌렸는지 구분이 안 된다.**
  연타는 막히지만 "반응 없음"으로 읽혀 다른 버튼을 누르게 된다

### `invisible contents`를 쓴 이유

`Button`은 래퍼에 `inline-flex`를 준다. 여기서는 쓸 수 없다 — provider 로고가
narrow에서 **버튼 기준 `absolute`**로 배치되고 wide에서는 **버튼의 flex `gap`**을 받기 때문에,
래퍼가 자체 박스를 가지면 두 배치가 모두 깨진다. `display: contents`는 박스를 만들지 않고
`visibility: hidden`은 자식에게 상속되므로 배치를 유지한 채 숨길 수 있다.

## 5. 수동 스모크 — 남음

| 확인             | 절차                                                | 상태 |
| ---------------- | --------------------------------------------------- | ---- |
| 스피너 표시      | 실제 클릭 → 스피너가 보이고 버튼 크기가 안 변하는지 | ⬜   |
| 이동             | 스피너 상태에서 인가 페이지로 넘어가는지            | ⬜   |
| narrow/wide 배치 | 두 크기 모두 로딩 중 로고·레이블 위치가 유지되는지  | ⬜   |

자동 검증으로 덮이지 않는다. **브라우저 확인이 필요하다.**
