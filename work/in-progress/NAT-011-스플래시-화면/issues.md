# NAT-011 이슈 분해

`spec.md`의 ADR과 「플랫폼 전제」·「검증 전제」를 전제로 한다.
**AC의 정본은 이 문서다.** `spec.md`의 「확정 명세 · 검증 기준」은 이 문서를 가리키는 포인터다.

> ⚠️ **2026-09-08 구성 변경 (ADR-6).** 구현 단계에서 **JS 스플래시 오버레이를 폐기하고 정적
> 스플래시 하나로** 끝내는 방식으로 바꿨다. 오버레이·타이밍 훅을 전제하던 AC를 아래에서
> 재정의했고, 성립하지 않게 된 AC는 「폐기된 AC」에 남겼다. 이슈 번호(#193·#194)와 담당 구간은
> 그대로 두되, **두 이슈가 같은 정적 스플래시를 서로 다른 축(동작 / 외형)으로 본다.**

## 범위 레이블

`apps/native`에 테스트 러너가 없어 `단위`·`통합` 두 레이블을 쓸 수 없다
(`spec.md`「자동 테스트를 쓰지 않는 이유」). 이 문서의 AC는 전부 `수동` 범위다.

| 레이블 | 뜻                                                          | 이 문서에서 |
| ------ | ----------------------------------------------------------- | ----------- |
| `단위` | 순수 함수·훅. `renderHook` 또는 직접 호출                   | 사용 안 함  |
| `통합` | 컴포넌트 렌더링 포함. RTL `render` / `userEvent`            | 사용 안 함  |
| `수동` | Android 실기기에서 사람이 관찰. 녹화·캡처·`adb logcat` 사용 | **전부**    |

`수동` AC 중 타이밍 경계값(AC-5)은 `INFRA-013`이 러너 도입 후 `단위`로 소급할 수 있다.
`수동`으로 남는 이유가 "검증 불가"가 아니라 "지금 러너가 없어서"임을 구분하기 위해 레이블을 나눈다.

## 이 작업의 슬라이싱 근거

구성 변경 전에는 **화면이 흰색인 구간**(정적 / 오버레이)으로 이슈를 나눴다. 오버레이가 사라진
지금은 층이 하나뿐이라, 같은 정적 스플래시를 두 축으로 나눠 본다.

```
앱 실행 ───────────────────────────────────────▶ 웹 첫 화면
        │            정적 스플래시               │
        │  #193: 언제까지 떠 있나 (동작)         │
        │  #194: 무엇이 그려지나 (외형)          │
```

두 축을 합친 전 구간 검증은 AC-10이 담당한다.

## Issue 1: [NAT] WebView 로드가 끝날 때까지 스플래시를 유지한다

GitHub Issue: [#193](https://github.com/Team-Gravit/gravit-web/issues/193)

> 원래 제목은 「WebView 로딩 구간을 스플래시 오버레이로 덮는다」였다. 오버레이 폐기(ADR-6)로
> **같은 목적을 정적 스플래시 유지로 달성**하게 되어 제목과 AC를 바꿨다.

### 설명

기본 동작에서는 정적 스플래시가 JS 실행 직후 내려가고, WebView가 아직 로드되지 않아 흰 화면이
남는다. 자동 숨김을 막고 **웹 첫 화면이 준비된 뒤에** 직접 내려 이 구간을 없앤다.

### 구현 범위

| 파일                          | 작업                                                                                     |
| ----------------------------- | ---------------------------------------------------------------------------------------- |
| `apps/native/app/_layout.tsx` | `preventAutoHideAsync()`, `setOptions({ duration: 1000, fade: true })`, placeholder 제거 |
| `apps/native/app/index.tsx`   | `hideAsync()` 소유 — `onLoadEnd` · `onError` · 상한 타이머(`SPLASH_MAX_WAIT_MS`)         |

**상한 타이머가 필요한 이유** — 서버가 응답 없이 매달리면 `onLoadEnd`도 `onError`도 오지 않아
스플래시에 갇힌다. 폐기된 `use-splash-gate`의 `MAX_WAIT_MS`가 하던 역할이 이것만 남았다.

### 완료 조건 (Acceptance Criteria)

☐ **AC-1** (범위: 수동)
Given `EXPO_PUBLIC_WEB_URL`이 로컬 dev 서버(`pnpm --filter @repo/web dev`)를 가리키고 정상 응답한다
When 앱을 콜드 스타트하고 웹 첫 화면이 그려질 때까지 녹화한다
Then 정적 스플래시가 웹 첫 화면 직전까지 유지되고, 그 사이 흰 화면 프레임이 `0`개다

> **검증 상태** — development build 첫 실행에서 흰 화면이 관찰됐고 reload에서는 정상 동작했다.
> 원인은 미확정이며, release 빌드를 실제 기기에 설치한 뒤 콜드 스타트를 검증한다.

☐ **AC-4** (범위: 수동)
Given `EXPO_PUBLIC_WEB_URL`이 로컬 dev 서버를 가리켜 로드가 빠르게 끝난다
When `[WebView] load end` 로그 시각과 스플래시가 화면에서 사라진 시각을 비교한다
Then 스플래시는 그 로그보다 먼저 사라지지 않는다

☐ **AC-5** (범위: 수동)
Given `EXPO_PUBLIC_WEB_URL`을 응답 없는 주소(예: `http://10.255.255.1:5173`)로 바꿔 `onLoadEnd`·`onError`가 오지 않는다
When 디버거로 `WebviewPage`의 effect에서 타이머를 등록한 시각과 타이머 콜백에서 `hideSplash()`를 호출한 시각을 측정한다 (중단점으로 실행을 정지하지 않는다)
Then 호출은 등록 후 `10000ms` 이전에 발생하지 않고, JS 스레드가 지연되지 않는 검증 환경에서는 `11000ms` 이내에 발생한다

앱 시작부터 JS 로딩·컴포넌트 마운트까지 걸린 시간은 이 10초에 포함하지 않는다.
종료 기준은 화면이 완전히 사라진 시점이 아니라 **숨김 호출 시점**이다. 페이드 연출은 별도이며,
JS 스레드 지연 시 타이머 호출도 늦어질 수 있다. 정상 로드·실패 이벤트가 먼저 오면 그때 숨긴다.

☐ **AC-6** (범위: 수동)
Given 앱이 실행 중이고 스플래시가 이미 사라진 상태다
When 앱을 백그라운드로 보냈다가 다시 포그라운드로 가져온다
Then 스플래시가 다시 나타나지 않는다

### 의존성

## Issue 2: [NAT] 정적 스플래시를 브랜드 화면으로 교체한다

GitHub Issue: [#194](https://github.com/Team-Gravit/gravit-web/issues/194)

### 설명

스캐폴드 잔재인 흰 배경 스플래시(`assets/splash.png`)를 브랜드 화면으로 바꾼다. 앱을 켠 순간부터
흰색이 아니라 `O.0`의 색과 로고가 보이게 한다.

### 구현 범위

| 파일                                        | 작업                                                       |
| ------------------------------------------- | ---------------------------------------------------------- |
| `apps/native/assets/splash-gradient.png`    | iOS 전체화면 그라디언트 이미지 (1290×2796)                 |
| `apps/native/assets/splash-logo-square.png` | Android 아이콘 슬롯용 정사각형 로고 (920×920)              |
| `apps/native/assets/splash.png`             | 스캐폴드 잔재 삭제                                         |
| `apps/native/app.json`                      | `expo-splash-screen` 설정 교체 (iOS / Android 분기, ADR-2) |
| `docs/implementation-status.md`             | `O.0` 행 갱신 — **iOS 미검증 사실을 함께 적는다**          |

**Android 아이콘 슬롯에 브랜드 로고를 넣는다.** `expo-splash-screen`의 `image`는 Android 12+에서
화면 중앙의 아이콘 슬롯(`windowSplashScreenAnimatedIcon`)으로 들어간다. 여기를 비우면 JS가 실행되기
전까지 **민무늬 보라 화면**이 이어져 스플래시로 성립하지 않고, `styles.xml`이 참조하는
`@drawable/splashscreen_logo`가 생성되지 않아 **빌드도 깨진다.**

로고는 `O.0`의 `176×153` 대신 **정사각형 판본**을 쓴다. 슬롯이 정사각형 영역이라 가로로 긴
워드마크가 잘릴 수 있기 때문이다. 실제 적용 폭은 `imageWidth: 150`이다.

**앱 윈도우 배경(`app.json` 최상위 `backgroundColor`)은 `#FFF`로 유지한다.** development build의
첫 실행에서 흰 화면이 관찰됐고 reload에서는 정상 동작했다. 배경색이 원인인지는 확인하지 않았다.
release 빌드를 실제 기기에 설치해 콜드 스타트를 확인한 뒤 재현 여부와 원인을 판단한다.

`app.json`을 고치면 CNG 재생성이 필요하다.

```bash
pnpm --filter @repo/native exec expo prebuild -p android --clean
pnpm --filter @repo/native android
```

### 완료 조건 (Acceptance Criteria)

☐ **AC-2** (범위: 수동)
Given Android 기기에서 앱을 콜드 스타트해 정적 스플래시가 표시 중이다
When 화면을 캡처해 Figma `O.0`(`12898:23224`)과 대조한다
Then 배경이 `#8100B3`이고, 화면 중앙에 로고가 `1`개 있으며 잘린 부분이 없다

☐ **AC-7** (범위: 수동)
Given `app.json`을 고친 뒤 `expo prebuild -p android --clean`을 돌린다
When `android/app/src/main/res/values/colors.xml`의 `splashscreen_background`를 읽는다
Then 값이 `#8100B3`이다

☐ **AC-8** (범위: 수동)
Given Android 기기에서 앱을 콜드 스타트한다
When 정적 스플래시가 보이는 순간을 캡처한다
Then 배경 전체가 `#8100B3`이고 흰색 영역이 `0`개다

☐ **AC-9** (범위: 수동)
Given `apps/native/assets/`를 확인한다
When `splash.png`를 찾는다
Then 파일이 존재하지 않고, `app.json`의 어떤 항목도 `splash.png`를 참조하지 않는다

☐ **AC-10** (범위: 수동)
Given Issue 1과 Issue 2가 모두 반영된 빌드이고 `EXPO_PUBLIC_WEB_URL`이 로컬 dev 서버를 가리킨다
When 앱 실행부터 웹 첫 화면이 그려질 때까지 **전 구간**을 녹화한다
Then 녹화 구간 전체에 흰 화면 프레임이 `0`개다 (release 빌드 설치 후 검증 전까지 미검증으로 남긴다)

☐ **AC-11** (범위: 수동)
Given AC-10과 같은 녹화본이다
When 앱 아이콘을 탭한 시점부터 스플래시가 사라질 때까지의 각 프레임에서 로고 유무를 센다
Then 로고가 보이지 않는 구간이 `300`ms 이하다

> **왜 이 AC가 생겼나** — 「흰 화면 0개」만으로는 민무늬 보라 화면이 한참 이어져도 통과한다.
> 그건 스플래시가 아니라 그냥 색칠된 대기 화면이다. 브랜드가 **처음부터** 보여야 스플래시다.

### 검증하지 않는 항목 (미검증·미해결로 남긴다)

아래는 **구현하되 확인할 수단이 없거나, 이번에 해결하지 않기로 판정한 것**이다. AC를 세우면 통과
판정을 지어내게 되므로 세우지 않는다 (`spec.md`「검증 전제」).

| 항목                                                            | 성격                           | 어디서 닫나                    |
| --------------------------------------------------------------- | ------------------------------ | ------------------------------ |
| iOS 정적 스플래시가 전체화면 그라디언트로 렌더되는지            | 검증 수단 없음                 | `INFRA-012`                    |
| iOS safe area 기준 스플래시 표시                                | 검증 수단 없음                 | `INFRA-012`                    |
| **iOS 스플래시에 로고가 없다** — `splash-gradient.png`가 배경뿐 | **미해결. 판정 필요**          | 후속 `NAT-`                    |
| development build 첫 실행의 흰 화면 — reload 정상, 원인 미확정  | **release 콜드 스타트 미검증** | release 빌드 실기 설치 후 확인 |

`docs/implementation-status.md`의 `O.0` 행에 **「iOS 미검증」을 명시**하는 것이 이 이슈의 완료
조건에 포함된다 (AC 없이 산출물로 확인).

## 폐기된 AC (2026-09-08, ADR-6)

오버레이·타이밍 훅을 전제하던 AC다. 구현이 그 층을 갖지 않으므로 성립하지 않는다.

| AC        | 원래 내용                                        | 폐기 사유                                                                      |
| --------- | ------------------------------------------------ | ------------------------------------------------------------------------------ |
| AC-3      | 오버레이 로고가 safe area 기준 세로 중앙 ±2dp    | 로고를 그리는 JS 층이 사라졌다. 위치는 OS(아이콘 슬롯 / storyboard)가 정한다   |
| AC-12     | 정적 스플래시 로고와 오버레이 로고의 폭 차이 8dp | 비교 대상 하나가 없어졌다                                                      |
| AC-4 (구) | 최소 노출 1000ms 보장                            | `MIN_VISIBLE_MS` 폐기. 같은 번호를 「로드 완료 전에 사라지지 않는다」로 재정의 |
| AC-5 (구) | 실패 시에도 10초 유지                            | 실패는 즉시 해제로 바뀌었다. 같은 번호를 「무응답 시 10초 상한」으로 재정의    |
