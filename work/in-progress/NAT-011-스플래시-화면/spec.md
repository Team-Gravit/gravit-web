# NAT-011 — 앱 스플래시 화면과 앱 아이콘 적용

> PR #195(`feat/#193/splash`)의 작업을 현재 앱 구조에 맞춰 다시 구현한다. 그 PR은 `develop`에서 오래 갈라져
> `app.json`을 그대로 가져오면 번들 ID와 Apple 로그인 권한이 사라진다. 이미지와 살아 있는 결정만 가져온다.
> 폐기된 결정(JS 오버레이 · 최소 노출 시간 등)의 이력은 그 PR의 문서에 있다.

## 배경 · 목표

앱을 켜면 스캐폴드 흰 스플래시가 뜨고, WebView가 웹을 불러오기 전에 내려가 **흰 화면**이 보인다.
아이콘도 스캐폴드 그대로다. 브랜드 스플래시를 WebView 로드까지 유지하고 Figma 아이콘을 적용한다.

## 플랫폼 전제

| 플랫폼  | 위치                                        | 요구 수준                                     |
| ------- | ------------------------------------------- | --------------------------------------------- |
| iOS     | 출시 대상. Expo 앱으로 배포한다             | 시안 일치                                     |
| Android | 다른 개발자가 별도 앱으로 배포. 개발 확인용 | 동작만 하면 된다. 시안 일치를 요구하지 않는다 |

Android 담당자가 이탈하면 Expo Android를 배포해야 할 수 있다. 그때 필요한 일은 「Out of Scope」에 적었다.

## Out of Scope

- **오류 · 재시도 화면.** 로드 실패 시 스플래시를 내리면 실패한 WebView가 그대로 보인다. 별도 `NAT-`
- **스플래시 애니메이션.** 시안에 모션 정의가 없다. 페이드아웃만 쓴다
- **Android 시안 일치와 적응형 아이콘 교체.** 시스템 스플래시 배경은 단색만 받는다. 현재 `adaptiveIcon` 설정은 건드리지 않는다. Expo Android를 배포하게 되면 로고를 줄인 전용 아이콘(지금 로고 폭은 81.5%라 원형 마스크에서 잘린다)과 그라디언트 처리 여부를 정한다
- **native 테스트 러너.** 없다. AC는 모두 수동이다
- **웹 첫 렌더 신호.** `onLoadEnd`로 시작한다. 흰 화면이 남으면 그때 별도로 다룬다

## 기술 결정

### ADR-1. 라이브러리 — `expo-splash-screen` 유지

**Context** — 이미 설치된 공식 패키지로 충분한지, `react-native-bootsplash`로 바꿀 이유가 있는지 정해야 한다.

**Decision** — `expo-splash-screen`을 유지한다.

**Alternatives**

| 안                           | 거부 이유                                                                                                                                          |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `react-native-bootsplash`    | README의 입력이 로고와 단색 배경뿐이라 그라디언트를 해결하지 못한다. 강점인 숨김 애니메이션은 시안에 없다. 다크 · 브랜드 옵션은 유료 키가 필요하다 |
| `react-native-splash-screen` | npm 마지막 갱신이 2022-06이고 README에 Expo · Android 12 언급이 없다                                                                               |
| JS 오버레이                  | 네이티브 스플래시가 먼저 떠서 화면이 두 단계가 된다. PR #195에서 만들었다가 폐기했다                                                               |

**Consequences**

- (+) SDK와 같이 올라가고 의존성이 늘지 않는다
- (−) 사라지는 연출은 페이드만 가능하다. `fade` 옵션은 iOS 전용이다

### ADR-2. iOS 스플래시 — 그라디언트와 로고를 한 이미지로

**Context** — 시안은 그라디언트인데 플러그인의 배경은 단색이다. PR #195의 이미지에는 로고가 없다.

**Decision** — iOS는 `enableFullScreenImage_legacy` + `resizeMode: cover`로 전체화면 이미지를 쓰고, 이미지에 로고를 넣는다. Android는 단색 `#8100B3` + 로고.

**Alternatives**

| 안                                | 거부 이유                                                              |
| --------------------------------- | ---------------------------------------------------------------------- |
| 양쪽 단색 + 로고 (표준 설정)      | 가장 안정적이지만 시안과 다르다. 옵션이 제거될 때의 대안으로 남겨 둔다 |
| 그라디언트만, 로고 없음 (PR #195) | 시안과 다르고, 브랜드가 없는 보라 화면만 보인다                        |

**Consequences**

- (+) 시안과 같은 화면을 추가 라이브러리 없이 낸다
- (−) 옵션이 "제거 예정"이다. 설치된 57.0.8과 SDK 58 문서에는 있다. 제거되면 그라디언트가 작은 사각형으로 보여 SDK 업그레이드 때 바로 드러난다. 그때 단색 + 로고로 바꾼다
- (−) 기기 비율에 따라 위아래가 잘리고 그라디언트 각도가 조금 달라진다. 로고는 이미지 중앙에 두어 잘리지 않게 한다. PR #195는 위치가 달라진다는 이유로 이 안을 거부했으나, `cover`는 중앙 기준으로 자르므로 중앙의 로고는 유지될 것으로 본다. **실기기로 확인한다** (AC-3)

### ADR-3. 숨김 시점 — WebView 로드 끝 또는 10초

PR #195의 결정을 유지한다. `onLoadEnd`나 `onError`에 숨기고, 신호가 없으면 10초에 숨긴다.

- (−) 로드 실패 시 실패한 WebView가 보인다. 오류 화면 작업이 맡는다
- (−) `onLoadEnd`는 웹 첫 렌더보다 앞설 수 있어 잠깐 흰 화면이 보일 수 있다. PR #195에서도 개발 빌드 첫 실행의 흰 화면 원인을 확정하지 못했다. preview 빌드에서 판정한다

## 확정 명세 · 검증 기준

모두 수동이다. Expo 문서가 개발 빌드로 스플래시를 테스트하지 말라고 하므로 **스플래시 판정은 preview 빌드에서 한다.**
