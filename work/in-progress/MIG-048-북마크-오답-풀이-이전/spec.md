# MIG-048 — 북마크 문제 풀이 · 오답노트 문제 풀이 이전

## 배경 · 목표

유닛 상세의 「북마크」 · 「오답노트」 카드는 `MIG-030` 이후 빈 라우트로 이어진다
(`_focus/learning.units.$unitId.bookmarked-problems.tsx` · `…incorrect-problems.tsx`).
legacy 에서 두 화면이 하던 풀이를 `apps/web` 으로 옮겨, 유닛에서 모은 문제를 다시 풀 수 있게 한다.

레슨 풀이(`FEAT-038`)가 이미 `apps/web` 에 있다. 그쪽은 **마지막에 한 번 일괄 제출**하고,
이 두 화면은 **문제마다 즉시 단건 제출**한다 (`FEAT-038` Out of Scope 의 근거).

## 범위

실행 이슈 2개로 나눈다. 연결할 GitHub Issue 는 `issues.md` 에 기록한다.

| 이슈 | 화면               | 경로                                          |
| ---- | ------------------ | --------------------------------------------- |
| A    | 북마크 문제 풀이   | `/learning/units/$unitId/bookmarked-problems` |
| B    | 오답노트 문제 풀이 | `/learning/units/$unitId/incorrect-problems`  |

B 는 A 가 만든 풀이 흐름 위에 오답노트 전용 동작만 얹는다.

## Out of Scope

- **유닛 상세의 진입 차단** — 풀 문제가 없을 때 카드에서 막는 것은 `FIX-036` 이 맡는다
- **신고 버튼** — `FEAT-038`·`FEAT-044` 에서 레슨 풀이에도 넣지 않은 별도 작업이다
- **레슨 풀이 화면의 동작 변경** — 공용화 과정에서 레슨 풀이의 사용자 동작이 바뀌면 안 된다
- 재진입 복원 (뒤로가기·새로고침 후 이어 풀기)

## 용어 정의 (Ubiquitous Language)

| 용어          | 정의                                                                         |
| ------------- | ---------------------------------------------------------------------------- |
| 복습 풀이     | 북마크 풀이와 오답노트 풀이를 함께 부르는 말. 레슨 풀이와 구분한다           |
| 단건 제출     | 답 하나를 고른 즉시 `POST /api/v1/problems/results` 로 그 문제 결과만 보낸다 |
| 일괄 제출     | 레슨 풀이처럼 마지막에 모든 답을 한 번에 보낸다. 이 작업에서는 쓰지 않는다   |
| 오답노트 제외 | `DELETE /api/v1/wrong-answered-notes` 로 문제를 오답노트에서 내리는 것       |

## 확인이 필요한 제약 (Known Constraints)

### API 계약 — legacy 와 현재 명세의 차이

`apps/web/src/shared/api/generated/` (현재 OpenAPI) 기준. 네 엔드포인트 모두 생성물에 있다.

| 엔드포인트                                  | 생성 함수                          | legacy 와 다른 점                                                                                                                         |
| ------------------------------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/v1/bookmarks/{unitId}`            | `getAllBookmarkedProblemInUnit`    | 없음. 응답 `BookmarkedProblemResponse { unitSummaryResponse, problems, totalProblems }`                                                   |
| `GET /api/v1/wrong-answered-notes/{unitId}` | `getAllWrongAnsweredProblemInUnit` | 없음. 응답 `WrongAnsweredProblemsResponse` — 위와 같은 모양                                                                               |
| `POST /api/v1/problems/results`             | `saveProblemSubmission`            | **요청에 선택 필드가 늘었다** — `selectedOptionId?`(객관식) · `submittedContent?`(주관식). legacy 는 `{ problemId, isCorrect }` 만 보낸다 |
| `DELETE /api/v1/wrong-answered-notes`       | `deleteWrongAnsweredProblem`       | 없음. 명세 설명: 「기록은 남으며, 해당 문제를 다시 틀리면 오답노트로 복귀」                                                               |
| `POST` / `DELETE /api/v1/bookmarks`         | `addBookmark` · `deleteBookmark`   | 없음                                                                                                                                      |

두 목록 응답은 레슨 문제 응답(`LessonResponse`)과 같은 `ProblemResponse[]` + `unitSummaryResponse` 를 쓴다.
따라서 `entities/problem` 의 문제 변환을 그대로 쓸 수 있는지 계획 단계에서 확인한다.

### apps/web 에 이미 있는 대응물

| 대응물                                      | 그대로 쓸 수 있나                                                                                                              |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `entities/problem` — 문제 카드·선지·해설 UI | 대부분. 해설 표시 규칙은 `FEAT-038` 확정분(R9~R11)이 legacy 와 다르다 → 시안 대조 대상                                         |
| `features/lesson-quiz` — 풀이 상태·채점     | 채점(`gradeObjective`·`gradeSubjective`)은 후보. 세션 Provider 는 `lessonId` 와 `sessionStorage` 에 묶여 있고 일괄 제출 전제다 |
| `features/problem-bookmark` — 북마크 토글   | 아니다. 낙관적 갱신 대상이 **레슨 문제 캐시**(`lessonId`)로 고정돼 있다. 목록 캐시를 받도록 넓혀야 한다                        |
| `pages/lesson-quiz` — 상단바·로딩·타이머    | 레슨 페이지 안에 있어 다른 page 에서 import 할 수 없다 (cross-slice). 공용화하면 아래 레이어로 내려야 한다                     |

### 토큰 호환성

legacy 해설 색(`text-correct` `#00A80B` · `text-error-info` `#D00000`)은 `apps/web` `tokens.css` 에도
같은 값으로 남아 있지만 **호환 토큰**이다. `FEAT-038` R10 은 `semantic-success` · `semantic-error` 를
쓰기로 확정했으므로 새 화면은 그 규칙을 따른다 (`design-source-policy.md` §8).

## 동일성 확인 방법

- **단건 제출 (K1·K2)**: MSW 로 문제 3개 목록을 주고 3문제를 모두 풀면 `POST /api/v1/problems/results` 가
  정확히 3번, `POST /api/v1/lessons/results` 는 0번 호출되는지
- **오답노트 제외 노출 (K3)**: 오답노트 풀이에서 객관식을 맞히면 「오답노트에서 제외하기」가 보이고, 틀리면 없는지
- **제외 요청**: 누르면 `DELETE /api/v1/wrong-answered-notes` 가 `{ problemId }` 로 1번 가고, 성공 후 버튼이 사라지는지
- **끝내기 (K4)**: 유닛 상세 → 북마크 풀이 → 마지막 문제 다음 → 경로가 `/learning/units/{unitId}` 이고 목록 쿼리가 무효화됐는지
- **레슨 회귀 (K5)**: 기존 `pages/lesson-quiz` · `features/lesson-quiz` 테스트가 수정 없이 통과하는지
- **수동 스모크**: 실제 계정으로 오답 문제를 맞히고 제외 → 유닛 상세로 돌아가 오답노트 진입 가능 여부가 바뀌는지
- 기존 테스트: legacy 에는 없다

## 기준선을 쓰면서 발견한 것

판단하지 않고 관찰만 적는다. 처리 여부는 시안 대조 뒤 게이트에서 정한다.

1. **단건 제출 실패가 조용히 묻힌다 (C6)** — 실패를 잡는 곳이 없어 사용자도 모르고, 서버 기록만 빠진다.
2. **빈 목록이면 화면이 깨질 수 있다** — 목록이 0건이면 첫 문제가 없는데 문제 머리·신고 모달이
   그 문제를 읽는다. 지금은 유닛 상세에서 진입을 막는 `FIX-036` 이 아직 to-do 다.
3. **직접 진입 후 끝내면 앱 밖으로 나갈 수 있다 (D1·D3)** — 끝내기와 X 가 모두 브라우저 뒤로가기라,
   주소로 바로 들어온 경우 돌아갈 기록이 없다. 개념노트 화면은 이 경우 유닛 상세로 `replace` 이동한다.
4. **오답노트 제외의 낙관적 갱신 플래그를 아무도 읽지 않는다** — `isRemovedFromIncorrect` 를 캐시에
   쓰지만 화면은 버튼 자체의 상태로만 숨긴다.
5. **경과 시간이 어디에도 쓰이지 않는다 (D4)** — 표시만 하고 서버로 보내지 않는다.
6. **상단바 제목이 레슨 풀이와 다르다 (B1)** — legacy 복습 풀이는 유닛 제목만, `apps/web` 레슨 풀이는
   `Unit01 - 제목` 이다.
7. **레슨 풀이와 상호작용 모델이 다르다 (B5·C1)** — `apps/web` 레슨 풀이는 이전/다음 이동과 진행 패널이
   있고 마지막에 일괄 제출한다. legacy 복습 풀이는 앞으로만 가고 답마다 즉시 제출한다.

### 확인 필요

1. **풀이 UI 를 레슨 풀이(`apps/web`)에 맞출지, legacy 복습 풀이에 맞출지** — 이전/다음 이동·진행 패널·
   객관식 즉시 제출·해설 규칙이 갈린다. 시안 대조(`design-diff`)에서 복습 풀이 시안이 따로 있는지 먼저 본다.
2. **단건 제출에 `selectedOptionId` · `submittedContent` 를 실을지** — 현재 명세에는 있고 legacy 는 보내지
   않는다. 레슨 일괄 제출은 이미 싣는다. 서버가 이 값으로 무엇을 하는지(오답 기록에 남기는지) 확인이 필요하다.
3. **단건 제출 실패 시 사용자에게 알릴지 (발견 1)** — 알린다면 문구와, 풀이를 막을지 계속할지.
4. **오답노트에서 정답을 맞히면 서버가 자동으로 노트에서 내리는지** — 명세 설명은 「제외」 API 만
   다룬다. 자동으로 내려간다면 「제외하기」 버튼의 의미가 달라진다.
5. **끝낸 뒤 이동 대상 (발견 3)** — 뒤로가기를 유지할지, 유닛 상세로 명시 이동할지.
6. **신고 버튼** — Out of Scope 로 두었다. 레슨 풀이와 함께 별도 작업으로 다룰지 확인.

      Then 1번 문제가 그대로 있고 진행률 분모가 3이다
- [ ] **AC-9** (통합)
      Given 북마크를 하나 해제한 상태
      When 풀이를 떠난다 (X 또는 `완료`)
      Then 다음 진입 때 `GET /api/v1/bookmarks/7` 이 다시 요청된다
- [ ] **AC-9-1** (통합)
      Given 유닛 상세에서 북마크 풀이로 들어왔다
      When 북마크를 하나 해제하고 풀이를 닫는다
      Then 유닛 상세 `GET /api/v1/lessons/7` 이 다시 요청된다 (`bookmarkAccessible` 은 유닛 전체 집계라 화면에서 계산하지 않는다)
- [ ] **AC-10** (통합)

      When 해설을 본다
      Then `오답노트에서 제외` 버튼이 0개다

### 오답노트 풀이

- [ ] **AC-11** (통합)
      Given 오답노트 풀이에서 객관식 정답을 맞혔다
      When 해설을 본다
      Then 넓은 화면은 하단 `이전 문제` 왼쪽, 좁은 화면은 펼쳐진 정답 선지 안에 `오답노트에서 제외` 버튼이 1개 보인다
- [ ] **AC-12** (통합)
      Given AC-11 상태
      When `오답노트에서 제외` 를 누른다
      Then `DELETE /api/v1/wrong-answered-notes` 가 `{ problemId }` 로 1번 호출되고, 성공하면 토스트 `오답노트에서 제외했어요.` 가 보이고 버튼이 0개가 되며 해설은 그대로 보인다
- [ ] **AC-13** (통합)
      Given 오답노트 풀이에서 틀렸다
      When 해설을 본다
      Then `오답노트에서 제외` 버튼이 0개다
- [ ] **AC-14** (통합)
      Given 제외 요청이 500 을 준다
      When `오답노트에서 제외` 를 누른다
      Then 토스트 `오답노트에서 제외하지 못했어요.` 가 1번 보이고 버튼이 1개 남아 다시 누를 수 있다
- [ ] **AC-15** (통합)
      Given 문제 하나를 제외했다
      When 풀이를 떠난다
      Then 다음 진입 때 `GET /api/v1/wrong-answered-notes/7` 이 다시 요청된다
