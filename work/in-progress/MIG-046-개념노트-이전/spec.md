# MIG-046 — 개념노트 화면 이전

GitHub Issue: [#261](https://github.com/Team-Gravit/gravit-web/issues/261)

## 배경 · 목표

유닛 상세의 「개념노트」 카드가 가리키는 `/learning/units/$unitId/concept-note`는 지금 빈 라우트다
(MIG-030). legacy의 개념노트 화면을 `apps/web`으로 옮겨 유닛의 개념 설명을 읽을 수 있게 한다.

마크다운 렌더링은 학습 문제 본문(서버가 md로 준다)에서도 쓸 예정이므로 **재사용 가능한 단위로
만든다.** 단 legacy의 라이브러리 조합과 구조를 그대로 따르지 않고, 실제 콘텐츠가 쓰는 문법을
근거로 다시 고른다.

## 범위

- 개념노트 화면 (`pages`) · 라우트 연결 (`app/routes`)
- 마크다운 렌더링 공용 모듈 (`shared`)
- 개념노트 조회 API 연결

## Out of Scope

- 학습 문제 본문의 마크다운 렌더링 적용 — 별도 작업
- 개념노트 원본(`Team-Gravit/gravit-cs-notes`)의 작성 규칙 변경
- 북마크 · 오답노트 화면

## 용어 정의 (Ubiquitous Language)

| 용어      | 정의                                                                                           |
| --------- | ---------------------------------------------------------------------------------------------- |
| 개념노트  | 유닛 하나에 대응하는 마크다운 문서. 서버가 `text/markdown`으로 준다                            |

### E. 실제 콘텐츠가 쓰는 문법 (노트 원본 전수 조사)

`Team-Gravit/gravit-cs-notes` 268개 `.md` · 약 2.6MB를 코드 블록 밖에서 집계했다 (2026-09-26).
dev API `GET /api/v1/cs-notes/units/1` 이 같은 형식의 `text/markdown`을 돌려주는 것을 확인했다.

| 문법                             | 사용                                                      | 비고                                                                  |
| -------------------------------- | --------------------------------------------------------- | --------------------------------------------------------------------- |
| 제목                             | `##` 302 · `###` 2,317 · `####` 38 · `#` 2                | 원본 규칙은 `##` 제목 + `###` 절. `#`·`####`는 규칙 밖이지만 존재한다 |
| GFM 표                           | 251개 파일                                                | 헤더·핵심 값을 `**굵게**`                                             |
| 코드 블록                        | 언어 지정 약 1,000개 (python·swift·java·kotlin·sql·tsx …) | 언어 없는 블록은 ASCII 다이어그램                                     |

## 확인이 필요한 제약 (Known Constraints)

| #   | 제약                                                                                                                                          |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| X1  | legacy가 부르는 `GET /api/v1/cs-notes/{unitId}` 는 OpenAPI에 **deprecated** 로 표시돼 있다. 대체 경로는 `GET /api/v1/cs-notes/units/{unitId}` |
| X2  | orval 생성 함수는 두 경로 모두 `responseType: 'blob'` 이다. 텍스트로 쓰려면 변환이 필요하다 (생성물은 직접 고치지 않는다)                     |
| X3  | `apps/web` 라우트는 `$chapterId` 가 없다 (`docs/routes.md` `LRN-04`). 배너의 챕터 이름·유닛 순번을 `unitId` 만으로 얻어야 한다                |
| X4  | 원시 HTML을 허용하면 정화가 필수다 (K3). 허용하지 않으면 `<br>`·`<img>` 가 렌더링되지 않는다 (K2)                                             |

## 동일성 확인 방법

- **라우트 진입:** 유닛 상세 → 「개념노트」 → URL이 `/learning/units/{같은 unitId}/concept-note`, 배너에 챕터 이름과 `Unit{NN} 개념노트`
- **콘텐츠 렌더링 (자동):** 노트 원본 규칙의 대표 문법을 담은 픽스처로 표 · 코드 블록 · `<br>` · `<img width>` · 콜아웃이 각각 해당 요소로 렌더링되는지
- **정화 (자동):** `<script>` · `onerror=` · `javascript:` 링크가 DOM에 남지 않는지
- **실제 콘텐츠 (수동):** 표가 많은 `data-structure/unit01`, 이미지가 많은 `algorithm/unit04` 를 dev API로 열어 원문 텍스트 노출이 없는지
- **실패 (자동):** 노트 요청이 500이면 실패 문구가 보이는지
- 기존 테스트: legacy에 없음

## 기준선을 쓰면서 발견한 것

1. **로딩 중에도 「정보를 불러오지 못했습니다.」** — 챕터 목록이 아직 없을 때와 실패했을 때를 구분하지 않는다 (C1).
2. **제목 중복** — 첫 줄 `## 배열(Array)` 이 카드 부제와 본문 첫 제목으로 두 번 보인다 (B3·B4).
3. **deprecated 경로 사용** (X1).
4. **배너만을 위한 별도 요청** — 챕터 유닛 목록 전체를 받아 순번을 계산한다 (D3). `apps/web` 에는 `unitId` 로 챕터 요약과 유닛 순번(`displayOrder`)을 주는 유닛 조회가 이미 있다 (`entities/learning` `useUnitLessons`).
5. **legacy 스타일은 토큰 밖이다** — `#1f2328` · `#f6f8fa` · `#dfe2e5` 등 원시 색상과 `@tailwindcss/typography` 의 `.prose` 를 `!important` 로 덮는다. `apps/web` 에는 typography 플러그인이 없다.
6. **노트 원본에 작성 규칙이 있다** — 쓰는 문법이 닫힌 집합이다 (E). 렌더러 선택의 근거로 쓸 수 있다.
7. **`remark-gfm` 은 `apps/web` 에 이미 있다** — Storybook MDX용이다 (`.storybook/main.ts`).

### 확인 필요

1. **모바일 표현.** 사용자 전언으로는 시안에서 좁은 화면은 **바텀시트(약 80% 높이)**, 넓은 화면은 별도 페이지다. legacy는 둘 다 페이지다 (A3). 시안 확인은 `design-diff` 에서 한다.
   - AOS 앱(`gravit-aos` `Study/Lesson/Note.kt`)이 같은 표현이다 — 유닛 상세 위 시트, 72%·90% 두 단계, URL·뒤로가기 처리 없음. 시안이 이를 따른 것으로 보인다.
   - **잠정 결정 (2026-09-26, 사용자)** — 디자이너 답을 받기 전까지 아래로 간다.
     - 좁은 화면은 **URL을 가진 바텀시트**, 넓은 화면은 페이지. URL은 `LRN-04` 그대로
     - 끌기는 **핸들에서만** 받는다. 본문 스크롤과 겹치지 않게 한다
     - 두 단계: 절반(시안 값) · 전체. **전체 상태는 `<` 제목 헤더를 가진 페이지 모양**이 된다
     - 끌기 외 닫기 수단(`x` · `Esc` · 배경 탭 · 뒤로가기)을 둔다
     - 절반 높이가 너무 낮다고 판단되면 나중에 **처음부터 전체 페이지**(`<` 제목 헤더)로 바꾼다. 그래서 헤더·본문은 시트와 분리한다
   - 미정: 전체 상태의 `<` 가 **닫기(뒤로가기)** 인지 **절반으로 내리기** 인지. 닫기를 권장한다 (뒤로가기와 같은 의미가 된다)
   - **최종 결정 (2026-10-07, 사용자)** — 바텀시트와 단계를 제거하고 모든 화면 폭에서 페이지로 연다. 모바일은 닫기 상단바를 쓰고 앱 셸의 하단 탭을 숨긴다.
   - 디자이너 문의 (사용자 판단) — 맥락 유지가 의도인지, AOS 방식을 맞춘 것인지.
2. **제목 중복을 유지할지** (발견 2).
3. **대체 경로 `/cs-notes/units/{unitId}` 로 옮길지** (X1) — 동작이 같다고 명시돼 있다.

### 확인 필요

> 2026-09-26 사용자 답변. 디자이너 문의가 어려워 **사용자가 직접 결정**한다.
> 해결된 항목: 딤은 시안에 있다(`black/40`) · 카드 반경은 웹·모바일 모두 12 · 배경은 학습 화면과 같다.

1. **높이 단계** — 시안은 하나. 사용자는 전체 화면 단계를 두는 쪽으로 기운다. 전체 상태의 머리 구성
   (`<` · `x` 를 공용 `IconButton` 으로)과 하단 `닫기` 버튼 유지 여부를 정한다.
2. **W2 `제목`** — 자리표시자로 본다. 넓은 화면 카드 제목에 무엇을 쓸지 정한다.
3. **W4 카드 높이 700 고정** — 긴 노트(최대 23KB)를 카드 안 스크롤로 볼지, 카드가 늘어날지. 사용자가 정한다.
4. **M5 좁은 화면 제목** — 시안에 없다. 우리가 구성한다 (사용자).
5. **시안 전체에 로딩·실패·빈 상태가 없다** (S1~S3). 기존 공용 `Skeleton` · 실패 문구 방식으로 채울지.
6. **딤 색** — Figma `black/40` 은 순수 검정 기준일 가능성이 있다. 이 프로젝트의 `black` 은 `#222124`
   (`--color-black`)라 `bg-black/40` 은 그 색의 40%다. 공용 `Modal` 이 이미 `bg-black/40` 을 쓰므로 같은 값으로 맞출지.
