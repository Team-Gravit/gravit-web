# MIG-068 — 문제 신고 모달 이전

## 배경 · 목표

legacy 풀이 화면에서는 문제마다 신고 버튼을 눌러 신고 유형과 내용을 적어 제출할 수 있다.
`apps/web`에는 신고 버튼도 모달도 없다 (`FEAT-038` D2 · `FEAT-044` · `MIG-048` P9에서 범위 밖으로 미뤘다).
legacy 동작을 기준으로 신고 작성 모달과 제출 성공 모달을 이전하고 Figma 시안과 맞춘다.

## 범위

- 신고 작성 모달 · 제출 성공 모달
- 모달을 여는 신고 버튼 (위치는 시안 대조에서 정한다)
- 대상 풀이 화면은 시안 대조에서 정한다 (legacy는 레슨 · 북마크 · 오답 세 곳 모두, 기준선 A3)

## Out of Scope

- 그만두기 모달 (`MIG-066`)
- 모달이 열린 동안 풀이 타이머 멈춤 — 그만두기 모달과 같은 문제라 `FIX-067`에서 함께 다룬다
- 내 신고 목록 · 신고 상세 · 관리자 신고 처리 (legacy `report-api`에 있지만 화면 없음)

## 용어 정의 (Ubiquitous Language)

| 용어           | 정의                                                         |
| -------------- | ------------------------------------------------------------ |
| 신고 버튼      | 풀이 중인 문제를 신고하는 버튼. 누르면 신고 작성 모달이 열림 |
| 신고 작성 모달 | 신고 유형 4개 중 하나를 고르고 신고 내용을 적어 제출하는 창  |

## 동작 계약 (바뀌면 안 되는 것)

| #   | 계약                                                                 | 깨지면 무슨 일이 생기나                                    |
| --- | -------------------------------------------------------------------- | ---------------------------------------------------------- |
| K1  | 요청 본문 `{ problemId, reportType, content }`와 `reportType` 4개 값 | 서버가 거부하거나 다른 유형으로 집계된다                   |
| K2  | `problemId`는 신고 버튼을 누른 시점에 보이던 문제                    | 엉뚱한 문제가 신고되어 운영자가 잘못 고친다                |
| K3  | 유형 미선택 또는 내용 공백이면 제출할 수 없다 (C1)                   | 빈 신고가 쌓이거나 서버 검증 오류가 난다                   |
| K4  | 신고가 풀이 진행 상태를 바꾸지 않는다 (F2)                           | 신고하다 푼 답이나 현재 문제 위치를 잃는다                 |
| K5  | 제출이 성공했을 때만 성공 모달을 띄운다 (C6)                         | 실패했는데 접수됐다고 안내해 사용자가 다시 신고하지 않는다 |

## 확인이 필요한 제약

- API: `apps/web`에 orval 생성 `useSubmitProblemReport`(`POST /api/v1/reports`)가 이미 있다. `reportType`은 스펙상 `string`(`minLength 1`)이라 4개 값은 생성 타입이 보장하지 않는다
- `apps/web` 아이콘에 `siren.svg`가 있다. legacy 신고 아이콘(`features/quiz/ui/modal/assets/report.svg`)과 같은 모양인지는 시안 대조에서 본다

## 동일성 확인 방법

- 신고 버튼 → 작성 모달: 제목 "신고하기", 유형 4개 문구·순서, "제출하기" 비활성
- 유형만 고름 → 비활성 / 공백만 입력 → 비활성 / 유형 + 글자 → 활성 (C1)
- 제출 → MSW로 요청 본문이 `{ problemId: <현재 문제>, reportType: 'ANSWER_ERROR', content: '<입력값>' }`인지 (K1 · K2)
- 성공 응답 → 작성 모달 닫힘 · 성공 모달 제목·설명 3줄 · "확인"으로 닫힘 (E2~E4)
- 실패 응답 → 성공 모달이 뜨지 않음 (K5). 무엇을 보여줄지는 확인 필요 2
- 신고 전후 현재 문제 번호와 고른 답이 같은지 (K4)
- 기존 테스트: 없음 (legacy에 테스트가 없다)

## 기준선을 쓰면서 발견한 것

> 현행 동작이 아니라 관찰이다. 판단하지 않고 아래 `확인 필요`로 올린다.

1. **입력이 닫아도 남는다 (D2 · D3)** — 다른 문제로 넘어가도 이전 문제에 쓴 내용이 남은 채 새 문제로 제출된다
2. **실패 시 반응 없음 (C7)** · **요청 중 중복 제출 가능 (C5)**
3. **고른 유형을 해제할 수 없다 (B3)** — 체크박스 모양이지만 동작은 라디오다
4. 유형 줄 클릭 시 선택 함수가 두 번 불린다 (`li` 클릭 + 체크박스 클릭). 같은 값이라 관찰되는 차이는 없다
5. 모달 열림 중 타이머 멈춤(F1)은 그만두기 모달에서 `FIX-067`로 분리한 것과 같은 동작이다

### 확인 필요

| #   | 항목                          | 판정 (2026-10-26)                                                                         |
| --- | ----------------------------- | ----------------------------------------------------------------------------------------- |
| 1   | 입력 유지 (D2 · D3)           | **고침** — 열 때마다 유형·내용을 비운다                                                   |
| 2   | 실패 처리 (C7)                | **고침** — 작성 모달을 열어 둔 채 입력을 남기고 토스트로 안내                             |
| 3   | 요청 중 상태 (C5)             | **고침** — 「제출하기」에 로딩 표시. 요청 중 다시 보낼 수 없다                            |
| 4   | 내용 필수 여부 (C2)           | **유지** — 내용 필수. 운영자가 고칠 곳을 알 수 있어야 한다 (서버 명세는 빈 값 허용, 아래) |
| 5   | 신고 버튼 위치·대상 (A1 · A3) | **고침** — 새 시안에 맞춘다. 위치와 대상 화면은 `design-diff`에서 시안으로 확인           |
| 6   | 타이머 멈춤 (F1)              | **나중** — 이 작업에서 빼고 `FIX-067` 범위를 「풀이 중 모달 전체」로 넓혀 한 번에 고친다  |

**4번 서버 명세 (dev `/v3/api-docs`, 2026-10-26 조회)**

- `content`는 `required`지만 `minLength`가 없다. 같은 요청의 `reportType`에는 `minLength: 1`이 있다
  → 서버는 빈 문자열 `""`을 받는 것으로 보인다 (명세 기준. 실제 요청으로는 확인하지 않음)
- 응답에 400(검증 실패)이 정의돼 있지 않다. 정의된 실패는 404 `PROBLEM_4041`(문제 없음) · 500뿐이다
- 즉 내용 필수는 서버 제약이 아니라 **legacy 화면의 선택**이다. 유지할지는 제품 결정이다

## 확정 명세 · 검증 기준

> 2026-10-26 판정 기준. 시각 항목(시안 대조 R1 · R3~R5 · R7 · R9 · T1~T2 · T4~T6)은 테스트가 아니라
> Storybook · 실기기 대조로 확인한다 (AC-12).

- [ ] **AC-1** (범위: 통합) 세 풀이 화면에 신고 버튼이 있다
      Given 레슨 풀이 · 북마크 문제 풀이 · 오답 문제 풀이 화면 중 하나가 열려 있다
      When 상단바를 본다
      Then 왼쪽 끝 「풀이 닫기」와 같은 상단바 오른쪽 끝에 이름이 "문제 신고"인 버튼이 1개 있다
- [ ] **AC-2** (범위: 통합) 신고 버튼을 누르면 작성 모달이 열린다
      Given 풀이 화면이 열려 있다
      When 「문제 신고」를 누른다
      Then 제목 "신고하기" 대화상자가 열리고, 유형 4개가 "문제/선지에 오탈자가 있습니다." · "문제 자체에 오류가 있습니다." · "답안에 오류가 있습니다." · "기타" 순서로 있으며 아무것도 선택돼 있지 않고, 「제출하기」는 비활성이다
- [ ] **AC-3** (범위: 단위) 유형과 내용이 모두 있어야 제출할 수 있다
      Given 작성 모달이 열려 있다
      When (a) 유형만 고른다 (b) 내용에 공백만 입력한다 (c) 유형을 고르고 "오타 있음"을 입력한다
      Then 「제출하기」가 (a) 비활성 (b) 비활성 (c) 활성이다
- [ ] **AC-4** (범위: 단위) 유형은 하나만 선택된다
      Given "문제/선지에 오탈자가 있습니다."가 선택돼 있다
      When "답안에 오류가 있습니다."를 누른다
      Then 선택된 유형은 "답안에 오류가 있습니다." 1개다
- [ ] **AC-5** (범위: 통합) 내용을 입력하면 라벨 "신고 사유"가 보인다
      Given 내용이 비어 있고 placeholder "신고 사유를 입력해주세요."가 보인다
      When "오타 있음"을 입력한다
      Then 입력칸 위에 "신고 사유"가 보인다
- [ ] **AC-6** (범위: 통합) 제출 요청 본문
      Given 문제 ID 42를 보는 중 신고 모달을 열고 "답안에 오류가 있습니다."를 고르고 " 오타 있음 "을 입력했다
      When 「제출하기」를 누른다
      Then `POST /api/v1/reports`가 1번 호출되고 본문은 `{ problemId: 42, reportType: 'ANSWER_ERROR', content: ' 오타 있음 ' }`이다
- [ ] **AC-7** (범위: 통합) 요청 중에는 다시 보낼 수 없다
      Given 제출 요청이 아직 끝나지 않았다
      When 「제출하기」를 다시 누른다
      Then 요청은 1번만 나가고 「제출하기」는 로딩 상태(`aria-busy="true"`)다
- [ ] **AC-8** (범위: 통합) 성공하면 성공 모달로 바뀐다
      Given 제출 요청이 200으로 끝난다
      When 응답을 받는다
      Then 작성 모달이 닫히고 제목 "회원님의 신고가 접수되었어요." · 설명 "회원님의 소중한 의견들을 모아" / "더욱 쾌적한 앱 환경을 만들겠습니다." / "단, 허위로 신고할 경우 제재 대상이 될 수 있어요."가 있는 대화상자가 열린다. 「확인」을 누르면 닫힌다
- [ ] **AC-9** (범위: 통합) 실패하면 모달을 유지하고 토스트로 알린다
      Given 제출 요청이 500으로 끝난다
      When 응답을 받는다
      Then 작성 모달이 열려 있고 고른 유형 · 입력한 내용이 그대로이며, 토스트 "신고에 실패했어요. 다시 시도해 주세요."가 보이고 성공 모달은 열리지 않는다
- [ ] **AC-10** (범위: 통합) 열 때마다 비운다
      Given 유형을 고르고 내용을 입력한 뒤 X · 「그만두기」 · Esc · 바깥 클릭 중 하나로 닫았다
      When 「문제 신고」를 다시 누른다
      Then 선택된 유형이 없고 내용이 비어 있으며 요청은 0번이다
- [ ] **AC-11** (범위: 통합) 신고해도 풀이가 그대로다
      Given 3번 문제에서 답을 입력한 상태다
      When 신고를 제출해 성공 모달의 「확인」까지 누른다
      Then 3번 문제와 입력한 답이 그대로 있고 경로가 바뀌지 않는다
- [ ] **AC-12** (범위: 수동) 시각 대조
      Given Storybook `Features/ProblemReport` (작성 · 성공, 넓은 · 좁은 화면)
