# FEAT-055 — AI면접 세션 설정 플로우

## 배경 · 목표

사용자가 AI면접을 시작하기 전에 **답변 방식 → 주제(모드) → 세부 선택 → 난이도**를 고르고, 확인 화면에서
「시작하기」를 누르면 면접 세션이 생성된다. 이 작업은 **세션 생성(`POST /api/v1/interview-sessions`)까지**를
책임지고, 생성된 `sessionId`를 문항 응답 화면(WEB-AI-08) 담당에게 넘긴다.

처음에는 선택 상태와 전이 로직부터 구현했다. 이후 사용자 요청으로 카드·체크박스·진행 바·난이도·확인 화면의
반응형 스타일까지 범위를 넓혔다. 자동 검사와 실제 화면 확인은 구분하며, 남은 항목은 `checklist.md`에 기록한다.

## 범위

- 화면: WEB-AI-01(답변 방식) · 02(주제) · 03(CS 분야) · 04(직군) · 05(스택) · 06(난이도) · 07(시작 확인)
- 상태: 여러 라우트에 걸친 선택 초안 → `features/interview-session-setup/model/` Zustand store
- 로직: 선택·해제·상호배타·전체선택 동기화·다음 버튼 활성 조건·이전/다음 목적지·요청 바디 조립
- API: CS 주제 목록 · 직군 그룹별 스택 목록 조회, 세션 생성 mutation
- UI: 반응형 선택 카드·난이도 라디오·CS 체크박스·진행 바·확인 화면, 조회 중 스켈레톤과 실패 재시도
- 연결: 데스크톱 GNB 진입, 설정 이탈 시 초안 초기화, 생성 후 설정 진입 기록까지 돌아가 목적지로 교체

## Out of Scope

- WEB-AI-00 AI면접 홈(대시보드·최근 이력·점수 추이·약점 분야) — 진입/이탈 지점으로만 참조
- WEB-AI-08 이후(문항 응답·답변 확인·피드백 리포트) — 학습 진행 담당
- Storybook, 실서버 검증과 최종 시안 대조는 아직 완료하지 않음
- 음성 모드 마이크 권한 확인·녹음(WEB-AI-07 안내 문구 표시만 포함, 권한 검사는 WEB-AI-08/native 담당)

### 흐름

```
AI-00 홈 ─[새 세션 시작]→ AI-01 답변 방식 → AI-02 주제
                                              ├─ CS 개념 모드 → AI-03 CS 분야 ─┐
                                              └─ 직군별 특화 모드 → AI-04 직군 → AI-05 스택 ─┤

```

**공통 규칙**

- 상단 홈/뒤로가기(`<`) 버튼 → **AI면접 홈(AI-00)**. 하단 「이전」 → **직전 단계 화면**. 둘의 목적지는 다르다
- 「이전」은 항상 활성. 선택 여부와 무관하게 이동한다
- 단일 선택 카드는 라디오형 상호 배타 + **재클릭 시 해제**
- 「다음」은 조건 미충족 시 비활성

## API 계약 (dev OpenAPI, 2026-10-10 확인)

| 용도             | 엔드포인트                                          | 생성 함수              | 비고                                                 |
| ---------------- | --------------------------------------------------- | ---------------------- | ---------------------------------------------------- |
| CS 주제 목록     | `GET /api/v1/interview-topics`                      | `getCsTopics`          | `[{ topic, displayName }]` (예시 5개)                |
| 직군 그룹 목록   | `GET /api/v1/interview-stack-groups`                | `getStackGroups`       | `[{ stackGroup, displayName }]` — Server/Web/AOS/iOS |

세션 생성 바디 규칙 (서버 검증)

- `COMMON_CS`: `topics` 중복 없는 1~5개, `stack` 비움
- `JOB_SPECIFIC`: `stack` 1개, `topics` 비움
- 실패: 400 `INTERVIEW_4007/4008/4016/4017/4018`(바디 규칙 위반) · 409 `INTERVIEW_4009`(문제 풀 부족) · 500

> ⚠️ 조회 3종은 OpenAPI에 **응답 schema가 없고 example만** 있어 orval 타입이 `unknown`이다.
> 주제·스택은 `InterviewTopicResponse` · `InterviewStackResponse` 모델이 따로 있으나 직군 그룹 모델은 없다.

## 기술 결정 (ADR)

### 선택 초안을 어디에 둘 것인가

**Context** — 7개 화면(라우트)에 걸쳐 선택값이 쌓이고, 07에서 한 번에 세션 생성 바디가 된다. 각 화면은
「이전」으로 되돌아와도 기존 선택이 남아 있어야 한다. 서버에는 생성 전 초안 API가 없다.

**Decision** — `features/interview-session-setup/model/`의 **Zustand store** (메모리, persist 없음).
상태 전이 규칙(토글·하위 선택 초기화)은 store 액션에, 파생값(활성 조건·목적지·바디)은 순수 함수로 둔다.

**Alternatives**

| 안                                | 내용                          | 거부 이유                                                                                              |
| --------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------ |
| 라우트 search params              | `?inputType=VOICE&topics=...` | 매 단계 URL이 길어지고 이전 단계로 돌아갈 때 search를 수동으로 이어 붙여야 한다. 주소 공유 요구도 없다 |
| 단일 라우트 + 컴포넌트 `useState` | 7단계를 한 화면 step 전환으로 | 브라우저/안드로이드 뒤로가기가 단계 단위로 동작하지 않는다(#288 뒤로가기 복원과 충돌)                  |
| `sessionStorage` persist          | 새로고침에도 초안 유지        | 시안·기획에 요구가 없다. 중간 새로고침은 처음부터 다시 고르게 하는 편이 단순하다(Q8)                   |

**Consequences** — 새로고침·딥링크로 중간 단계에 진입하면 초안이 비어 있으므로 **선행 선택이 없는 단계는
AI-01로 돌려보내는 가드**가 필요하다. 세션 생성 성공·홈 이탈 시 초기화 시점을 명시적으로 관리해야 한다.

## 시안 대조 결과

초기 시안·API 불일치와 구현 후 남은 확인 사항을 함께 기록한다.

### 확인 필요

**A. 진행 차단 — 2026-10-10 사용자 판정 완료**

- **Q1. 라우트 경로.** → **확정**: `_focus` 그룹 아래 `/interview/new/$step`
  (`answer-type|topic|cs-topics|job|stack|difficulty|confirm`, 그 외 값은 404)
- **Q2. AI면접 홈(AI-00)이 아직 없다.** → **확정**: GNB에 「AI면접」을 추가하고 새 페이지 `/interview`(앱 셸)를 만든다.
  상단 홈 버튼은 여기로 간다. 페이지는 「새 세션 시작」 진입점만 둔 자리이고 대시보드는 별도 작업
- **Q3. 세션 생성 후 이동.** → **확정 (2026-10-11 갱신)**: `/interview/sessions/$sessionId`로 이동(replace).
  - 이 작업은 **이동까지만** 책임진다. 목적지 라우트는 `beforeLoad`로 `sessionId`(양의 정수)만 검증해
    route context로 넘기는 빈 자리로 만들었다 (`_focus/interview.sessions.$sessionId.tsx`)
  - 질문 조회(`GET /interview-sessions/{sessionId}/questions`)는 `sessionId`가 생성 응답으로만 생기므로
    「시작하기」 전에 미리 받을 수 없다. 문항 화면(AI-08) 담당이 그 라우트의 `loader`에서 받고,
    `pendingComponent`로 학습과 같은 `QuizLoadingScreen`을 보여준다 (`pendingMs: 0` · `pendingMinMs` 권장)
  - AI-08이 연결되기 전까지 「시작하기」 후에는 빈 화면이 보인다
  - 이전 결정(2026-10-10): AI-08 라우트가 생기기 전까지 `/interview`로 이동(replace)

**A'. 판정 후 새로 생긴 확인 필요**

- **Q15. 모바일 하단 탭.** 하단 탭은 아이콘이 필수인데 AI면접 아이콘 시안이 없다. 지금은 **데스크톱 GNB에만** 노출되고
  모바일(`md` 미만)에서는 진입 경로가 없다. 아이콘 확정 시 `HEADER_NAV_ITEMS` → `NAV_ITEMS`로 옮긴다
- **Q16. GNB 순서.** 시안에 위치 정의가 없어 마지막(마이그래빗 뒤)에 두었다
- **Q17. 생성 실패 대체 문구.** 서버 `message`가 문자열이 아닐 때만 "세션을 만들지 못했어요. 다시 시도해 주세요."
  (기존 실패 토스트 어투를 따름). 기획 문구 확인 필요
- **Q18. CS 선택 카운터.** 초기 명세의 `n/전체 개수`가 현재 UI에 없다. 복원 또는 명세 제외 결정 전까지 AC-3 미완료
- **Q19. 생성 중 이전·홈 이동.** 시작 버튼 연타는 막지만 이전·홈은 누를 수 있다. 요청이 끝나면 이동 콜백이 실행되므로
  대기 중 이탈 정책과 실제 브라우저 동작 확인 필요
- **Q20. 난이도 하 문구.** 현재는 "기본 개념"을 사용한다. 시안의 "기본 기념" 표기를 그대로 반영할지는 미확정
