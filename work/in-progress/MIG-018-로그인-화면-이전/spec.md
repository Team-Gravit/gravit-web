# MIG-018 — 로그인 화면 이전

## 배경 · 목표

`apps/web`의 `/`는 아직 스캐폴드다(`HomePage`, "Gravit Web" 제목만 있는 placeholder).
legacy의 `/`는 소셜 로그인 3종 버튼이 있는 로그인 화면이다.

MIG-005 Issue 3에서 로그인 **로직**(인가 URL 조회 · 콜백 교환 · 로그아웃)은 완성했지만 그것을
부르는 화면이 없다. `useOauthLogin`에 호출부가 생겨야 "웹에서 로그인이 동작한다"가 사실이 된다.
MIG-005는 로그인 화면 UI를 Out of Scope로 명시해 이 작업으로 분리했다.

GitHub Issue [#203](https://github.com/Team-Gravit/gravit-web/issues/203) · 브랜치 `feat/#203/login-screen`

## 범위

| 대상                     | 내용                                                       |
| ------------------------ | ---------------------------------------------------------- |
| `shared/ui/layout`       | 로그인·온보딩·리그가 공유하는 진입 레이아웃과 배경 이미지  |
| `shared/ui/logo`         | 심볼 마크(`GravitSymbol`) 추가                             |
| `shared/lib`             | 뷰포트 판정 훅                                             |
| `features/auth-login/ui` | provider 3종 소셜 로그인 버튼                              |
| `pages/login`            | 화면 조립 (넓은 화면 · 좁은 화면)                          |
| `app/routes/index.tsx`   | 스캐폴드 대신 로그인 화면 연결 + 로그인 사용자 재진입 처리 |
| `pages/home`             | 스캐폴드 제거                                              |

## Out of Scope

- **인증 게이트(`_protected`)** — MIG-005 Issue 4가 담당한다. 이 작업은 `/` 라우트 자신의
  재진입 처리(L1)만 옮긴다
- **로그인 실패 알림(toast)** — `FEAT-017`. 이 화면이 생기면 사용자가 실제로 도달하지만,
  알림 자체는 별도 작업이다
- **콜백 화면(`/login/oauth2/code/$provider`)의 시각 디자인** — 시안이 없다. 현재의 빈 화면 유지
- **온보딩 화면 · 리그 화면** — 레이아웃을 공유하지만 화면 자체는 별도 작업
- **카카오 `#FFE240` · 네이버 `#00B116`의 토큰 승격** — 남의 브랜드 색이라 제품 디자인 시스템과
  성격이 다르다. 로그인 버튼 안의 상수로 둔다
- **`shared/ui/button`에 소셜 variant 추가** — 도메인(auth) 색이 shared로 올라가면 디자인
  시스템이 오염된다

## 용어 정의 (Ubiquitous Language)

| 용어               | 정의                                                                             |
| ------------------ | -------------------------------------------------------------------------------- |
| provider           | 소셜 로그인 제공자. `'google' \| 'kakao' \| 'naver'` (생성 타입 `LoginProvider`) |
| 워드마크           | "Gravit!" 글자가 들어간 가로로 긴 로고 (`logo-gradient.svg` · `logo-mono.svg`)   |
| 심볼               | 토끼 마크만 있는 정사각형 로고 (`logo-rabbit.svg`)                               |
| 넓은 화면 (wide)   | `min-width: 768px` — Figma WEB 시안 대상                                         |
| 좁은 화면 (narrow) | `768px` 미만 — Figma AOS 시안 대상. 네이티브 WebView가 여기 해당한다             |
| 진입 레이아웃      | 로그인·온보딩이 공유하는 배경·헤더 껍데기 (legacy `EntryLayout`)                 |

## 현행 동작 기준선

> legacy 코드를 읽고 관찰 가능한 동작만 적는다. 옳고 그름은 여기서 판단하지 않는다.

| #   | 동작                                                                                                                               | 확인한 위치 (legacy 경로)                           |
| --- | ---------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| L1  | `/` 진입 시 accessToken이 있으면 화면을 그리지 않고 `/main`으로 redirect한다                                                       | `pages/index.tsx` `beforeLoad`                      |
| L2  | 제목은 「교육행성에 어서 오세요. Gravit!」, 안내문은 「회원 서비스 이용을 위해 로그인 해주세요.」이다                              | 〃                                                  |
| L3  | 소셜 버튼은 **google → kakao → naver 순서**로 3개 있다                                                                             | 〃 `OAUTH_PROVIDERS`                                |
| L4  | 버튼 문구는 「Google로 시작하기」·「카카오로 시작하기」·「네이버로 시작하기」이다                                                  | `features/login/ui/social-login-button.tsx`         |
| L5  | 각 버튼 좌측에 provider 로고 이미지가 있고 `alt`는 provider 이름(`google`·`kakao`·`naver`)이다                                     | 〃                                                  |
| L6  | 버튼을 누르면 해당 provider의 인가 URL을 조회해 그 주소로 이동한다 (MIG-005 기준선 D1)                                             | 〃 + `entities/login/model/useOauthLogin.ts`        |
| L7  | 좁은 화면에서는 「로그인」 제목의 상단바가 보이고, 배경 이미지가 없으며, 심볼 로고를 쓴다                                          | `shared/ui/layout/entry-layout.tsx`                 |
| L8  | 넓은 화면에서는 우주 배경 이미지가 풀블리드로 깔리고, 카드 위쪽에 워드마크 로고와 「그래빗과 함께 CS 지식을 마스터해요!」가 보인다 | 〃                                                  |
| L9  | 화면에 **개인정보 처리방침·이용약관 링크가 없다**                                                                                  | `pages/index.tsx` 전체                              |
| L10 | 인가 URL 조회 중에도 **로딩 표시나 버튼 비활성이 없다** — 연타하면 요청이 그만큼 나간다                                            | `social-login-button.tsx` (`mutate`만 호출)         |
| L11 | 뷰포트 폭이 정확히 `768px`이면 상단바는 좁은 화면용인데 카드 스타일은 넓은 화면용이 적용된다                                       | `use-responsive.ts`(`maxWidth: 768`) + `md:` 클래스 |

> L11은 legacy의 판정 기준이 두 개(`react-responsive`의 `maxWidth: 768`, Tailwind `md:`의
> `min-width: 768px`)여서 생긴 어긋남이다. 결함이지만 여기서는 사실만 기록한다.

### 확인 필요 — 판정 결과 (2026-09-09)

1. **개인정보 처리방침 · 이용약관 링크** → **포함한다.** legacy에는 없지만(L9) 시안에 있고
   Figma가 SoT다. 링크 대상 `/privacy` · `/terms`는 MIG-004에서 이전 완료라 이동 대상이 존재한다.
   구현 착수 시 Dev Mode에서 문구와 배치를 확인한다.
   → 이 판정 과정에서 **두 화면 자체가 디자인 시스템을 따르지 않는다**는 사실이 드러났다
   (타이포 토큰 대신 `text-2xl font-bold`, 색 토큰 미지정, 좁은 화면 대응 없음).
   이번 작업 범위가 아니므로 `FIX-020`으로 분리했다.
2. **인가 URL 조회 중 표시** → **legacy 그대로 둔다**(표시 없음). 연타 방지는 `FIX-019`로 분리.
   이전 작업에 동작 변경을 섞지 않아, 검증에서 무엇 때문에 달라졌는지 구분할 수 있게 한다.
3. **`768px` 경계** → **Tailwind `md`(≥768px) 하나로 통일한다.** 훅과 클래스가 같은 값을 본다.
   정확히 768px일 때 legacy는 상단바만 좁은 화면이었으나 새 구현은 넓은 화면으로 일관된다.
   L11은 판정 기준이 두 개여서 생긴 결함이므로 새 코드에 복사하지 않는다.
   → `checklist.md`의 **의도적으로 바꾼 것**에 기록한다.

## 확정 명세 · 검증 기준

> 확인 필요 3건이 2026-09-09에 판정되어 확정했다.

- [ ] **AC-1** (범위: 통합)
      Given 저장소에 accessToken이 없다
      When `/`로 진입한다
      Then 「Google로 시작하기」·「카카오로 시작하기」·「네이버로 시작하기」 버튼이 이 순서로 3개 렌더된다

- [ ] **AC-2** (범위: 통합)
      Given 저장소에 accessToken이 없다
      When 「카카오로 시작하기」를 클릭한다
      Then `kakao`의 인가 URL 조회 요청이 **1회** 나간다

- [ ] **AC-3** (범위: 통합)
      Given 저장소에 accessToken이 `'t1'`으로 들어 있다
      When `/`로 진입한다
      Then 소셜 로그인 버튼이 렌더되지 않고 `/main`으로 이동한다

- [ ] **AC-4** (범위: 통합)
      Given 뷰포트가 `min-width: 768px`을 만족한다
      When `/`로 진입한다
      Then 「그래빗과 함께 CS 지식을 마스터해요!」가 렌더되고 「로그인」 상단바는 렌더되지 않는다

- [ ] **AC-5** (범위: 통합)
      Given 뷰포트가 `min-width: 768px`을 만족하지 않는다
      When `/`로 진입한다
      Then 「로그인」 상단바와 「교육행성에 어서 오세요. Gravit!」가 렌더된다

- [ ] **AC-6** (범위: 단위)
      Given `GravitSymbol`을 렌더한다
      When `variant` prop을 넘기지 않는다
      Then 심볼 SVG가 렌더되고 `GravitLogo`의 워드마크는 렌더되지 않는다

- [ ] **AC-7** (범위: 통합)
      Given `/`가 렌더되어 있다
      When 「개인정보 처리방침」과 「이용약관」 링크를 확인한다
      Then 각각 `href`가 `/privacy` · `/terms`이고 링크가 하나씩 있다
