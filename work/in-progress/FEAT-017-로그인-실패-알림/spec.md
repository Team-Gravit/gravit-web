# FEAT-017 — 로그인 실패를 사용자에게 알린다

## 배경 · 목표

`MIG-005` Issue 3(#201)에서 OAuth 콜백을 옮기면서 **에러를 알리는 경로만 빠졌다.** legacy는 콜백 실패 시
`toast.error(message)`로 사유를 띄운다(기준선 D7). `apps/web`에는 그때 토스트가 없어 옮기지 못했다.

지금은 `shared/ui/toast`가 있지만 로그인 실패는 여전히 알리지 않는다. 사용자는 왜 로그인이 안 됐는지 알 수
없고, 버튼이 풀리거나 로그인 화면으로 돌아온 것만 보게 된다.

## 범위

아래 세 경로의 실패에서 공통 토스트를 띄우고, 그 동작을 테스트로 고정한다.

| 경로                                      | 지금 동작             |
| ----------------------------------------- | --------------------- |
| 브라우저: 인가 주소 조회 실패             | 버튼만 풀림           |
| 브라우저: 콜백의 토큰 교환 실패           | `/`로 이동, 안내 없음 |
| 앱: SDK 오류 · 시간 초과 · 토큰 교환 실패 | 버튼만 풀림           |

## Out of Scope

- 사유별 문구 구분과 서버 `message` 노출
- `NAT-025`의 `UNSUPPORTED` 토스트 (`NAT-025` Issue 3)
- `docs/fe-implement-spec/o-3/o-3.md`의 O.3-F10 온보딩 제출 실패 알림. 이 문서가 `FEAT-017`을 가리키지만 로그인 실패가 아니다. 별도 번호로 뺀다

## 기술 결정

**Context** — 이 문서가 남겨 둔 결정은 세 가지였다. 표시 수단, 토스트 구현, 문구다.

**Decision**

- **표시 수단은 기존 `shared/ui/toast`를 쓴다.** 콜백 실패는 화면을 떠나 `/`로 이동하므로 화면 안 문구로는 남길 수 없다
- **문구는 `로그인에 실패했습니다. 다시 시도해 주세요.` 하나로 통일한다** (2026-11-04 사용자 확정)
- **문구 상수는 `features/auth-login/model/login-outcome.ts`에 둔다.** 표시는 `pages`가 한다

**Alternatives**

| 안                    | 거부 이유                                                                    |
| --------------------- | ---------------------------------------------------------------------------- |
| 서버 `message` 그대로 | 사용자용 문구인지 확인되지 않았고, SDK 오류와 시간 초과에는 서버 문구가 없다 |
| 로그인 화면 안 문구   | 콜백 경로는 이동 뒤 상태를 넘겨야 하고, 시안도 없다                          |

**Consequences**

- (+) 경로와 관계없이 같은 문구로 안내한다
- (−) 사유를 구분하지 못한다. 네트워크 문제와 서버 문제가 같은 문구로 보인다
- (−) legacy의 "서버 `message` 표시"와 달라진다. 의도한 변경이다

## 확정 명세 · 검증 기준

토스트 `로그인에 실패했습니다. 다시 시도해 주세요.`를 `LOGIN_FAILED`라 부른다.
