## 4. 측정

spec `측정 조건`과 같다. 이번 단계 변경을 모두 넣은 빌드를 4174에, `develop`을 4173에 띄운다.

| 측정          | 회차       | 판정                                            |
| ------------- | ---------- | ----------------------------------------------- |
| 모바일 실측   | 번갈아 5회 | LCP가 기준선보다 흔들림(약 0.3초) 이상 줄어든다 |
| 모바일 계산   | 3회        | 나빠지지 않는다 (기록용)                        |
| 데스크톱 계산 | 3회        | 나빠지지 않는다 (기록용)                        |

- 1단계만으로는 1차 목표(3.5초)에 닿지 않을 것으로 본다(실험 4.07초). 목표 판정은 범위 3 ~ 5 뒤에 한다
- 로그인한 사용자가 `/main`으로 바로 들어올 때 첫 청크 증가분(gzip 약 3.3 KB + 로고)의 영향은 `/main` 계산 3회로 확인한다 — 흔들림 안이면 통과
  - **실행 중 변경:** `/main`은 로그인이 필요해 로그아웃 상태의 Lighthouse가 `/`로 이동해 버린다. 같은 첫 청크를 받는 공개 화면 `/terms`로 대신 쟀다 (결과는 spec `결과 — 1단계`)

## 6. 진행 전 확인

1. **로고가 4 KiB 미만으로 줄면 JS에 넣을지** — 넣으면 로고가 글자와 함께 바로 보이고 요청 1개가 줄지만(느린 4G에서 약 0.6초 늦게 뜨던 것이 사라짐), 모든 화면의 첫 청크가 그만큼(base64라 약 1.33배) 커진다. 안 넣으면 지금처럼 화면을 그린 뒤 따로 받는다. **결과 크기를 보고 측정으로 정하는 것을 제안한다**
2. **`work/in-progress/`에 이미 11개 작업이 있다** (`work-management.md` §3은 하나만 허용). 승인되면 규칙대로 이 작업을 옮기되, 기존 11개 정리는 이 작업 범위 밖이다 — 별도로 정리 방향을 정해야 한다
