## 3. 성능

`/main` 모바일 LCP: 412×915 · DPR 2.625 · 9 Mbps/RTT 60ms · CPU 4배, 번갈아 5회, 고정 응답 서버. LCP 요소는 전후 모두 `<img>`.

| 빌드    | 중앙값(ms) | 평균(ms) | 흔들림(ms) |
| ------- | ---------- | -------- | ---------- |
| develop | 4,280      | 4,258    | 904        |
| 변경    | 4,516      | 4,550    | 612        |

중앙값 +236ms, 평균 +292ms. 흔들림보다 작지만 5회 중 4회 변경 쪽이 느렸고, `/users` 응답을 기다린 뒤 화면을 그리는
구조상 예상된 비용이다. **오차로 판정하지 않는다.** 사용자 채택 여부 확인 필요. 이 측정은 AC-15~18 반영 전 빌드다. 반영 후 재측정은 하지 않았다.

### 중간에 막혔던 지점 — 스킬에 반영할 것

- **`ai-quick`으로 시작했다가 승격했다.** 인증 흐름이 얽히고 `MIG-005`에 작업 항목이 있어 제외 조건에 걸렸다.
  온보딩 · 세션 가드 요청은 처음부터 `ai-plan`으로 가는 것이 맞다.
- **부모 라우트의 `errorComponent`는 자식 에러까지 받는다.** 자식에 `errorComponent`가 없으면 경계를 만들지 않기
  때문이다(`Match.tsx`). 게이트 전용 화면은 에러 표식으로 구분해야 한다.
- **새로 쓴 코드도 라이브러리 deprecated 경고를 확인해야 한다.** `ensureQueryData`를 썼다가 사용자가 편집기 경고로 발견해 `query`로 바꿨다.
- **MSW로는 게이트 지연을 잴 수 없다.** 요청이 네트워크를 타지 않아 `/users` 왕복이 빠진다. 고정 응답 서버를 썼다.
- **측정용 워크트리를 깊은 임시 경로에 만들면 `git worktree remove`가 `Filename too long`으로 실패한다.**
  Node `fs.rmSync`로 지웠다.
