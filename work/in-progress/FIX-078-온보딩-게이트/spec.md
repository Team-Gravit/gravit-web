# FIX-078 — 온보딩 미완료 사용자의 서비스 화면 진입 차단

## 배경 · 목표

`_authenticated` 가드가 토큰 유무만 보기 때문에 온보딩을 마치지 않은 사용자가 `/main`을 포함한 인증
화면 전체에 들어갈 수 있다. 온보딩 도중 앱을 다시 켜기만 해도 `/` → `/main`으로 이동해 온보딩을
건너뛴다. 온보딩 미완료 사용자는 `/onboarding`에만 머물게 한다.

`MIG-005` Issue 4에 같은 요구가 있지만 해당 작업은 보류 상태이고 세션 상태 재설계까지 포함한다.
여기서는 온보딩 판정과 그 판정에 필요한 대기·실패 화면만 분리한다.

## 범위

- `_authenticated` 진입 시 `GET /api/v1/users`의 `isOnboarded`로 목적지를 판정한다
- 판정 중 대기 화면, 조회 실패 시 재시도 화면
- 완료 화면 「홈으로」를 `replace` 이동으로 변경해 뒤로 가기로 완료 화면에 돌아오지 않게 한다
- 넓은 화면 온보딩에 좁은 화면과 같은 「이전」(로그아웃 후 로그인 화면 이동) 버튼 추가
- 게이트가 읽는 사용자 쿼리의 `gcTime`을 `Infinity`로 둔다. 헤더 없는 화면에 5분 넘게 머문 뒤 이동해도 재조회로 막히지 않게 한다
- 세션이 어떤 경로로 끝나도 쿼리 캐시를 비운다. `gcTime` 때문에 이전 계정의 값이 남지 않게 한다

## Out of Scope

- `MIG-005`의 나머지: 세션 상태 모델 재설계, 웹↔네이티브 토큰 메시지, 401 갱신 흐름
- 공개 라우트(`/`, `/terms`, `/privacy`, `/restore`, `/withdraw`, `/withdraw-email-sent`, OAuth 콜백)의 접근 정책
- 404 화면의 게이트 적용. 경로가 라우트 트리 밖이라 서비스 화면이 아니다
- 다른 탭에서 온보딩을 마친 경우의 캐시 동기화. 새로고침으로 해결되며 별도 작업으로 다룬다
- 백엔드 API의 온보딩 권한 검사

## 용어 정의 (Ubiquitous Language)

| 용어        | 정의                                                                 |
| ----------- | -------------------------------------------------------------------- |
| 게이트      | `_authenticated` 라우트의 `beforeLoad`에서 수행하는 진입 판정        |
| 미온보딩    | 토큰이 있고 `GET /api/v1/users`의 `isOnboarded`가 `false`인 사용자   |
| 온보딩 완료 | 토큰이 있고 `GET /api/v1/users`의 `isOnboarded`가 `true`인 사용자    |
| 판정 불가   | 세션은 남아 있지만 사용자 조회가 실패한 상태 (5xx, 네트워크 오류 등) |

## 시안 대조 결과

`docs/implementation-status.md`의 에러 화면 시안은 `E.1`(401)과 `E.2`(404)뿐이고 조회 실패 화면은 없다.
시안 없음 (2026-11-04 대장 기준 확인, Figma 파일 직접 조회는 하지 않음).

### 확인 필요

1. **넓은 화면 「이전」 버튼의 시각 확인.** 시안에는 없는 요소다. 게이트가 들어가면 잘못된 계정으로 로그인한
   웹 사용자가 빠져나갈 방법이 없어져 추가하기로 사용자가 판정했다 (2026-11-04). 유리 카드 위 표현은 디자이너
   확인이 필요하다. 구현을 막지는 않는다.
2. **조회 실패 화면.** 시안이 없다. 계획안은 기존 `CardRetryStatus`의 문구·버튼을 재사용한다.

## 확정 명세 · 검증 기준

- [x] **AC-1** (범위: 통합)
      Given 토큰이 있고 사용자 조회가 `{ isOnboarded: false }`다
      When `/main`, `/learning`, `/my/summary`, `/settings`, `/notifications`로 각각 진입한다
      Then 모든 경우 최종 경로가 `/onboarding`이다
- [x] **AC-2** (범위: 통합)
      Given 토큰이 있고 사용자 조회가 `{ isOnboarded: false }`다
      When `/`로 진입한다
      Then 최종 경로가 `/onboarding`이다
- [x] **AC-3** (범위: 통합)
      Given 토큰이 있고 사용자 조회가 `{ isOnboarded: false }`다
      When `/onboarding`으로 진입한다
      Then 최종 경로가 `/onboarding`이고 사용자 조회 요청은 1회다
- [x] **AC-4** (범위: 통합)
      Given 토큰이 있고 사용자 조회가 `{ isOnboarded: false }`다
      When history state `fromOnboarding: true`로 `/onboarding/success`에 진입한다
      Then 최종 경로가 `/onboarding`이다
- [x] **AC-5** (범위: 통합)
      Given 토큰이 있고 사용자 조회가 `{ isOnboarded: true }`다
      When `/main`으로 진입한다
      Then 최종 경로가 `/main`이다
- [x] **AC-6** (범위: 통합)
      Given 토큰이 있고 사용자 조회가 `{ isOnboarded: true }`다
      When `/onboarding`으로 진입한다
      Then 최종 경로가 `/main`이다
- [x] **AC-7** (범위: 통합)
      Given 온보딩 폼에서 제출이 성공했고 응답이 `{ isOnboarded: true }`다
      When 완료 화면으로 이동한다
      Then 최종 경로가 `/onboarding/success`이고 사용자 조회 요청이 추가로 발생하지 않는다
- [x] **AC-8** (범위: 통합)
      Given 온보딩 완료 사용자가 완료 화면에 있다
      When 「홈으로」를 누른 뒤 뒤로 가기를 한다
      Then 완료 화면의 「계정 생성 완료!」가 렌더되지 않는다
- [x] **AC-9** (범위: 통합)
      Given 토큰이 있고 사용자 조회가 `500`이다
      When `/main`으로 진입한다
      Then 「사용자 정보를 불러오지 못했어요.」와 「다시 시도」가 렌더되고 경로는 `/onboarding`이나 `/`로 바뀌지 않는다
- [x] **AC-10** (범위: 통합)
      Given AC-9의 화면이고 사용자 조회가 이제 `{ isOnboarded: true }`다
      When 「다시 시도」를 누른다
      Then `/main` 화면이 렌더된다
- [x] **AC-11** (범위: 통합)
      Given 사용자 조회가 `401`이고 토큰 재발급도 `401`이다
      When `/main`으로 진입한다
      Then 저장소 토큰이 `null`이고 최종 경로가 `/`다
- [x] **AC-12** (범위: 통합)
      Given 사용자 조회 응답이 아직 도착하지 않았다
      When `/main`으로 진입한다
      Then `/main` 화면이 렌더되지 않는다. 응답이 지연되면 대기 표시가 렌더된다
- [x] **AC-13** (범위: 통합)
      Given 넓은 화면의 온보딩 폼이다
      When 「이전」을 누른다
      Then 저장소 토큰이 `null`이고 최종 경로가 `/`다
- [x] **AC-14** (범위: 통합)
      Given 인증 화면의 자식 라우트가 렌더 중 에러를 던진다
      When 해당 화면에 진입한다
      Then 「사용자 정보를 불러오지 못했어요.」가 렌더되지 않는다
- [x] **AC-15** (범위: 통합)
      Given 게이트가 사용자 조회를 1회 마쳤고 그 쿼리를 구독하는 화면이 없다
      When 5분이 지난 뒤 다시 게이트를 통과한다
      Then 사용자 조회 요청은 그대로 1회다
- [x] **AC-16** (범위: 통합)
      Given 쿼리 캐시에 데이터가 있고 세션이 있다
      When 사용자 조회와 재발급이 모두 `401`이어서 세션이 끝난다
      Then 쿼리 캐시가 비어 있고 최종 경로가 `/`다
- [x] **AC-17** (범위: 통합)
      Given 게이트가 사용자 조회 응답을 기다리는 중이다
      When 세션이 끝난다
      Then 재시도 화면이 렌더되지 않고 최종 경로가 `/`다
- [x] **AC-18** (범위: 단위)
      Given 쿼리 캐시에 데이터가 있다
      When 재발급으로 토큰만 바뀐다
      Then 캐시 데이터가 그대로 남는다
- [x] **AC-19** (범위: 통합)
      Given 사용자 조회 응답의 `error`가 `USER_4041`이다
      When `/main`으로 진입한다
      Then 저장소 토큰이 `null`이고 최종 경로가 `/`이며 재시도 화면이 렌더되지 않는다
- [x] **AC-20** (범위: 통합)
      Given 재시도 화면이고 사용자 조회 응답의 `error`가 이제 `USER_4041`이다
      When 「다시 시도」를 누른다
      Then 저장소 토큰이 `null`이고 최종 경로가 `/`다
- [x] **AC-21** (범위: 통합)
      Given 사용자 조회가 `error` 코드 없는 `404`다
      When `/main`으로 진입한다
      Then 저장소 토큰이 유지되고 재시도 화면이 렌더된다
