# FEAT-060 — 상태 표시줄 영역 배경을 화면 배경과 통일

## 배경 · 목표

iOS 앱에서 시계·배터리가 있는 상태 표시줄 영역은 화면과 상관없이 항상 흰색이다.
이 영역은 웹이 아니라 네이티브 View(`apps/native/app/index.tsx`의 `paddingTop: insets.top`,
`backgroundColor: '#ffffff'`)가 칠한다. 리그(보라 그라데이션)나 앱 셸(`bg-bg-2`)처럼 배경이
흰색이 아닌 화면에서는 맨 위에 흰 띠가 생겨 화면이 끊겨 보인다.

목표는 상태 표시줄 영역에 각 화면의 배경이 그대로 이어지게 하는 것이다. Safari 브라우저에서도
상단 영역 색이 화면과 어울리게 한다.

## 범위

- `apps/native/app/index.tsx`: WebView가 상태 표시줄 뒤까지 그려지도록 상단 여백 제거
- `apps/web/index.html`: viewport에 `viewport-fit=cover` 추가
- `apps/web`: 화면 맨 위에 붙는 요소에 상단 안전 영역 여백(`env(safe-area-inset-top)`) 적용
- Safari: 상단 영역 색(`theme-color` 또는 페이지 배경) 지정

## Out of Scope

- 하단 홈 인디케이터 영역 색 통일 (상단과 같은 방식이 필요하면 새 항목으로 뽑는다)
- Android 상태 표시줄 색 (iOS 확인 후 판단)
- 화면 레이아웃·간격 개선. 안전 영역 여백 추가 외의 시각 변경은 하지 않는다
- 데스크톱 헤더(`widgets/header`). 모바일 폭에서는 숨겨져 있다

## 용어 정의 (Ubiquitous Language)

| 용어             | 정의                                                                      |
| ---------------- | ------------------------------------------------------------------------- |
| 상태 표시줄 영역 | 화면 맨 위 시계·배터리가 있는 영역. 높이는 `env(safe-area-inset-top)`     |
| 안전 영역 여백   | 콘텐츠가 상태 표시줄에 가리지 않도록 맨 위 요소 안쪽에 주는 여백          |
| 맨 위 요소       | 화면에서 상태 표시줄 바로 아래에 오는 요소 (제목 막대, 퀴즈 상단 막대 등) |

## 기술 결정 (ADR)

### 상태 표시줄 영역을 누가 칠하는가

**Context** — 지금은 네이티브 View가 흰색으로 칠하고, 웹은 그 아래에서 시작한다. 화면마다
배경이 다르고 리그는 그라데이션이라 단색 하나로는 맞출 수 없다.

**Decision** — 웹이 상태 표시줄 뒤까지 그린다. 네이티브는 상단 여백을 없애고, 웹은
`viewport-fit=cover`로 안전 영역 값을 받아 맨 위 요소 안쪽에 여백을 준다.

**Alternatives**

| 안                                    | 내용                                                    | 거부 이유                                                             |
| ------------------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------- |
| 웹이 배경색을 네이티브에 알림         | 라우트마다 배경색을 선언하고 postMessage로 View 색 변경 | 단색만 가능해 리그 그라데이션이 끊긴다. 화면 전환 때 색이 늦게 바뀐다 |
| 네이티브 View를 앱 대표색 하나로 고정 | `#ffffff` 대신 고정색 하나                              | 화면마다 배경이 달라 어느 한 색으로도 모든 화면을 맞출 수 없다        |

**Consequences**

- 장점: 각 화면의 배경이 그대로 이어진다. 그라데이션·이미지 배경도 맞는다. 네이티브와 주고받는
  통신이 필요 없다.
- 단점: 맨 위 요소가 있는 모든 화면에 여백을 줘야 한다. 한 곳이라도 빠지면 콘텐츠가 시계·배터리
  밑으로 들어간다. 새 화면을 만들 때도 이 규칙을 지켜야 한다.
- 단점: `viewport-fit=cover`는 하단 안전 영역 값도 켠다. 하단 고정 요소(바텀탭·토스트)가
  달라지는지 확인해야 한다.

---

## 확인 필요

- iOS WebView의 `contentInsetAdjustmentBehavior` 기본값이 안전 영역을 이중으로 적용하지 않는지
- Safari의 상단 영역 색 규칙이 iOS 버전마다 다르다(`theme-color` 지원 여부). 실기기 iOS 버전으로 확인
- 리그처럼 배경이 `fixed`인 화면과 앱 셸 배경(`bg-bg-2`)이 상태 표시줄 뒤까지 깔리는지
