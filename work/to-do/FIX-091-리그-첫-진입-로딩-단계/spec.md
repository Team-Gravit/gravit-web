# FIX-091 — 리그 첫 진입이 로딩중 → 스켈레톤 → 순위로 세 번 바뀌고 줄 높이가 달라 흔들림

## 배경 · 목표

리그 화면은 CLS가 0.000(좋음)이지만 첫 진입 때 화면이 세 번 바뀌고 순위 목록이 흔들린다(`performance/real-env/results/REPORT.md` §3-③).
스켈레톤이 새 줄로 「교체」되는 것은 CLS가 세지 않는다. **성능 지표가 아니라 화면 다듬기 작업이다.**
`FIX-059`(다시 불러올 때 로딩 화면)와 다른 문제다 — 이건 첫 진입이다.

## 재현

모바일 웹 · 스텁 응답 600ms로 `/league`를 열고 시간 순으로 찍는다(`cls-probe/film_league/`).

1. ~1.0초: 전체 화면 「로딩중」 — `pages/league/ui/league-page.tsx`, 프로필 · 홈 쿼리 대기
2. ~1.1~1.7초: 헤더(티어)와 순위 줄 스켈레톤 — 줄 높이 약 76px, 간격 88px
3. 1.7초~: 실제 순위 줄 — 줄 높이 약 62px, 간격 74px. 바뀌는 순간 목록 전체가 촘촘해진다

요청은 두 단계로 이어진다: `league/home` · `ranking/me` → `league/{id}` · `ranking/user-leagues/page/0`.

## 범위

- 순위 줄 스켈레톤 높이를 실제 줄에 맞추기
- 「로딩중」 → 스켈레톤 두 단계를 한 단계로 줄일지 검토

## Out of Scope

- 다시 불러올 때의 로딩 화면 (`FIX-059`)
- 리그 배경 · 아레나 레이아웃

## 확인 필요

- 첫 진입의 전체 화면 「로딩중」을 스켈레톤으로 바꿔도 되는지 (시안에 로딩 상태 프레임이 있는지)

## 확정 명세 · 검증 기준

- [ ] **AC-1** (범위: 통합)
      Given 모바일 웹 · 스텁 응답 600ms
      When `/league`를 시간 순으로 찍는다
      Then 첫 번째 순위 줄 스켈레톤과 실제 줄의 높이 · 시작 위치 차이가 각각 2px 이하다
