# REF-064 — Pretendard 글꼴을 단일 subset 파일로 교체

GitHub Issue: #319 · 관련 #299 · 브랜치 `perf/#319/font-subset`

## 배경 · 목표

본문 글꼴은 `PretendardVariable.woff2` 전체(2,057,688 B, 한글 11,172자)를 자체 호스팅한다. 첫 방문마다 2MB를 받고,
이 응답이 첫 화면의 이미지·API와 대역폭을 나눠 쓴다. 앱에서 쓰는 글자만 남긴 **단일 subset 파일(653,456 B)** 로 바꿔
받는 양을 줄이고 글꼴이 더 일찍 적용되게 한다. 화면에 보이는 글꼴과 굵기는 바꾸지 않는다.

근거: `local-docs/performance/evidence/2026-10-21_font-subset/` (로컬 전용)

## 비교한 방식 (2026-10-21 측정)

녹화 응답 재생 · CPU 4x · Fast 4G · 캐시 끔 · 번갈아 5회 중앙값. 절대값은 실행마다 달라 **같은 실행 안에서만** 비교한다.
흔들림 = 같은 빌드를 다른 포트에서 다시 잰 차이.

| 방식                        | `/main` LCP           | `/learning` LCP | 개념 노트 LCP | 글꼴 도착 (개념 노트) | 받는 양   | 판단                |
| --------------------------- | --------------------- | --------------- | ------------- | --------------------- | --------- | ------------------- |
| 현행 — 전체 자체 호스팅     | 4.08s                 | 5.11s           | 7.64s         | 5.64s                 | 2,010KB   | 기준                |
| jsdelivr dynamic subset     | 4.26s                 | 5.43s           | **9.10s**     | 8.37s                 | 173~379KB | ❌ 개념 노트 +1.46s |
| jsdelivr + `preload` 비차단 | (2회차) +0.08s vs CDN | +0.35s vs CDN   | +0.28s vs CDN | —                     | 같음      | ❌ 이득 없음        |
| **단일 subset 자체 호스팅** | **4.13s**             | **4.99s**       | **7.75s**     | **4.01s**             | **638KB** | ✅ 채택 후보        |
| 흔들림 (subset 재측정)      | 0.09s                 | 0.04s           | 0.14s         |                       |           |                     |

4회차 — 자체 호스팅 dynamic subset 추가 (`pretendard@1.3.9` 조각 92개를 `fonts/`에 두고 `@font-face` 93개)

| 방식                       | `/main` LCP | `/learning` LCP | 개념 노트 LCP | 글꼴 도착 (`/main` · `/learning` · 개념 노트) | 받는 양 · 요청   |
| -------------------------- | ----------- | --------------- | ------------- | --------------------------------------------- | ---------------- |
| 현행 — 전체 자체 호스팅    | 4.05s       | 5.22s           | 7.72s         | 6.00 · 6.26 · 5.70s                           | 2,010KB · 1      |
| 단일 subset 자체 호스팅    | 4.32s       | 5.10s           | 7.97s         | **4.60 · 4.12 · 4.01s**                       | 638KB · 1        |
| dynamic subset 자체 호스팅 | 4.64s       | 5.46s           | 7.96s         | 6.33 · 4.99 · 7.39s                           | 158~361KB · 6~14 |
| 흔들림 (dynamic 재측정)    | 0.22s       | 0.03s           | 0.20s         |                                               |                  |

- **LCP는 현행과 같은 수준**이다. 단일 subset의 차이는 3회차 +0.05 · −0.12 · +0.11s, 4회차 +0.27 · −0.12 · +0.26s로
  흔들림(0.03~0.22s) 근처에서 오간다. LCP는 JS 첫 청크와 이미지가 결정하고 있어 글꼴로는 크게 움직이지 않는다
- **글꼴 도착은 단일 subset이 두 회차 모두 가장 빠르다** — 현행보다 1.4~2.1s. 대체 글꼴로 보이는 시간이 그만큼 줄어든다
- dynamic subset은 글자가 배치될 때 해당 조각을 요청하므로, 마크다운이 늦게 그려지는 개념 노트에서 글꼴 요청 14~15건이 늦게 시작된다.
  자체 호스팅해도 개념 노트 글꼴 도착이 7.39s로 늦다 — **늦은 요청은 CDN이 아니라 dynamic subset 구조 탓**이다.
  다만 LCP 손해는 CDN(+1.46s)보다 작다(+0.25s) → CDN 손해의 상당 부분은 외부 연결 쪽이다
- 외부 CSS가 화면을 막는 시간은 원인이 아니었다 — CSS는 0.56s에 도착하고 FCP는 JS 첫 청크가 정한다 (preload로 FCP가 줄지 않음)

5회차 — 최종 확인 (2026-10-24). 기준을 `develop`(`ae8cfa02`)으로 바꾸고, 이 브랜치의 변경을 그대로 빌드했다.
조건은 위와 같다. 1~4회차는 #299 브랜치 위에서 쟀으므로 절대값을 섞어 비교하지 않는다.

| 화면        | FCP (현행 → subset) | LCP (현행 → subset) | 글꼴 도착 (현행 → subset) | 흔들림 FCP · LCP |
| ----------- | ------------------- | ------------------- | ------------------------- | ---------------- |
| `/main`     | 5.35 → 5.07s        | 5.35 → 5.07s        | 7.03 → **5.28s**          | 0.01 · 0.01s     |
| `/learning` | 4.79 → 4.76s        | 6.56 → 6.67s        | 7.27 → **5.20s**          | 0.04 · 0.22s     |
| 개념 노트   | 4.69 → 4.42s        | 9.01 → 8.54s        | 6.64 → **4.84s**          | 0.16 · 0.48s     |

- 글꼴 도착은 세 화면 모두 1.8~2.1s 이르다
- LCP는 `/learning` +0.11s가 흔들림(0.22s) 안이고, 개념 노트 −0.48s는 흔들림과 같은 크기라 개선으로 보지 않는다
- FCP는 나빠진 화면이 없다. `/main` −0.28s는 흔들림(0.01s)보다 크다
- 45회 모두 글꼴 로드 오류 0 · 녹화에 없는 요청 0 · 한글 요소의 렌더 글꼴 Pretendard · 받은 글꼴 2,058KB → 654KB

## 범위

- `apps/web/src/app/styles/fonts/`의 Pretendard 파일 교체 (전체 → 단일 subset)
- `base.css`의 `@font-face` `src` 경로
- subset 생성 방법을 `docs/design-system/`에 기록 (다시 만들 수 있게)
- 전후 측정: `/main` · `/learning` · 개념 노트 FCP·LCP·글꼴 도착 시점 (위와 같은 방식, 같은 빌드 재측정 포함)

## Out of Scope

- MBC1961GulimM 글꼴 로딩 방식
- 글꼴 preload(`<link rel="preload" as="font">`) — 효과는 따로 측정해야 한다
- CDN 방식 — 위 비교로 기각
- 타이포 토큰 · 굵기 · 글꼴 종류 변경

## 용어 정의

| 용어           | 정의                                                                                  |
| -------------- | ------------------------------------------------------------------------------------- |
| 단일 subset    | 변수 글꼴 하나에서 지정한 글자만 남긴 woff2 한 파일. 모든 굵기를 담는다               |
| dynamic subset | 유니코드 범위별로 쪼갠 수십~수백 개 파일. 브라우저가 화면에 나온 글자의 조각만 받는다 |
| 글꼴 도착      | 측정 중 마지막 Pretendard 응답이 끝난 시각 (CDP `Network.loadingFinished`)            |

## 결정 (2026-10-21 사용자)

1. **단일 변수 subset을 쓴다** — 공식 정적 subset 4개(`Pretendard-{Regular,Medium,SemiBold,Bold}.subset.woff2`, 합 1,075KB)는
   직접 생성이 필요 없지만 굵기별 파일로 나뉘고 800·900을 담지 않는다. 정적 4개는 측정하지 않았다
2. **굵기 축은 자르지 않는다** (wght 45–930 유지) — 400–700으로 자르면 마크다운 h1(800)·h1 안 굵게(900)를 그릴 수 없다 (기준선 3-1)
3. **빠지는 글자를 수용한다** — 한글 11,172자 중 2,780자만 남는다. 녹화된 API 응답·소스 문자열에서는 빠지는 글자가 없었다.
   사용자가 입력한 닉네임·문의에 드문 음절이 들어오면 그 글자만 시스템 글꼴로 보인다
4. **원본 2MB 파일은 저장소에서 지운다** — 다시 만들 때는 npm `pretendard@1.3.9`에서 받는다 (`docs/design-system/README.md` §3-8)

- [ ] **AC-1** (범위: 통합)
      Given 빌드 산출물
      When `dist/assets`의 woff2 파일을 확인하면
      Then Pretendard 파일은 1개이고 크기는 2,057,688 B보다 작다
- [ ] **AC-2** (범위: 통합)
      Given `/main` · `/learning` · `/learning/units/11/concept-note`

      When 현행과 변경 빌드의 LCP 중앙값을 비교하면
      Then 세 화면 모두 변경 빌드가 현행보다 흔들림(같은 빌드 재측정 차이) 이상 느리지 않다
- [ ] **AC-4** (범위: 통합)
      Given 같은 측정

      Then 세 화면 모두 변경 빌드가 현행보다 이르다
- [ ] **AC-5** (범위: 수동)
      Given Storybook `Foundations/Typography`
      When 문서를 열면
      Then 400 · 500 · 600 · 700 굵기 예시가 Pretendard로 그려진다
