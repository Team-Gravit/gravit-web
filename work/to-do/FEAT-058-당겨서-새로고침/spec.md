# FEAT-058 — 앱 셸 화면에서 당겨서 새로고침

GitHub Issue #304 · 브랜치 `feat/#304/pull-to-refresh`

> iPhone Safari 레이아웃 조사(2026-10-13)의 수정 6단계 중 **3단계**다. 1단계 `FIX-055`(#300),
> 2단계 `FIX-057`(#302). 원래 「튕김 회색 공백 제거」였으나 당겨서 새로고침 기능으로 확장했다.
> 그림과 용어는 `local-docs/문서/safari-스크롤/쉬운-설명.html` 그림 3.

## 배경 · 목표

학습·마이 화면 맨 위에서 아래로 당기면 제목 막대까지 함께 내려가고, 그 위로 회색 캔버스가 드러난다.
앱 셸의 스크롤 영역 전체가 iOS 고무줄 효과로 움직이기 때문이다.

제목 막대는 제자리에 두고 **그 아래 콘텐츠만** 내려오게 한다. 충분히 당겼다 놓으면 현재 화면의
데이터를 다시 불러온다. 네이티브 앱의 당겨서 새로고침과 같은 경험을 웹뷰 안에서 제공한다.

## 원인 (코드로 확정)

- 모바일 제목 막대 `PageTitleBar`는 `sticky top-0`이고, 앱 셸 스크롤 영역
  `div[data-scroll-restoration-id="app-shell"]` **안쪽**에 있다
- 그 스크롤 영역은 `overflow-y-auto overscroll-y-contain`이다. `contain`은 바깥으로 스크롤이
  넘어가는 것만 막고, 영역 자체의 고무줄 효과는 그대로 둔다
- 고무줄 효과는 sticky 요소를 포함한 영역 전체를 끌어내린다. 드러나는 배경은 앱 셸의
  `fixed -z-20 bg-bg-2` 캔버스다
- 네이티브 `bounces={false}`(`apps/native/app/index.tsx`)는 문서 스크롤에만 적용되고 안쪽 영역에는 닿지 않는다

## 적용 화면 (2026-10-13 결정)

**탭 루트 4개에만 넣는다.** 내려가는 영역은 「제목 막대가 있으면 그 아래, 없으면 화면 전체」다.

| 라우트      | 맨 위 요소                     | 내려가는 영역                     |
| ----------- | ------------------------------ | --------------------------------- |
| `/main`     | 히어로 이미지 (`HeroGreeting`) | 히어로를 포함한 화면 전체         |
| `/learning` | `PageTitleBar`                 | 제목 막대 아래                    |
| `/league`   | 리그 배경 (overlay)            | 화면 전체 (배경 처리는 확인 필요) |
| `/my/*`     | 프로필 카드 (`ProfileCard`)    | 프로필 카드를 포함한 화면 전체    |

판단 근거:

- 레슨 제출(`features/lesson-quiz/api/use-submit-lesson.ts`)이 챕터 · 유닛 · 레슨 · 홈 · 리그 · 프로필
  캐시를 이미 무효화한다. **내가 학습해서 바뀐 데이터는 당기지 않아도 새로 불러온다**
- 당겨서 새로고침이 필요한 경우는 ① 다른 사람 · 날짜 · 다른 기기로 데이터가 바뀔 때(리그 랭킹,
  일일 미션, 팔로워) ② 불러오기에 실패해 다시 시도할 때다
- 학습 탭은 ①이 거의 없지만 넣는다. **이유는 데이터 갱신이 아니라 탭 간 일관성이다.** 하단 탭 네 개 중
  하나만 당겨지지 않으면 고장으로 느끼기 쉽다
- 하위 화면(챕터 · 유닛 상세 · 친구)은 뒤로 가기가 있는 짧은 방문이라 넣지 않는다. 친구 목록은 써
  보고 필요하면 별도 작업으로 추가한다

`concept-note`는 내용이 고정된 전체 화면이다. 퀴즈 · 결과 화면은 앱 셸 밖(`_focus`)이다.

## 범위

| 위치                                             | 변경                                                             |
| ------------------------------------------------ | ---------------------------------------------------------------- |
| `app/routes/_authenticated/_app-shell/route.tsx` | 스크롤 영역 `overscroll-y-contain` → `overscroll-y-none`         |
| `shared/ui/` (새 컴포넌트, 이름 미정)            | 당긴 거리만큼 콘텐츠를 내리고 그래빗 로고를 그리는 표시 컴포넌트 |
| 탭 루트 4개 화면 (`pages/`)                      | 내려가는 영역을 새 컴포넌트로 감싼다                             |

새로고침 동작은 「지금 화면에 붙은 쿼리 다시 불러오기」로 공통 처리한다. 화면마다 따로 짜지 않는다.

## 새로고침 표시 (2026-10-14 결정)

회전 스피너(`shared/ui/spinner`) 대신 **그래빗 공식 로고**를 쓴다. 회전 스피너로는 당긴 비율을 보여 줄 수
없기 때문이다. 기존 `Spinner` 사용처는 바꾸지 않는다 — 이 표시는 당겨서 새로고침 전용이다.

| 단계             | 연출                                                                 |
| ---------------- | -------------------------------------------------------------------- |
| 당기는 중        | 당긴 비율만큼 로고 몸통이 한 획으로 그려진다 (`stroke-dashoffset`)   |
| 임계 도달        | 눈 두 개가 나타난다 — 「놓으면 새로고침」 신호                       |
| 새로고침 중      | 완성된 로고가 통통 튄다                                              |
| 끝               | 로고를 지우지 않고 그대로 둔 채 틈이 닫힌다                          |
| 실패             | 틈이 닫힌 뒤 토스트를 띄운다                                         |
| 동작 줄이기 설정 | 튀는 대신 흐려졌다 진해지기를 반복한다 (`Spinner`처럼 멈추지 않는다) |

- 에셋: 사용자가 제공한 공식 로고 SVG (`Group 1171282351.svg`). 원본은 흰색 선이라 `currentColor`로 바꾼다.
  선 끝이 둥글어 길이 0에서도 점이 찍히므로 시작 전에는 숨긴다
- 움직임: **Figma 시안 없음 (2026-10-14 확인)**. 위 연출은 데모로 비교한 뒤 사용자가 정했다.
  디자이너에게 공유하고, 시안이 생기면 별도 작업으로 맞춘다
- 아이콘 파이프라인(`shared/ui/icon`, SVGR)에 넣지 않는다. 경로 하나를 따로 움직여야 하므로 경로를 가진
  전용 컴포넌트로 둔다
- 데모: `local-docs/문서/safari-스크롤/당겨서-새로고침-데모.html`

`overscroll-y-none`은 앱 셸 화면 전체에 적용된다. 당겨서 새로고침이 없는 하위 화면도 고무줄 효과가
사라지며, 그 화면의 제목 막대 위 회색 공백도 함께 없어진다.

## Out of Scope

## 기술 결정 (ADR)

### 헤더 아래에서만 튕기게 하는 방법

**Context** — 제목 막대가 스크롤 영역 안쪽에 있어, iOS 고무줄 효과가 막대까지 끌어내린다.
막대는 고정하고 아래 콘텐츠만 움직여야 하며, 놓는 시점에 새로고침을 시작해야 한다.

**Decision** — B. 앱 셸 스크롤 영역의 기본 튕김을 끄고(`overscroll-behavior: none`), 스크롤이
맨 위일 때의 터치 이동을 직접 받아 제목 막대 아래 콘텐츠만 `transform`으로 내린다.

**Alternatives**

| 안  | 내용                                                   | 거부 이유                                                                                           |
| --- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| A   | 제목 막대를 스크롤 영역 밖에 고정하고 기본 튕김 사용   | `PageTitleBar`를 쓰는 화면 전부와 앱 셸 구조를 바꿔야 한다. 고무줄의 놓는 시점·거리를 다루기 어렵다 |
| C   | 기본 튕김을 그대로 두고 음수 `scrollTop`으로 거리 측정 | 막대가 함께 내려가는 문제가 남는다. 브라우저마다 음수 `scrollTop` 노출이 다르다                     |

**Consequences**

- 장점: 앱 셸과 공용 컴포넌트만 바꾼다. 회색 공백 제거(원래 3단계)도 함께 해결된다
- 단점: 맨 위가 아닌 곳에서도 iOS 고무줄 효과가 사라진다(맨 아래 포함). 터치 처리와 스크롤의
  경계 판단을 직접 유지해야 한다. `touchmove`의 기본 동작을 막으려면 passive가 아닌 리스너가 필요하다

### 라이브러리를 쓸지, 직접 구현할지

**Context** — 안 B는 「앱 셸이 가진 안쪽 스크롤 영역」에서 「제목 막대 아래 요소만」 내려야 한다.
라이브러리가 스크롤 영역을 스스로 소유하거나 문서 스크롤만 본다면 이 조건을 만족하지 못한다.
조사 기준일 2026-10-14, npm 레지스트리와 배포 소스를 직접 확인했다.

**Decision** — 직접 구현한다. 원리가 맞는 두 라이브러리(`react-simple-pull-to-refresh`,
`antd-mobile` `PullToRefresh`)의 소스에서 시작 판단 · 고무줄 저항 · 상태 단계만 가져온다.
가져올 것과 버릴 것의 근거는 `local-docs/문서/safari-스크롤/당겨서-새로고침-같이-찾아볼-것.md`.

**Alternatives**

| 안                                      | 내용                                                                                  | 거부 이유                                                                                                                     |
| --------------------------------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `react-simple-pull-to-refresh` 1.3.4    | 의존성 없음. 터치 대상의 조상 스크롤을 확인하고 `touchmove`를 `passive: false`로 등록 | 래퍼에 `height:100%; overflow:hidden`을 걸고 CSS를 런타임에 주입한다. 임계를 넘은 뒤 되돌려 놓아도 새로고침되고 실패를 삼킨다 |
| `antd-mobile` `PullToRefresh` 5.43      | 상태 4단계 · 고무줄 저항 · 세로 축 고정. 실패 시 다시 던짐                            | `@use-gesture` · `@react-spring` 두 의존성이 들어온다. 헤드 `height`를 애니메이션해 매 프레임 레이아웃을 다시 계산한다        |
| `react-infinite-scroll-component` 7.2.1 | 무한 스크롤 컴포넌트의 `pullDownToRefresh` 옵션                                       | 컴포넌트가 스크롤 영역을 소유한다. 앱 셸 스크롤 영역(스크롤 복원 포함)과 겹치고, 무한 스크롤은 쓰지 않는다                    |
| `react-pull-to-refresh` 2.0.1           | hammerjs 기반                                                                         | 맨 위 판단에 문서 스크롤(`bodyEl.scrollTop`)만 본다. 안쪽 스크롤 영역에서는 동작하지 않는다. 2022-11 이후 배포 없음           |
| 네이티브 `pullToRefreshEnabled`         | react-native-webview의 `RefreshControl`                                               | 웹뷰 전체 위(헤더 위)에서 벌어지고 페이지를 통째로 다시 불러온다. Safari 웹에는 적용되지 않는다                               |

**Consequences**

- 장점: 의존성이 늘지 않는다. 내려가는 요소 · 스피너 · 새로고침 범위를 우리 구조에 맞게 정한다
- 단점: 터치 경계 상황(`touchcancel`, 가로 스와이프, 중첩 스크롤)을 직접 테스트하고 유지해야 한다.
  라이브러리가 이미 겪은 기기별 문제를 우리가 다시 겪을 수 있다 (예: antd의 「당길 때 떨림 방지」 빈 리스너)

## 확정 명세 · 검증 기준

> 모바일 폭(`md` 미만) 기준이다. 수동 AC는 iPhone Safari와 네이티브 앱 WebView에서 확인한다.

- [ ] **AC-1** (수동 · 학습 탭)
      Given `/learning` 스크롤이 맨 위다
      When 아래로 당긴다
      Then 제목 막대는 화면 맨 위에 그대로 있고, 막대 아래 챕터 목록만 내려가며 그 사이에 로고가 당긴 비율만큼 그려진다
- [ ] **AC-2** (수동 · 홈 · 마이)
      Given `/main` 또는 `/my` 스크롤이 맨 위다
      When 아래로 당긴다
      Then 히어로 이미지(홈) · 프로필 카드(마이)를 포함한 화면 전체가 내려가고, 그 위에 로고가 그려진다
- [ ] **AC-3** (수동 · 임계 거리 미만)
      Given 탭 루트 화면 스크롤이 맨 위다
      When 임계 거리보다 적게 당겼다 놓는다
      Then 콘텐츠가 원위치로 돌아가고 네트워크 요청이 발생하지 않는다
- [ ] **AC-4** (통합 · 새로고침)
      Given 탭 루트 화면에 표시 중인 쿼리가 있다
      When 임계 거리 이상 당겼다 놓는다
      Then 그 화면의 활성 쿼리가 다시 요청되고, 응답이 끝날 때까지 완성된 로고가 보인 뒤 콘텐츠가 원위치로 돌아간다
- [ ] **AC-4b** (통합 · 실패)
      Given 다시 요청한 쿼리 중 하나가 실패한다
      When 새로고침이 끝난다
      Then 콘텐츠가 원위치로 돌아가고 실패 토스트가 1개 나타난다
- [ ] **AC-4c** (통합 · 중복 방지)
      Given 새로고침이 진행 중이다
      When 다시 당긴다
      Then 콘텐츠가 내려가지 않고 추가 요청이 발생하지 않는다
- [ ] **AC-4d** (통합 · 접근성)
      Given 새로고침이 진행 중이다
      Then `role="status"` 요소에 「새로고침 중」 문구가 있다
