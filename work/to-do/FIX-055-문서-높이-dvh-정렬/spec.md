# FIX-055 — 모바일 Safari 바깥 문서 스크롤 제거 (문서 최소 높이 100vh → 100dvh)

GitHub Issue #300 · 브랜치 `fix/#300/document-dvh`

> iPhone Safari 레이아웃 조사(2026-10-13)에서 나온 수정 6단계 중 **1단계**다.
> 전체 그림과 용어는 `local-docs/문서/safari-스크롤/쉬운-설명.html`.
> 단계마다 가설 하나만 넣고 실기기로 확인한 뒤 다음 단계로 간다.

## 배경 · 목표

앱 셸은 **바깥 문서는 고정하고 안쪽 상자만 스크롤**하도록 설계했다. 그런데 iPhone Safari에서
바깥 문서까지 스크롤되어 홈 히어로가 상태바와 겹치고, 학습 화면의 제목 바가 상태바 밑으로 들어간다.
문서 최소 높이를 앱 셸과 같은 `100dvh`로 맞춰 바깥 문서의 스크롤 여분을 없앤다.

## 관찰 (배포 버전, iPhone Safari)

| 캡처        | 화면 | 보인 것                                                               |
| ----------- | ---- | --------------------------------------------------------------------- |
| `_04` 10:12 | 학습 | sticky 제목 바 「학습」이 상태바 밑으로 올라가 잘림. 하단 탭은 제자리 |
| `_05` 10:11 | 홈   | 히어로의 레벨 · 티어 · 알림 줄이 시계 · 배터리와 겹침                 |
| `_01` 2:01  | 학습 | 페이지가 맨 위일 때는 웹 화면이 상태바 아래에서 시작함 (비교 기준)    |

캡처 원본: `KakaoTalk_20261013_140326086_01~05.png` (사용자 보관)

## 원인

**코드로 확인한 사실**

- 앱 셸 `app/routes/_authenticated/_app-shell/route.tsx` — 루트 `h-dvh overflow-hidden`, 스크롤은
  안쪽 `div[data-scroll-restoration-id="app-shell"]`(`h-full overflow-y-auto overscroll-y-contain`)이 맡는다.
  설정 셸(`settings/route.tsx`)도 같은 구조다
- 변경 전 `app/styles/base.css` — `body`와 `#app`이 `min-height: 100vh`
- 바깥 문서 높이에 영향을 주는 다른 요소는 찾지 못했다. 헤더는 `md:`에서만 보이고, 배경 레이어와
  하단 탭은 `fixed`다
- sticky 제목 바(`PageTitleBar`)는 안쪽 상자 기준으로 붙는다. 안쪽만 스크롤됐다면 `_04`처럼 잘릴 수 없다
  → `_04`는 바깥 문서가 스크롤된 상태다

**가설 (실기기 확인 필요)**

- iOS Safari에서 `vh`는 주소창이 접힌 큰 화면(`lvh`) 기준이다. 주소창이 펼쳐져 있으면
  `body`(100vh)가 셸(100dvh)보다 길어지고, 그 차이만큼 바깥 문서가 스크롤된다
- 하단 탭처럼 안쪽 상자 밖에서 시작한 드래그나, 안쪽 상자가 끝에 닿은 뒤의 드래그가 바깥 문서를 움직인다
- 상태바 영역에 내용이 비치는 것은 문서가 스크롤될 때 Safari가 보이는 기본 표시다. 버그는
  **바깥 문서가 스크롤된다는 점**이다

## 범위

| 파일                               | 변경                                                   |
| ---------------------------------- | ------------------------------------------------------ |
| `apps/web/src/app/styles/base.css` | `body` · `#app`의 `min-height: 100vh` → `100dvh` (2줄) |

## Out of Scope

같은 조사에서 나온 나머지 단계다. 각각 별도 작업으로 다룬다.

- 학습 완료 화면 달 넘침 — `overflow-x-hidden` → `overflow-clip` (2단계)
- 학습 · 마이그래빗 위쪽 회색 공백 — 안쪽 상자 튕김, `overscroll-y-none` 여부는 UX 결정 (3단계)
- 문제풀이 키보드를 닫은 뒤 하단 흰 띠 — 이번 작업에서는 **관찰만** 한다 (4단계)
- 알림 `h-svh`, 리그 상태 화면 `min-h-screen` 단위 정리 (5단계)
- 문서 배경 정책 (`fixed -z-20` 레이어 제거, 라우트별 문서 배경) (6단계)
- `viewport-fit=cover` · `safe-area-inset` 도입, native 셸 안전 영역 처리
- 화면 이동 시 스크롤 초기화 · 복원 — `FIX-052`

## 용어 정의

| 용어                  | 정의                                                                                                 |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| 바깥 문서 스크롤      | 페이지 전체(`html`)가 움직이는 스크롤. `window.scrollY`                                              |
| 안쪽 스크롤           | 앱 셸의 `app-shell` 상자 안에서만 움직이는 스크롤. `element.scrollTop`                               |
| `lvh` / `svh` / `dvh` | 주소창이 접힌 큰 화면 / 펼친 작은 화면 / 현재 상태를 따라가는 높이. iOS Safari의 `vh`는 `lvh`와 같다 |

## 결정에 따른 영향

- 앱 셸과 설정 화면에서는 바깥 문서가 스크롤되지 않으므로 **Safari 주소창이 스크롤로 접히지 않는다.**
  지금까지는 접히면서 콘텐츠 영역이 넓어지는 경우가 있었다. 의도한 셸 구조에 맞는 결과지만
  체감이 달라질 수 있다
- 페이지 자체가 스크롤되는 화면(로그인 · 온보딩 `min-h-svh`, 학습 완료 `min-h-dvh`)은 문서 최소 높이만
  바뀐다. 내용이 화면보다 길면 지금처럼 문서가 스크롤된다

## 확인 필요

- 배포 버전과 로컬 코드가 같은가 — 캡처는 배포본이다
- 실기기 iOS · Safari 버전
- 측정 수단 — Windows에서는 Safari Web Inspector를 쓸 수 없다. 임시 디버그 오버레이
  (`scrollY` · `innerHeight` · `visualViewport` 표시)를 쓸지, Mac을 쓸지 정한다
- 실기기 확인 경로 — 같은 Wi-Fi에서 `pnpm --filter @repo/web dev -- --host`로 접속할 때 소셜 로그인
  리다이렉트가 동작하는가. 막히면 develop 머지 후 배포본으로 확인한다
