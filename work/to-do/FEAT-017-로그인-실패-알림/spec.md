# FEAT-017 — 로그인 실패를 사용자에게 알린다

## 배경 · 목표

`MIG-005` Issue 3(#201)에서 OAuth 콜백을 옮기면서 **에러를 알리는 경로만 빠졌다.**

legacy는 콜백 실패 시 `toast.error(message)`로 사유를 띄운다(기준선 D7). `apps/web`에는 toast가
없어(의존성·`shared/ui` 모두) 그 분기를 옮기지 못했고, 현재는 탈퇴 계정(`USER_423`)이 아닌
실패가 **아무 표시 없이 무시된다.**

사용자 입장에서는 provider 로그인까지 마치고 돌아왔는데 빈 화면에서 멈춘다. 왜 실패했는지 알 수
없고 다시 시도할 단서도 없다.

지금은 로그인 화면과 `/main`·`/onboarding` 본체가 없어 이 경로에 도달할 수 없다. **로그인 화면을
만드는 작업 전까지 해결한다.**

## 범위

- 로그인 실패 사유를 사용자에게 전달하는 수단 도입
- `pages/oauth-callback`의 에러 분기 연결 (현재 `return`으로 끝난다)

## Out of Scope

- `MIG-005`의 나머지 이슈
- 로그인 화면 UI 본체

## 먼저 결정할 것

구현 방식이 정해지지 않았다. 착수 시점에 판단한다.

- **전역 toast를 도입할지, 로그인 화면 안에 에러 문구를 표시할지.** 실패를 보여줄 화면이 이미
  있다면 toast가 없어도 된다
- toast로 간다면 **라이브러리를 쓸지 직접 만들지.** Portal·레이어 순서·스크린리더 알림·자동
  닫힘이 얽혀 있어 `component-convention.md`가 직접 구현을 기본값으로 삼지 말라고 하는 부류다
- **어떤 문구를 보여줄지.** 서버 `message`를 그대로 노출할지, 고정 문구로 감쌀지.
  `api-convention.md` §6은 "에러 문구를 임의로 지어내지 않는다"고 한다
