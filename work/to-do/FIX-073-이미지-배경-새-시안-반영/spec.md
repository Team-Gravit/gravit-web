## 기술 결정 (ADR)

### ADR-1 「그라데이션 + 장식 캔버스」 위치 (2026-10-29 결정: B · REF-054에서 이관)

메인 히어로 · 학습 카드 · 공용 우주 배경 세 곳이 그라데이션과 투명 장식을 한 상자에 넣고 화면에 맞춰 덮거나 붙이는 같은 구조를 쓴다.

| 안           | 내용                                                                                                | 장점                                                               | 단점                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| A            | 화면마다 직접 작성                                                                                  | 각 화면에서 자유롭게 조정                                          | 비율 고정 CSS가 3번 반복 · 한 곳만 고쳐질 위험                                        |
| **B (선택)** | `shared/ui`에 공용 컴포넌트 신설 — 그라데이션 · 이미지(`srcset`) · 캔버스 비율 · 기준 위치를 받는다 | 개념 · 변경 이유가 같은 코드를 한 곳에 둔다 · 한 곳씩 옮길 수 있다 | props가 4 ~ 5개로 늘고, 세 곳의 차이를 props로 표현해야 한다                          |
| C            | 기존 `SpaceBackground`에 variant로 흡수                                                             | 새 파일이 없다                                                     | 전체 화면 배경 컴포넌트에 카드 · 히어로가 섞여 의미가 흐려지고 기존 사용처 9곳에 영향 |

- 적용 범위: 그라데이션 + 장식 구조 세 곳만. 형식 · 크기만 바꾸는 이미지(리그 · 마스코트 · 행성 등)는 쓰지 않는다
- Consequences: 공용 컴포넌트의 props 계약을 먼저 고정하고 세 곳을 옮긴다. 세 곳의 기준 위치(오른쪽 아래 · cover · 폭 맞춤)가 달라 props가 늘 수 있다

### 색 토큰 (REF-054 확인 필요 4 결정)

같은 두 색이 세 시안에서 쓰이고 각도만 다르다. Figma 변수 목록에는 없어(2026-10-29 확인) 임시 이름(예: `--color-space-start` · `--color-space-end`)으로 `tokens.css`에 두고 `docs/design-system/README.md`에 「Figma 변수 없음 · 디자이너 확인 필요」로 남긴다. 각도 · 정지점은 화면마다 다르므로 색만 공유한다.

## 시안 · 에셋

### 5-1. 학습 카드 배경 (2026-10-29 새 시안)

- Figma `card-background` (`15918:38812`, 589×377). 최종 카드 배경은 그 안의 `crop` 영역(x 64 · y 0 · 355×377)이며 **그라데이션도 이 영역만큼 잘린다**
- 그라데이션: 선형 `#4721CA` → `#17034E`, Figma 계산 각도 303.01deg (589×377 기준). crop 안에는 원래 그라데이션의 18.4% ~ 97.0% 구간만 보인다
- **CSS 값(crop 355×377 기준):** `linear-gradient(303.01deg, #4721CA -23.34%, #17034E 103.83%)` — 원래 두 색(토큰)을 그대로 쓰고 정지점만 바깥으로 민다
  - 계산: Figma `gradientTransform`에서 픽셀당 변화량을 구하고, crop 상자에서 CSS 그라데이션 선의 양 끝이 원래 그라데이션의 어느 지점인지 구했다
  - 검증: Figma에서 내보낸 그라데이션을 crop으로 잘라 CSS 렌더와 355×377 전체 픽셀 비교 — 최대 2/255 · 평균 0.66. 원래 색을 0 ~ 100%로 그냥 쓰면 최대 24/255로 어긋난다 (도구 `local-docs/.../2026-10-29_ref054-image-inventory/card-gradient/`)
- 장식은 그라데이션을 숨기고 crop 영역을 투명 이미지로 내보낸다 — **내보냄(2026-10-29):** Figma 복제본에서 그라데이션만 숨기고 crop으로 잘라 2배(710×754) 투명 PNG 207 KB로 받은 뒤 복제본은 지웠다. webp q80 54 KB(현재 카드 배경 19 KB보다 크다 — 시안에 구름 · 유성이 늘었다). 원본 `local-docs/.../card-gradient/card-decoration@2x.png`
  - 검증: CSS 그라데이션 위에 장식을 합성해 Figma 원본 crop과 710×754 전체 비교 — 최대 4/255 · 평균 0.75 · 8/255 넘는 픽셀 0%
- **카드 비율:** 위 값은 355:377 상자에서 정확하다. 챕터 카드(정사각형)는 거의 같지만 유닛 카드(가로로 긴 `h-39`)는 비율이 다르다. 구현 때 그라데이션과 장식을 **같은 355:377 상자에 함께 넣고 카드에 맞춰 덮게(cover)** 해서, 카드 비율과 상관없이 둘이 함께 잘리게 한다

### 5-2. 메인 히어로 새 시안 (2026-10-29)

| 프레임            | 360×266 · 잘림 없음                                         | 1920×274 · 잘림                                              |

- 두 화면 모두 같은 그라데이션 설정을 비율이 다른 사각형에 써서 각도가 다르다(303° · 335°). 시안 그대로 옮긴다
- 검증: Figma 그라데이션 렌더와 CSS를 캔버스 전체 픽셀로 비교 — 둘 다 최대 2/255 · 평균 0.66
- 내보내기: Figma 복제본을 잘림 프레임에 넣어 그라데이션만 숨기고 2배로 받은 뒤 복제본과 임시 프레임을 지웠다. 원본 `local-docs/.../hero-gradient/`
- **모바일 폭 대응:** 캔버스를 오른쪽 아래 기준으로 실제 크기(475×304)에 붙인다. 360px은 시안 프레임과 같고, 361 ~ 475px은 여백에 이미 그려진 장식이 드러난다. 475px을 넘으면 폭에 맞춰 키운다(cover). 위쪽 38px 여백은 상태 표시줄 영역을 채운다
- **데스크톱 폭 대응:** 오른쪽 기준(지구 쪽)으로 붙여 1920보다 좁으면 왼쪽이 잘리고, 넓으면 cover로 키운다
- **그라데이션은 장식과 같은 캔버스 상자에 둔다.** 캔버스가 줄거나 커질 때 둘이 같이 움직여 경계가 맞는다. 캔버스가 덮지 못하는 곳(긴 상태 표시줄 등)은 바깥 상자의 같은 그라데이션이 채운다 — 이 부분만 폭에 따라 색이 아주 약간 달라질 수 있다

### 리그 배경 (2026-10-29 추가)

- **현상:** 768px 미만에서 폭을 바꾸면 화면 전체 그라데이션과 장식 이미지가 서로 다른 비율로 늘어난다. 장식 이미지(`league-bg-mobile.png`, 360×692)는 82.5%가 투명이라 그 틈으로 그라데이션이 보이는데, 그라데이션은 화면 전체에 맞춰 늘고 이미지는 `object-cover`로 화면 비율에 따라 폭 또는 높이 기준으로 커진다
- 이번 변경 전부터 있던 배치다(REF-054 #350은 형식만 webp로 바꿨다). 768px 이상 데스크톱 배경은 불투명이라 해당 없다
- **방향:** 그라데이션과 장식을 한 캔버스에 넣어 함께 늘린다(ADR-1 공용 컴포넌트). 장식은 Figma에서 2배로 다시 받는다 — REF-054 Out of Scope였던 「리그 모바일 2배 원본」을 여기서 함께 처리한다
- **시안 (2026-10-29 받음)** — 두 노드 모두 그라데이션 `#4721CA` → `#17034E`, 같은 gradientTransform 설정(`[[-0.772, -0.32, 1.054], [0.321, -0.315, 0.486]]`)을 비율이 다른 상자에 쓴다. CSS 값은 학습 카드와 같은 방법으로 계산 · 검증한다
  - **데스크톱:** `league-background` (`15382:17808`, 1920×2582, 잘림). 그라데이션은 별도 레이어 `gradient`(`15382:17809`, 1920×2561, 지금 숨김)이고 나머지는 투명 장식(행성 · 마스코트 · 길 · 별). 사용자 설명: 리그 너비에 맞으며 **여러 학습 화면에서도 쓰인다** — 사용처는 구현 전에 확인한다
  - **모바일:** `lesson-result-bg-mobile` (`14600:22711`, 387×740, 잘림). 그라데이션은 프레임 자체 채우기다. 상태바 · 내비게이션 바 · 하단 프레임은 숨김. **레슨 결과 모바일 배경과 같은 시안**이다 — 지금 레슨 결과 `background-decoration-mobile.webp`(1161×2220 = 3배, 불투명 · 그라데이션 포함)가 이 프레임을 그대로 쓴 것으로 보인다
  - 리그 · 레슨 결과가 같은 배경을 쓰므로 에셋과 캔버스를 공유할 수 있다. 위치(공용 `shared/ui` 또는 각 화면)는 ADR-1 공용 컴포넌트를 만들 때 정한다
  - 장식 2배 내보내기 전
- 그라데이션 각도 · 정지점 · 캔버스 크기 · 기준 위치는 시안을 받은 뒤 학습 카드 · 히어로와 같은 방법(Figma 렌더와 CSS 픽셀 비교)으로 정한다
