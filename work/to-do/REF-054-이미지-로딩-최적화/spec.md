# REF-054 — 이미지 로딩 최적화와 메인 히어로 배경 교체

GitHub Issue: #349 (관련 REF-072 #345)

## 배경 · 목표

배경·장식 이미지의 형식(PNG)·해상도(표시 크기의 1배 또는 4배 이상)·로딩 방식(CSS 배경, 우선순위 없음)이
제각각이라 첫 화면이 늦게 그려지는 화면이 있다. 이미지마다 **역할을 분류해 로딩 정책을 하나로 정하고**,
전후 LCP·전송량을 같은 조건에서 측정해 효과를 수치로 남긴다.
FIX-053 의 이관 항목 1(메인 히어로 배경 분리)을 새 정책의 첫 적용 대상으로 함께 처리한다.

## 범위

- `apps/web/src`의 이미지 파일 85개(webp · png · svg, 아이콘 제외)와 그 렌더링 코드
- 이미지 변환을 빌드 단계로 옮긴다 (`vite-imagetools` 9.0.3 도입)
- 새 시안 반영: 메인 히어로 · 학습 카드 · 공용 우주 배경을 CSS 그라데이션 + 투명 장식으로 바꾼다 (**외형 변경 — 성능 이슈와 분리**)
- 측정 절차와 전후 기록

## Out of Scope

- SVG 아이콘(`shared/ui/icon`) — 이미 인라인 SVG
- 로고 SVG 컴포넌트(`shared/ui/logo`) — 첫 청크 정리는 REF-071
- 마크다운 본문의 외부 이미지 — 원본을 제어할 수 없다
- JS 번들 분할 · API 요청 순서 등 이미지 외 LCP 요인 — 측정에서 원인으로 나오면 새 작업으로 뽑는다
- preload — 형식 · 크기 · `<img>` 전환 뒤 측정해서 다시 판단한다 (확인 필요 3)
- 리그 모바일 배경의 2배 원본 교체 — 원본을 받기 전까지는 형식만 바꾼다
- 화면 문구 · 레이아웃 · 동작 변경, 새 시안에 없는 디자인 개선
- native(Expo) 쪽 이미지

### 성공 기준

- 각 이슈의 대상 이미지가 표시 크기 기준 해상도 · 형식으로 바뀌고 전송량이 줄어든다 (빌드 결과물로 확인)
- 대상 화면 LCP가 나빠지지 않는다 (로그인 측정 도구와 같은 조건 · 흔들림 기준)
- 보존 계약 C1 ~ C8 유지 · `pnpm verify` 통과

## 기술 결정 (ADR)

### ADR-1 「그라데이션 + 장식 캔버스」 위치 (2026-10-29 결정: B)

메인 히어로 · 학습 카드 · 공용 우주 배경 세 곳이 그라데이션과 투명 장식을 한 상자에 넣고 화면에 맞춰 덮거나 붙이는 같은 구조를 쓴다.

| 안           | 내용                                                                                                | 장점                                                               | 단점                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| A            | 화면마다 직접 작성                                                                                  | 각 화면에서 자유롭게 조정                                          | 비율 고정 CSS가 3번 반복 · 한 곳만 고쳐질 위험                                        |
| **B (선택)** | `shared/ui`에 공용 컴포넌트 신설 — 그라데이션 · 이미지(`srcset`) · 캔버스 비율 · 기준 위치를 받는다 | 개념 · 변경 이유가 같은 코드를 한 곳에 둔다 · 한 곳씩 옮길 수 있다 | props가 4 ~ 5개로 늘고, 세 곳의 차이를 props로 표현해야 한다                          |
| C            | 기존 `SpaceBackground`에 variant로 흡수                                                             | 새 파일이 없다                                                     | 전체 화면 배경 컴포넌트에 카드 · 히어로가 섞여 의미가 흐려지고 기존 사용처 9곳에 영향 |

- 적용 범위: 그라데이션 + 장식 구조 세 곳만. 형식 · 크기만 바꾸는 이미지(리그 · 마스코트 · 행성 등)는 쓰지 않는다
- Consequences: 공용 컴포넌트의 props 계약을 먼저 고정하고 세 곳을 옮긴다. 세 곳의 기준 위치(오른쪽 아래 · cover · 폭 맞춤)가 달라 props가 늘 수 있다

### 공통 관찰 (10-08 대비 바뀐 것 포함)

- `index.html`에 preload가 없고, 이미지는 모두 라우트 청크 안에서 import된다 → JS를 받고 렌더링한 뒤에야 요청이 시작된다
- CSS 배경은 4곳(공용 우주 배경 2종 · 카드 배경 · 프로필 배너). 우선순위 힌트를 줄 수 없고 스타일 계산 뒤에 요청된다
- `loading="lazy"`를 쓰는 곳이 여전히 없다. `fetchPriority="high"`는 2곳(퀴즈 로딩 마스코트 · 레슨 결과 배경)
- **화면 전체를 덮는 배경은 Chrome이 LCP 후보에서 뺀다** (REF-072 로그인 데스크톱 측정에서 확인). 공용 우주 배경을 「LCP 후보」로 둔 전략 1의 분류는 고쳐야 한다
- LCP 수치는 로그인 화면만 측정했다(REF-072). 나머지 화면은 아래 6번 절차로 기준값을 잰다

## 전략 (안) — 사용자 확정 전

### 1. 역할별 로딩 정책

| 역할               | 예                                                        | 정책                                                                    |
| ------------------ | --------------------------------------------------------- | ----------------------------------------------------------------------- |
| **LCP 후보**       | 메인 히어로 · 리그 배경 · 레슨 결과 배경 · 공용 우주 배경 | `<img>` 로 그린다 · `fetchPriority="high"` · `loading` 기본값(eager)    |
| 첫 화면 장식(작음) | 마스코트 · 프로필 배너 · 카드 배경                        | `<img>` 또는 CSS 배경 유지 · 우선순위 기본값                            |
| 화면 밖 · 목록     | 행성(챕터·유닛 카드) · 푸터 로고                          | `loading="lazy"` · `decoding="async"`                                   |
| 조건부(상태 화면)  | 퀴즈 로딩 마스코트                                        | 상태 진입 전에 미리 받는다(현행 `fetchPriority` 유지) · 해상도만 줄인다 |

> `fetchPriority="high"` 는 화면당 1개만 둔다. 여러 개면 서로 경쟁해 효과가 사라진다.
> 첫 화면 안에 들어오는 이미지에는 `loading="lazy"` 를 쓰지 않는다. 레이아웃이 끝날 때까지 요청이 미뤄져 LCP 가 늦어진다.

### 2. 형식과 해상도

- PNG 사진·일러스트 → **webp**. 아이콘성 이미지(구글 로고)는 SVG 가 있으면 SVG
- 원본은 **최대 표시 크기의 2배**로 맞춘다 — 4320px · 3840px 원본은 줄이고, 360px 1배 원본은 720px 로 키운다(새 원본 필요)
- 좁은·넓은 화면 이미지가 다르면 `<picture><source media>` 로 **한쪽만** 받는다 (리그 · 히어로는 이미 이 형태)

### 3. 첫 요청 앞당기기

- LCP 후보를 CSS 배경 → `<img>` 로 바꾼다 (공용 우주 배경)
- 그래도 늦으면 preload 를 건다. 해시 파일명이라 `index.html` 에 정적으로 못 쓴다 → 방법은 확인 필요

### 4. 로딩 중 표시

- **이미지 아래에 대표색·그라데이션을 깐다.** 이미지가 늦어도 글자는 즉시 읽히고, 도착하면 그 위에 덮인다
- 컨테이너 크기를 미리 고정해 레이아웃 이동(CLS)을 막는다 (`aspect-ratio` 또는 고정 높이)
- **LCP 후보에는 페이드인을 쓰지 않는다.** `opacity: 0` 동안은 그려진 것으로 치지 않아 LCP 가 오히려 늦어진다
- 스켈레톤은 데이터 영역 전용으로 두고 장식 이미지에는 쓰지 않는다
