# FIX-059 — 리그 화면이 다시 불러올 때마다 로딩 화면으로 바뀜

GitHub Issue #306 · 브랜치 `fix/#306/league-refetch-loading`

> `FEAT-058`(당겨서 새로고침, #304)을 리그 탭에 연결하다 발견했다. 리그 연결은 이 작업이 머지된 뒤
> `FEAT-058`에서 한다.

## 배경 · 목표

리그 화면은 데이터를 다시 불러오는 동안 아레나 전체가 「로딩중」으로 바뀌었다가 돌아온다. 앱으로
돌아올 때처럼 쿼리를 다시 불러오는 상황마다 생기며, 당겨서 새로고침을 연결하면 당길 때마다 생긴다.
첫 진입에만 로딩 화면을 보여 주고, 다시 불러오는 동안에는 이미 받은 화면을 유지한다.

## 원인 (코드로 확정)

- `pages/league/ui/league-page.tsx`가 프로필 쿼리의 `isFetching`으로 로딩 화면을 고른다.
  `isFetching`은 데이터가 이미 있어도 요청이 진행 중이면 `true`다
- 홈 쿼리는 `isLoading`, 프로필 쿼리는 `isFetching`으로 두 쿼리의 기준이 다르다
- `widgets/league-arena/ui/league-arena.tsx`가 선택 티어를 `useState(myLeagueId)`로 처음 한 번만 받는다.
  다시 불러와 내 리그가 바뀌어도 선택은 예전 리그에 남아 「내 티어」 랭킹이 아닌 쪽을 조회한다

## 범위

| 파일                                       | 변경                                                                                                                                                                  |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pages/league/ui/league-page.tsx`          | 두 쿼리 모두 `isPending`으로 로딩 판단. 도달할 수 없는 「데이터 없음」 분기 제거. 시즌 팝업 조건을 `seasonPopup` 하나로 합침. `modalChecked` → `hasClosedSeasonModal` |
| `widgets/league-arena/ui/league-arena.tsx` | 사용자가 고른 티어(`pickedTierId`)만 저장하고 선택값은 `pickedTierId ?? myLeagueId`로 계산. 랭킹 쿼리 변수에 `Query` 접미사                                           |

## Out of Scope

- 리그 탭 당겨서 새로고침 연결 · 배경을 화면 바깥으로 빼기 — `FEAT-058`
- 로딩 · 에러 화면의 문구와 모양 — 시안 확인 전까지 그대로 둔다
- `myLeagueId`(prop)와 `selectedTierId`(state)의 이름 체계 통일 — `TierSelector`와 API 경계까지 바뀐다
- 티어 버튼의 접근 가능한 이름 — 선택되지 않은 티어는 이름이 `aria-hidden`이라 비어 있다

## 확인 필요

- 로딩 · 에러 화면(「로딩중」 · 「에러 발생」)의 시안 — 흰 글자가 회색 캔버스 위에 떠 잘 보이지 않는다
