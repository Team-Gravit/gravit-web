# INFRA-031 — 학습 화면 명세 승격

## 배경 · 목표

`MIG-027`(학습 홈)이 끝났지만 확정 명세가 `docs/fe-implement-spec/`으로 올라가지 않았다.
`MIG-025`는 `main-01/main-01.md`를 남겼으므로 학습 영역만 기준 문서가 비어 있는 상태다.

`work-management.md` §6은 확정 명세의 `docs/` 승격을 완료 단계로 규정한다. 승격이 없으면 다음
작업자가 화면의 확정 동작을 `work/done/`의 흐름 문서에서 역추적해야 한다.

학습 상세 두 화면(`MIG-029` 챕터 상세 · `MIG-030` 유닛 상세)이 곧 이어지므로, 세 화면이 공유하는
셸·문구·상태 규칙을 한 번에 정리하는 편이 중복이 적다. **`MIG-029`·`MIG-030` 완료 후 착수한다.**

## 범위

| 대상                                | 내용                                                       |
| ----------------------------------- | ---------------------------------------------------------- |
| `docs/fe-implement-spec/l-1/l-1.md` | 학습 홈. `work/done/MIG-027-학습-홈-이전/spec.md`에서 승격 |
| `docs/fe-implement-spec/l-2/l-2.md` | 챕터 상세(유닛 목록). `MIG-029` 산출물에서 승격            |
| `docs/fe-implement-spec/l-3/l-3.md` | 유닛 상세(레슨 목록). `MIG-030` 산출물에서 승격            |
| `docs/fe-implement-spec/README.md`  | 명세 인덱스에 세 화면 추가                                 |
| `docs/implementation-status.md`     | `L.1`~`L.3` 비고의 「화면 명세 미승격」 표기 제거          |

형식은 `docs/fe-implement-spec/main-01/main-01.md`를 따른다 — 화면 개요 · 기능 명세 표(기능 ID ·
우선순위 · 상태 · 완료/제외) · 동작 계약.

## Out of Scope

- **화면 구현 변경** — 문서만 다룬다. 구현과 문서가 어긋나면 고치지 않고 차이를 기록한 뒤 별도
  `FIX-`로 분리한다
- **`L.4` 이후 학습 화면** — 개념노트 · 레슨 풀이 · 오답노트 · 북마크는 해당 `MIG-`가 끝난 뒤
- **`MIG-024`·`MIG-025`의 밀린 동작 검증 기록** — `migration-status.md`에서 `/main`·`/onboarding`이
  검증 기록 없이 남아 있다. 별개 문제이므로 이 작업에서 다루지 않는다

## 선행 조건

- [ ] `MIG-029` 완료 (챕터 상세)
- [ ] `MIG-030` 완료 (유닛 상세)

## 확인 필요

1. `L.1`의 Figma 프레임 이름이 「학습 홈 · 유닛 목록」인데 우리 구현은 **챕터** 카드 그리드다.
   시안의 「유닛」이 우리의 「챕터」를 가리키는지 확인하고, 용어가 어긋나면 명세에 대응표를 남긴다.
   `fe-implement-spec/README.md`도 `L.1`을 「유닛 카드 목록」으로 적고 있다
2. `L.2`·`L.3`의 화면 ID가 실제 Figma 프레임과 맞는지 — 현재 `implementation-status.md`의
   `L.2`~`L.4` 행은 화면 이름이 비어 있다
