# INFRA-008 — Vite 5 → 8 업그레이드 (Vitest 3 → 4 동반)

## 배경 · 목표

`apps/web`이 **Vite 5.4.17**을 쓴다. Vite 5는 **2023-11-16** 메이저로 2년 3개월 됐고,
그 사이 6·7·8이 나왔다.

이 때문에 **Vitest를 3에 묶어 두고 있다** — Vitest 4는 Vite 6+ 를 요구한다(`INFRA-#183`).
즉 Vite 5가 다른 도구의 발목을 잡는 상태다.

## 조사 결과 (2026-09-01 실측)

### 메이저 출시 시점

| 메이저 | 출시일            |
| ------ | ----------------- |
| 5.0.0  | 2023-11-16        |
| 6.0.0  | 2024-11-26        |
| 7.0.0  | 2025-06-24        |
| 8.0.0  | 2026-03-12        |
| 8.2.2  | 2026-08-20 (최신) |

### ⭐ 막는 것이 없다 — 플러그인 전부 Vite 8 지원

| 패키지                    | 현재      | vite peer 범위         |           8 지원           |
| ------------------------- | --------- | ---------------------- | :------------------------: |
| `@vitejs/plugin-react`    | `^5.1.4`  | 5.2.0 부터 `…\|^8.0.0` | ✅ **메이저 안 올려도 됨** |
| `vite-plugin-svgr`        | `5.2.0`   | `>=3.0.0`              |        ✅ 이미 최신        |
| `@storybook/react-vite`   | `10.5.10` | `^5\|^6\|^7\|^8`       |             ✅             |
| `@tailwindcss/vite`       | `4.3.3`   | `^5.2.0\|^6\|^7\|^8`   |             ✅             |
| `@tanstack/router-plugin` | `^1.168`  | `>=5`                  |             ✅             |
| `vitest`                  | `^3`      | 4는 `^6\|^7\|^8`       |       ✅ 함께 올라감       |

### Node 요구

Vite 7·8 모두 `^20.19.0 || >=22.12.0`.
이 저장소는 `engines.node: >=22.13.0`, 실제 실행 `v24.4.1` → **문제 없음**.

## 범위

- `apps/web/package.json` — `vite` `^5.1.4` → `^8`, `vitest` `^3` → `^4`,
  `@vitejs/plugin-react` `^5.1.4` → `^5.2.0`(최소) 또는 `^6`
- `pnpm-lock.yaml` 재생성
- `apps/web/vite.config.ts` · `vitest.config.ts` — 옵션 변경 대응
- `CLAUDE.md` Tech Stack 표 갱신, `.claude/rules/` 의 Vite 5 언급 정정

## Out of Scope

- 다른 워크스페이스(`apps/native` · `apps/legacy-web`) — legacy-web은 편집 금지
- 기능 변경. **동작 보존이 목표다**

## ⚠️ 주의 — 번들러가 바뀐다

```
vite@5.4  →  rollup ^4.20 + esbuild ^0.21
vite@8.2  →  rolldown ~1.2.4
```

Rust 기반 **Rolldown**으로 교체됐다. 빌드는 빨라지지만 **산출물이 달라질 수 있다** —
청크 분할, 트리셰이킹 결과, 소스맵. "버전만 올리고 끝"이 아니라 **빌드 결과를 확인해야 하는 작업**이다.

## 착수 판단 (`refactor-checklist.md` 필수 게이트)

| 질문                               | 판정        | 근거                                                                 |
| ---------------------------------- | ----------- | -------------------------------------------------------------------- |
| 목표와 비목표가 명확한가           | 충족        | 도구 버전과 설정만 바꾸고 제품 기능은 보존한다                       |
| 반복 비용이나 확장 차단이 있는가   | 충족        | Vite 5가 Vitest 4 도입을 막는다                                      |
| 기준선이 있는가                    | 충족        | 현재 dev·build·Storybook·test 결과와 번들 산출물을 비교할 수 있다    |
| 검증 방법이 있는가                 | 충족        | dev·build·Storybook·test 및 주요 라우트 수동 확인이 가능하다         |
| 범위를 독립적으로 완료할 수 있는가 | 충족        | 패키지·잠금 파일·Vite/Vitest 설정으로 한정한 단독 PR로 진행한다      |
| 위험을 격리했는가                  | 조건부 충족 | 단독 PR과 산출물 비교, 되돌리기 커밋으로 번들러 교체 영향을 격리한다 |

모든 게이트의 근거를 설명할 수 있으므로 착수 가능하다. 다만 번들러 교체 영향이 넓어 다른 변경을
섞지 않고, 기존 빌드와의 차이를 설명할 수 없으면 배포하지 않는다.

### 업그레이드 순서

[Vite 8 공식 마이그레이션 권고](https://vite.dev/blog/announcing-vite8)에 따라 한 번에 원인을
섞지 않는다.

1. Vite 7에서 `rolldown-vite`로 전환해 Rolldown 관련 회귀를 먼저 확인한다.
2. 같은 검증 기준을 통과하면 Vite 8과 Vitest 4로 올린다.
3. 각 단계의 잠금 파일·빌드 산출물 차이를 기록하고, 실패하면 해당 단계만 되돌린다.

## 확정 명세 · 검증 기준

- [ ] **AC-1** (범위: 통합)
      Given Vite 8 로 올린 상태
      When `pnpm build` 를 실행한다
      Then 빌드가 성공하고 `apps/web/dist/` 에 산출물이 생긴다
- [ ] **AC-2** (범위: 통합)
      Given Vitest 4 로 올린 상태
      When `pnpm test` 를 실행한다
      Then 기존 테스트가 모두 통과한다 (개수 감소 없음)
- [ ] **AC-3** (범위: 통합)
      When `pnpm --filter @repo/web build-storybook` 을 실행한다
      Then 빌드가 성공한다
- [ ] **AC-4** (범위: 수동)
      When `pnpm dev` 로 띄워 `/terms` · `/privacy` 에 진입한다
      Then 화면이 그려지고 콘솔에 에러가 없다
