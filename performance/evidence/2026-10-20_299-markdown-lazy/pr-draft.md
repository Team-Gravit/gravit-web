첫 로딩 번들(`index-*.js`)에서 마크다운 렌더링 코드를 분리했습니다. 마크다운은 퀴즈와 개념 노트에서만 쓰는데, 북마크·오답 풀이 라우트 설정이 `@/entities/problem` 배럴을 거쳐 `ProblemCard`와 마크다운 라이브러리(react-markdown, micromark, refractor 등)까지 첫 번들로 끌고 오고 있었습니다.

`shared/ui/markdown`은 실제 구현을 `import()`로 불러오는 입구만 공개하고, 퀴즈·개념 노트 라우트의 loader에서 미리 받습니다. 처음에는 `React.lazy`만 썼는데, 모듈을 이미 받아 둔 상태에서도 첫 렌더에서 한 번 멈추면서 스켈레톤을 다시 그려 개념 노트 LCP가 2초 가까이 늦어지고 레이아웃 밀림이 늘었습니다. 그래서 받아 둔 모듈은 Suspense를 거치지 않고 바로 그리도록 했습니다.

첫 번째 커밋은 동작 변경 없이 코드 블록을 `code-block.tsx`로 분리하고 파일명을 정리한 것입니다. 마크다운이 비동기로 그려지면서 관련 테스트는 내용이 나타날 때까지 기다리도록 바꿨습니다.

### LCP

모바일(412×823), CPU 4x, Fast 4G에서 5회 측정한 중앙값입니다. API 응답은 녹화해 두고 매번 같은 지연으로 돌려줘서 네트워크 영향을 뺐고, before와 after를 번갈아 쟀습니다. 같은 빌드를 한 번 더 띄워 측정 흔들림도 같이 기록했습니다.

<!-- 이미지: lcp-comparison.png -->

| 화면 | before | after | 같은 빌드끼리 차이 |
| --- | --- | --- | --- |
| `/main` | 4.50s | 3.95s | 0.00s |
| 개념 노트 | 7.42s | 7.04s | 0.09s |
| `/learning` | 5.49s | 5.57s | 0.19s |

`/learning`은 FCP만 4.16s → 3.82s로 줄고 LCP는 차이가 없습니다. LCP 요소인 카드 배경 이미지가 챕터 API 응답 뒤에야 요청되는 구조라, 데이터 미리 요청과 이미지 로딩 작업에서 따로 다룹니다.

### 검증

`pnpm lint`, `pnpm check-types`, `pnpm test` (563개 통과), `pnpm build`, 변경 파일 Prettier 검사 통과.
개념 노트 세 개(코드 블록·표 포함)를 같은 응답으로 그려 본문 전체를 캡처했고, before와 after가 픽셀 단위로 같습니다. 퀴즈 문제 본문도 직접 확인했습니다.
전체 테스트를 세 번 실행했을 때 한 번 실패했고 재실행에서는 통과했습니다. 기존에 기록된 간헐 실패로 보고 있습니다.
