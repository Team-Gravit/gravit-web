# 제품 구현 현황

**Figma에 정의된 화면이 Web과 Native에서 구현·검증됐는지 확인하는 제품 대장이다.**

legacy 코드 대체 여부는 [`migration-status.md`](./migration-status.md), 화면별 상세 명세는
[`fe-implement-spec/`](./fe-implement-spec/README.md)에서 관리한다.

## 1. 기준과 완료 정의

- 화면 식별자는 Figma 프레임 이름을 그대로 쓴다
- WEB과 AOS에서 같은 ID는 같은 제품 화면의 플랫폼 변형이다
- 화면 ID를 Figma에서 확인하지 못한 구현은 추측해 연결하지 않고 `매핑 미확인`에 둔다
- 파일이 존재하거나 WebView에서 보이는 것만으로 구현 완료 처리하지 않는다

| 상태 | 의미                                                           |
| :--: | -------------------------------------------------------------- |
|  ✅  | 구현 존재 + 상태 프레임 반영 + 시안 대조 + 기능 검증 완료      |
|  🚧  | 구현 또는 검증 진행 중                                         |
|  ⬜  | 미구현                                                         |
|  △   | 구현은 있으나 Figma 매핑 또는 검증이 끝나지 않았다 (부분)      |
|  —   | **구현 대상이 아니다** — 시안이 없거나, 네이티브 구현이 불필요 |

### 플랫폼 명칭

현재 Figma에는 `WEB`과 `AOS` 시안만 있고 iOS 전용 시안은 없다. `apps/native`는 Android와 iOS가
공유하는 React Native 앱이지만, 현재 화면별 네이티브 UI가 아니라 WebView 하나로 `apps/web`을 연다.
따라서 이 문서는 플랫폼별 완료를 따로 주장하지 않는다. **네이티브 구현 열은 화면을 네이티브로
새로 만들기로 결정한 경우에만** 쓰고, 그 전까지는 `—`(대상 아님)로 둔다.

> **Web 구현이 62건 모두 `⬜`다.** `apps/web` 의 라우트는 `/` · `/terms` · `/privacy` 셋뿐이고,
> 그중 Figma 화면 ID에 대응하는 것은 없다. `/terms` · `/privacy` 는 아래 「매핑 미확인」에 둔다.
>
> **「네이티브 구현」은 모두 `—` 다.** `apps/native` 는 WebView 하나로 `apps/web` 을 여는 셸이라
> 화면별 네이티브 UI를 만들지 않는다. **Web 을 구현하면 앱에도 그대로 나온다.**
> 이 열은 나중에 특정 화면을 네이티브로 새로 만들기로 결정할 때만 `⬜` 로 바뀐다.

### 이름·구역 확인 필요

- **`A.*` 가 무엇의 약어인지** — 애니메이션 모달 묶음이다(`A.1.1` 티어 승급, `A.2` 레벨업).
  약어의 정식 의미는 확인되지 않았다
- **`A.4`(AOS) 는 `R.1`(WEB) 의 오기** — 내용이 같다(계정 복구). 한쪽으로 통일 필요
- **`INTERVIEW SIMULATOR` 섹션이 양쪽 다 비어 있다** — 미착수인지 다른 파일인지
- 화면 이름은 **내용을 직접 확인한 것만** 적었다. 나머지는 비워 두고 추측하지 않는다

## 4. 갱신 규칙

- `FEAT-`, `MIG-`, `FIX-`, `NAT-`에서 사용자 화면의 구현 또는 검증 상태가 바뀌면 갱신한다
- 화면 ID는 Figma에서 직접 확인한 경우에만 연결한다
- 같은 ID의 여러 프레임은 별도 화면이 아니라 상태 변형으로 검증한다
- 네이티브 구현 열은 **화면을 네이티브로 새로 만들기로 결정한 경우에만** 채운다
- 사용자 판정 전에는 시안 대조를 완료 처리하지 않는다
- 상세 AC와 디자인 차이는 이 문서에 복제하지 않고 작업 문서와 화면 명세에 링크한다
