**F05 의 조건이 `isOnboarded` 가 아닌 이유** — 서버 값으로 지키면 범위가 너무 넓다. 오래 전에
가입한 사용자가 주소만 쳐도 「계정 생성 완료!」를 다시 보게 된다. 이 화면이 요구하는 것은
「가입했는가」가 아니라 **「방금 이 흐름에서 제출했는가」** 이고, 그건 서버가 모른다.

통과권은 라우터 state(`fromOnboarding`)로 넘긴다. `history.state` 라 새로고침에도 남으므로
「완료 화면을 거쳐 `/main` 으로 간다」는 계약이 유지된다. 목적지를 여기서 정하지 않고
`/onboarding` 으로 넘기는 이유는, 그쪽 가드가 「가입을 마쳤으면 `/main`」을 이미 판정하기
때문이다 — 같은 규칙을 두 곳에 두지 않는다.

**ONB-02-F06 이 왜 필요한가** — legacy 에는 이 처리가 없어서, 등록 직후 사용자 조회가 여전히
「사용자 없음」이면 가입에 성공한 사람이 입력 화면으로 되튕길 수 있었다.

## 4. 라우트 및 화면 이동

```
/onboarding  ──(등록 성공 · replace)──▶  /onboarding/success  ──「홈으로」──▶  /main
                                              │
                                              └─(통과권 없이 직접 진입)──▶ /onboarding
                                                     ├─ 아직 가입 전 → 온보딩 폼
                                                     └─ 이미 가입   → /main
```
