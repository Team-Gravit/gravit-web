# 디자인 기준 정책

**디자인 의도의 Source of Truth는 Figma, 코드에서 사용할 토큰 계약은 `tokens.css`다.**
둘이 어긋나면 임의로 한쪽을 선택하지 않고 차이를 확인해 동기화한다.

---

## 1. 우선순위

값이 서로 어긋나면 이 순서로 따른다.

```
Figma (Dev Mode)      ← 디자인 의도
        ↕ 대조·동기화
tokens.css            ← 구현에서 사용하는 토큰 계약
docs/design-system/   ← 결정 근거와 현황을 설명하는 기준 문서
PNG 캡처              ← 참고용. 값의 근거로 쓰지 않는다
```

`docs/design-system/`은 Figma와 코드의 관계 및 결정 근거를 설명한다. 값이 어긋났다면 문서를
무시하지 말고 어느 쪽이 갱신되지 않았는지 확인한다.

## 2. ⚠️ Figma MCP가 만들어 준 코드를 구현에 쓰지 않는다

Figma MCP는 선택한 노드의 React/Tailwind 코드를 만들어 줄 수 있다. **붙여넣지 않는다.**

그 코드는:

- 우리 FSD 레이어 구조를 모른다 — 전부 한 파일에 쏟아낸다
- 우리 공용 컴포넌트(`Button` · `Icon` · `GravitLogo`)를 모른다 → 일회성 마크업을 만든다
- 우리 토큰 이름 대신 **원시 색상값**을 박는다 (`#242424` 대신 `text-text-1`이어야 한다)
- `cn()` / cva variant 체계를 우회한다
- `rounded-8` 같은 커스텀 스케일을 모르고 Tailwind 기본 이름을 쓴다 (**이 프로젝트엔 없는 이름**)

**생성 코드는 "시안에 무엇이 있는지" 읽는 용도로만 쓴다.**
구현은 우리 컴포넌트와 토큰으로 한다.

## 3. PNG에서 픽셀값을 역산하지 않는다

캡처 이미지를 재서 `gap-[29px]` 같은 값을 만들어내지 않는다.
정확한 간격·크기·색·타이포는 **Figma Dev Mode 또는 토큰**에서 가져온다.

PNG로 확인해도 되는 것: 요소의 **존재 여부 · 순서 · 정렬 · 상태 구분**.
PNG로 확인하면 안 되는 것: **수치**.

## 4. 시안과 구현을 비교할 때 보는 축

순진하게 "스크린샷 vs 구현"으로 붙이면 "2px 다름"을 수백 개 뱉고 정작 중요한 게 묻힌다.
아래 6개만 본다.

| 축                  | 비교 대상                                         |
| ------------------- | ------------------------------------------------- |
| ① **토큰**          | Figma 변수 ↔ `tokens.css` / Tailwind 클래스      |
| ② **공용 컴포넌트** | Figma 컴포넌트·variant ↔ 우리 `Button variant=…` |
| ③ **구조**          | 요소 존재 여부 · 순서 · 정렬                      |
| ④ **상태 커버리지** | 빈 / 로딩 / 에러 / 비활성 / 권한없음              |
| ⑤ **문구**          | 레이블 · 플레이스홀더 · 에러 메시지               |
| ⑥ 수치              | **토큰이 있는 경우에만** (`px-5` ↔ Margin 20)    |

**④가 가장 값어치 있다.** 시안에 상태 프레임이 있는데 구현에 없으면
그건 "시안과 다르다"가 아니라 **"기능이 없다"**이다.

**비교하지 않는 것**: 폰트 렌더링 차이 · 안티에일리어싱 · 애니메이션(시안에 정의가 없다) ·
토큰이 확정되지 않은 항목.

## 5. 소스가 충돌하면 결정하지 않는다

기획 · Figma · 확정 라우트 · API 계약이 서로 다르면 **임의로 고르지 않는다.**
`work/{ID}/spec.md`의 `확인 필요`에 적고 사용자 판정을 받는다.

여기서 내가 고르면 그게 제품 결정이 된다.

## 6. 미확정 토큰은 하드코딩하지 않는다

`tokens.css`에 없는 값을 공통 토큰처럼 새로 만들거나 임의의 이름으로 추가하지 않는다.

한 번 하드코딩되면 나중에 토큰이 확정돼도 찾아서 고치기 어렵다.

- spacing은 Figma 공통 토큰이 없으므로 우선 Tailwind 기본 스케일에서 가장 가까운 값을 사용한다
- shadow/elevation은 공통 정의가 확인되기 전까지 새로 추가하지 않는다
- 시안 고유 수치가 기본 스케일로 표현되지 않으면 Figma의 실제 값을 근거와 함께 기록하고,
  재사용되는 값인지 확인한 뒤 토큰 승격 여부를 결정한다
- 현재 토큰 상태와 예외는 `docs/design-system/README.md`에서 확인한다

## 7. 시안이 없는 화면

Figma 시안이 없는 화면은 다음처럼 처리한다.

- **"시안 없음"을 문서에 명시한다** (확인한 날짜와 함께)
- 그 작업에서는 **동작·외형을 그대로 옮기는 것만** 한다. 개선 판단을 하지 않는다
- 나중에 시안이 생기면 별도 작업에서 대조한다

## 8. 정리 대상 호환 토큰

- **새 화면에서 호환 토큰을 새로 쓰지 않는다.** 정식 토큰(`text-1`, `bg-1`, `main`, `cta` 등)을 쓴다
- 제거 전 `apps/web`과 `apps/legacy-web`의 실제 사용처를 모두 검색한다
- 사용처가 없고 대체 토큰이 확정된 항목만 별도 작업에서 제거한다
- 토큰 정리 상태는 `docs/design-system/README.md` §4에서만 관리한다
