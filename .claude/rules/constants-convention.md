# 상수 추출 규칙

값을 상수로 뽑을지 컴포넌트에 인라인으로 둘지 판단한다.
AI가 가장 자주 과하게 하는 일이 상수 추출이다 — padding 값까지 뽑아 파일 상단이 의미 없는 상수로 가득 차는 걸 막는다.

---

## 기본 원칙

> **"관리 포인트인가?"** 하나로 판단한다.
> 나중에 **기획·정책이 바뀌면 이 값을 찾아서 고쳐야 하는가?**

관리 포인트가 아니면 뽑지 않는다.

---

## 상수로 추출한다 — 아래 중 하나라도 해당하면

### 1. 요구사항이 명시적으로 지시했다

본문에 아래 표현이 있으면 **해석 여지 없이** 상수로 뽑는다. 패턴 매칭 룰이다.

- `설정값으로 관리` / `별도로 설정값으로 관리`
- `관리 포인트` / `관리포인트`
- `상수로 관리` / `상수로 정의`
- `설정으로 분리` / `설정값으로 분리`

기획이 "이건 나중에 바뀔 수 있다"고 말한 것이므로 판단할 필요가 없다.

### 2. 비즈니스·도메인 의미가 있다

- **제약값**: `MAX_UPLOAD_COUNT`, `QUIZ_PASS_SCORE`, `IDLE_TIMEOUT_MS`
- **사용자에게 보이는 문구 중 기획이 바꾸는 것**: placeholder, 에러 메시지, 빈 상태 문구, 버튼 레이블
- **도메인 식별자**: `DEFAULT_TIER` 같은 기본값

> 문구에 대한 주의 — 화면 고유의 본문 텍스트(약관 조항, 안내 문단)는 **인라인**이다.
> 뽑는 대상은 **여러 곳에 쓰이거나 기획이 바꿀 문구**다. i18n과는 무관하다 (`i18n-policy.md`).

### 3. 두 곳 이상에서 같은 값을 쓴다

두 개 이상의 파일·컴포넌트가 같은 값을 참조하면 상수로 뽑는다.

**단 레이아웃 수치는 예외다.** `px-4`가 여러 곳에 나와도 각 맥락이 다르므로 뽑지 않는다.

> ⚠️ 이건 **값을 상수로 뽑는** 기준이다. **코드(헬퍼·컴포넌트)를 추출하는** 기준은 다르다 —
> 그건 "2번 등장은 인라인, 3번 등장에 추출"이고 `refactor-checklist.md`에 있다. 헷갈리지 않는다.

### 4. 여러 사용처가 공유하는 정책값이다

- 여러 컴포넌트가 같은 기본 제한·문구·동작 정책을 공유한다
- 환경별 값의 이름과 기본 처리 정책을 한곳에서 관리해야 한다 (`import.meta.env.VITE_*`)

한 컴포넌트만 쓰는 prop 기본값은 구조 분해 위치에 인라인으로 둔다.

---

## 인라인으로 둔다 — 수치가 명시돼 있어도

### 1. 레이아웃·스타일 수치

padding · margin · gap · 아이콘 크기 · radius · font-size.
요구사항의 `"여백은 16px"`, `"간격은 8px"`은 **디자인 스펙**이지 관리 포인트가 아니다.

- Tailwind 클래스로 표현 가능하면 클래스 우선 (`px-4`, `gap-2`)
- 토큰에 없는 값이 필요하면 임의 값을 박기 전에 `design-source-policy.md` §6을 본다

### 2. 한 컴포넌트 안에서만 쓰이는 값

재사용되지 않으면 뽑지 않는다.

### 3. 순수 구현 디테일

- HTML 속성에 종속된 값 (`rows={1}`, `maxLength` 등)
- 요구사항에 명시되지 않은 내부 애니메이션 `duration`

## 판단 순서

```
값을 보면:
  ├─ 키워드("설정값으로 관리" 등)가 있나?     → 상수 ✅
  ├─ 비즈니스 의미가 있나 (제약·기획 문구)?   → 상수 ✅
  ├─ 두 곳 이상에서 쓰이나?                   → 상수 ✅ (레이아웃 수치는 제외)
  ├─ 여러 사용처가 공유하는 정책값인가?       → 상수 ✅
  ├─ 레이아웃·스타일 수치인가?                → 인라인 ❌
  └─ 그 외 한 컴포넌트 내부 값                → 인라인 ❌
```

**위에서부터 본다.** 키워드가 있으면 레이아웃 수치여도 상수다.

---

## 어디에 두는가

| 범위                 | 위치                                 |
| -------------------- | ------------------------------------ |
| 한 컴포넌트 안에서만 | 그 파일 상단 (컴포넌트 바깥)         |
| 한 slice 안에서      | `{layer}/{slice}/model/constants.ts` |
| 도메인 무관 전역     | `shared/config/`                     |

슬라이스를 넘겨 공유하려고 `shared`로 올리기 전에 **정말 도메인 무관인지** 확인한다.
도메인 값이면 `entities/{slice}/model/`에 있어야 한다.

## 네이밍

- `SCREAMING_SNAKE_CASE`
- 단위를 이름에 넣는다: `TIMEOUT_MS`, `MAX_WIDTH_PX`
- 무엇의 값인지 밝힌다: `LIMIT` ❌ → `MAX_UPLOAD_COUNT` ✅

---

## 의심스러우면 인라인

**인라인이 기본값이다.** 나중에 재사용이 생기거나 관리 포인트로 승격되면 그때 뽑는다.

반대 방향은 더 비싸다 — 상수로 먼저 만든 뒤 인라인으로 되돌리는 건 번거롭고,
**요구사항 변경 이력을 오염시킨다** (그 상수가 왜 생겼는지 추적이 흐려진다).
