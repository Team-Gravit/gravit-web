# design-diff

시안과 구현의 차이를 **판정 가능한 목록**으로 만든다.

## 왜 고치지 않고 목록만 만드는가

차이가 나왔을 때 셋 중 무엇인지는 **사람만 안다.**

| 차이의 정체          | 예                                   |
| -------------------- | ------------------------------------ |
| 구현이 틀렸다        | 토큰을 잘못 썼다                     |
| 시안이 최신이 아니다 | 그 사이 기획이 바뀌었다              |
| **의도된 것이다**    | 시안에 없지만 없으면 사용자가 막힌다 |

세 번째가 특히 위험하다. 실제로 Footer 대조에서 **약관·개인정보 링크가 시안에 없었지만,
그 화면으로 가는 유일한 경로**라 지우면 안 되는 경우가 나왔다.
AI가 "시안에 없으니 제거"로 판단하면 제품이 망가진다.

→ `design-source-policy.md` §5. **소스가 충돌하면 결정하지 않는다.**

## 전제

- **Figma 파일 링크** — `docs/design-system/README.md` §2에 파일 키와 노드 ID가 있다
- **화면 ID** — Figma 프레임 이름이 곧 ID다 (`docs/fe-implement-spec/README.md` §4)
- 대조 결과를 적을 `work/{to-do|in-progress}/{ID}/spec.md`

## 절차

### 1. 시안을 읽는다

**`get_design_context` 호출 전에 `figma-design-to-code` 스킬을 먼저 로드한다.** 필수 절차다.

| 도구                 | 무엇을 얻나                        | 주의                               |
| -------------------- | ---------------------------------- | ---------------------------------- |
| `get_screenshot`     | 실제 렌더 모습                     | **내용 유무 판정은 이걸로 한다**   |
| `get_variable_defs`  | 노드에 바인딩된 디자인 변수        | 원시값(rgba 등)은 안 나온다        |
| `get_design_context` | 색·타이포·여백 실제 값 + 참조 코드 | 코드는 **읽기용**. 붙여넣지 않는다 |
| `get_metadata`       | 구조·좌표·크기                     | 아래 함정 참고                     |

> ⚠️ **`get_metadata`로 "내용 없음"을 판정하지 않는다.** 섹션 전체를 조회하면 응답 크기 때문에
> 깊은 서브트리가 잘리고 `<frame ... />` self-closing 으로 나온다. **비어서가 아니라 안 펼쳐져서다.**
> 실제로 `L.10`·`A.1.1`·`A.2`를 빈 프레임으로 오판한 적이 있다. 내용 확인은 `get_screenshot`.

> ⚠️ 큰 노드는 응답이 수십만 자라 **파일로 떨어진다.** 프레임 이름만 필요하면 그 파일을 파싱한다
> (들여쓰기 2=섹션, 4=화면 프레임).

> ⚠️ **같은 이름 프레임이 여러 개면 상태 변형 후보로 본다.** 중복·초안일 수도 있으므로
> 각 프레임의 내용과 기획 근거를 대조해 목록에 올리고, 구현 대상인지는 사용자가 판정한다.

### 2. 토큰은 **디자인 시스템 페이지**와, **눈이 아니라 스크립트로** 대조한다

> ⚠️ **화면 노드의 변수를 토큰으로 착각하지 않는다.** 화면에서 `get_variable_defs`로 나오는 값에는
> 옛 값·로컬 오버라이드·이름 오타(`icon-defult`)가 섞여 있다. 실제로 그걸 기준으로 삼아
> "8건 불일치"라는 **틀린 보고**를 한 적이 있다. 기준은 **Alias Token 페이지 하나**다
> (링크는 `docs/design-system/README.md` §2).

> ⚠️ 페이지에 손으로 적은 hex 텍스트와 변수 값이 다르면 어느 한쪽을 임의로 고르지 않는다.
> Dev Mode의 변수 바인딩과 실제 값을 근거로 대조하고, 값을 조회할 수 없다면 충돌 사실을
> `확인 필요`에 남긴다. 스크린샷 픽셀은 색상값의 근거로 사용하지 않는다.

값 비교는 **스크립트로** 한다. 눈으로 보면 `#6d6d6d`와 `#6f6f6f`를 놓친다.

대조할 때 확인할 것:

- **별칭 토큰이 있는가** — 없으면 임의로 만들지 말고 `확인 필요`에 남긴다
  (`--primitive-*`는 Tailwind 유틸리티가 생성되지 않는다)
- **호환 토큰을 쓰고 있지 않은가** — 현재 목록과 제거 조건은
  `docs/design-system/README.md`에서 확인한다
- **시안 쪽이 원시값인가** — Figma가 `rgba(255,255,255,0.58)` 처럼 토큰 없이 쓰고 있으면
  그 자체가 보고 대상이다

### 3. 6축으로 본다

순진하게 "스크린샷 vs 구현"으로 붙이면 "2px 다름"을 수백 개 뱉고 정작 중요한 게 묻힌다.

| 축                  | 비교 대상                            |
| ------------------- | ------------------------------------ |
| ① 토큰              | Figma 변수 ↔ `tokens.css`           |
| ② 공용 컴포넌트     | Figma variant ↔ 우리 `variant`      |
| ③ 구조              | 요소 존재 · 순서 · 정렬              |
| ④ **상태 커버리지** | 빈 / 로딩 / 에러 / 비활성 / 권한없음 |
| ⑤ 문구              | 레이블 · 플레이스홀더 · 에러 메시지  |
| ⑥ 수치              | **토큰이 있는 경우에만**             |

**④가 가장 값어치 있다.** 시안에 상태 프레임이 있는데 구현에 없으면
그건 "다르다"가 아니라 **"기능이 없다"** 이다.

**비교하지 않는 것**: 폰트 렌더링 · 안티에일리어싱 · 애니메이션 · 미확정 토큰 항목.

### 4. 수치는 Dev Mode 에서만 가져온다

**PNG를 재서 `gap-[29px]` 같은 값을 만들어내지 않는다.** Figma 노드의 좌표·크기를 쓴다.

PNG로 확인해도 되는 것: 요소의 **존재 · 순서 · 정렬 · 상태 구분**.

> ⚠️ **PNG의 흰 글씨는 흰 배경에서 안 보인다.** 앱센터 로고를 "오른쪽이 비었다"고 오판한 적이 있다.
> 투명/흰색이 의심되면 알파 채널을 확인한다.

### 5. 결과를 spec.md 에 쓴다

`work/{to-do|in-progress}/{ID}/spec.md`의 **「시안 대조 결과」 섹션에만** 쓴다.
다른 섹션은 건드리지 않는다.

| #   | 항목 | 현행 | 시안 | 판정 |
| --- | ---- | ---- | ---- | ---- |

**판정 열은 비워둔다.** 사용자가 `고침 / 유지 / 나중` 중 하나로 채운다.

그리고 **임의로 결정하면 안 되는 것**을 「확인 필요」에 분리한다.

- 기획·Figma·라우트·API 계약이 서로 어긋날 때
- 지우면 사용자 경로가 끊기는 요소
- 토큰 이름을 새로 지어야 하는 경우
- 과거에 **일부러 바꾼 이력**이 있는 값 (`git log`로 확인한다)

> 실제 사례 — `bg-1`이 시안과 달랐는데 `fix(web): bg-1 토큰을 디자인 값 #FFFFFF로 수정` 커밋이
> 있었다. "당시 디자인 값"과 "현재 Figma"가 다른 것이라 단정할 수 없었다.

### 6. 시안이 없으면 그것을 기록한다

**"시안 없음"을 확인한 날짜와 함께 명시한다.** 비워두면 대조를 안 한 건지 시안이 없어서
못 한 건지 구분되지 않는다.

시안이 없는 화면은 **동작·외형을 그대로 옮기는 것만** 하고 개선 판단을 하지 않는다.
나중에 시안이 생기면 그 기록을 근거로 `FIX-` 항목을 만든다.

## ⏸ 게이트

대조 목록을 사용자에게 제시하고 **판정을 받는다.** 판정 없이 다음 단계로 가지 않는다.

판정이 끝나면:

- `고침` → 확정 명세·검증 기준으로 옮기고 구현 단계로
- `유지` → 사유를 함께 기록
- `나중` → `work/to-do/`에 `FIX-` 항목으로 분리

## 산출물

| 대상                     | 위치                                               |
| ------------------------ | -------------------------------------------------- |
| 대조 결과 표 · 확인 필요 | `work/{상태}/{ID}/spec.md` 「시안 대조 결과」      |
| 범위 밖 차이             | `work/to-do/FIX-{번호}-*/spec.md`                  |
| 확정된 토큰 판정 반영    | 사용자 판정 후 `docs/design-system/README.md`      |
| Figma 링크               | `docs/design-system/README.md` §2 — **1회만 기록** |

## 하지 않는 것

- **차이를 고치지 않는다.** 판정 전에 코드를 바꾸지 않는다
- **Figma MCP 생성 코드를 붙여넣지 않는다.** 우리 컴포넌트·토큰을 모른다
  (`design-source-policy.md` §2)
- **미확정 토큰을 하드코딩하지 않는다.** `확인 필요`에 남긴다
- **PNG에서 픽셀값을 역산하지 않는다**
- 폰트 렌더링·안티에일리어싱 차이를 보고하지 않는다
