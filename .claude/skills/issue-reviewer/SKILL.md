# issue-reviewer

각 항목은 처리 기준을 가진다.

- **[필수]** — 해결하기 전에는 이슈를 승인하거나 구현으로 넘기지 않는다
- **[권고]** — 이슈 실행은 가능하지만 품질·유지보수 위험을 검토하고 판단 근거를 남긴다

---

## 1. 형식

- **[필수]** `설명` 섹션이 있고 사용자 가치 중심 1~3문장인가
- **[필수]** `구현 범위` 섹션에 수정 대상 파일/레이어가 명시돼 있는가
- **[필수]** `완료 조건`의 AC가 Given-When-Then 형식인가
- **[권고]** 각 AC에 `(범위: 단위)` 또는 `(범위: 통합)` 레이블이 있는가
- **[필수]** work task 내부 순번이 중복 없이 부여돼 있는가
- **[권고]** 승인된 실행 이슈가 GitHub Issue와 1:1로 연결됐는가. 미등록이면 그 사실이 명시돼 있는가

## 2. 수직 슬라이싱

판단 기준: **"이 이슈만 완료하면 사용자에게 보여줄 수 있는 동작이 있는가?"**

- **[필수]** 이슈 단독으로 관찰 가능한 동작이 존재하는가
  - 실패 예: "API 함수만 추가", "스토어만 추가" — 이 상태로는 아무것도 동작하지 않는다
- **[필수]** 레이어(API / 상태 / UI)를 수평으로 잘라 나누지 않았는가
- **[권고]** 이 이슈만으로 구현 → 검증이 완결되는가

## 3. Acceptance Criteria

### Given

- **[필수]** 재현 가능한 값 또는 상태가 있는가
  - 허용: `[{ id: 1, name: '홍길동' }]` · `count === 0` · `provider: 'kakao'`
  - 허용: `userId: 1인 인증 사용자의 onboardingCompleted가 true`
  - 불허: "데이터가 있을 때" · "유효한 상태" · "필요한 정보가 준비됐을 때"
- **[권고]** 경계 조건(빈 값 · 최대값 · 중복)이 별도 AC로 커버되는가

### When

- **[필수]** 외부에서 **관찰 가능한 행동**인가 (함수 호출, 버튼 클릭, 라우트 진입)
  - 불허: "시스템이 처리할 때" · "내부 상태가 변경될 때"

### Then

- **[필수]** 검증 가능한 **값·개수·문구**가 명시돼 있는가
  - 허용: `items.length === 1` · `href가 '/main'` · `toast에 "저장되었습니다"`
  - 불허: "필터링된다" · "이동한다" · "저장된다"
- **[필수] 금지어가 없는가**
  `정상적으로` `적절히` `올바르게` `보여진다` `처리된다` `업데이트된다` `반영된다`
  → 결과값 없이 결과를 서술하므로 테스트로 1:1 변환이 불가능하다

### 범위 레이블

- **[권고]** `단위`는 순수 함수 또는 `renderHook`으로 검증 가능한가
- **[권고]** `통합`은 RTL `render` + `userEvent`로 검증 가능한가
- **[권고]** 시각 스타일을 AC로 잡고 있지 않은가 → 그건 Storybook + Figma 대조의 영역이다
  (`test-policy.md` · `design-source-policy.md`)

## 4. 용어 일관성

- **[권고]** 핵심 용어가 `spec.md`의 `용어 정의`와 일치하는가
- **[권고]** 같은 개념을 이슈마다 다른 단어로 부르고 있지 않은가

`spec.md`가 없으면 이슈 내부 일관성만 보고 **그 사실을 명시한다.**

## 5. 크기

- **[권고]** 반나절~하루라는 목표 크기를 크게 넘길 근거가 있는가
- **[필수]** 하나의 사용자 결과와 하나의 리뷰 가능한 변경 단위로 설명할 수 있는가
- **[권고]** 서로 독립적으로 배포·검증할 수 있는 결과가 둘 이상 섞여 있는가
- **[권고]** AC가 많다면 개수 자체가 아니라 서로 다른 사용자 결과가 섞였는지 검토했는가

## 6. gravit 구조 정합성

- **[필수]** 구현 범위가 FSD 레이어 책임과 맞는가 (`.claude/rules/fsd-*.md`)
  - 수직 슬라이스라면 여러 레이어가 한 이슈에 포함될 수 있다. 상향·cross-slice 의존과 범위 밖 변경을 본다
- **[필수]** 자동 생성물을 직접 수정하는 계획이 없는가
  (`routeTree.gen.ts` · `shared/api/generated/` — 훅이 차단한다)
- **[권고]** 라우트를 추가하는 이슈에 **트리 재생성** 단계가 고려돼 있는가
  (`ai-orchestrate` §4 — 빼먹으면 타입 검사가 실패한다)
- **[권고]** UI 변경이 Figma 또는 `tokens.css` 근거와 연결돼 있는가. 시안이 없으면 그 사실이 적혀 있는가
- **[권고]** web / native 경계를 넘는 이슈라면 **누가 무엇을 소유하는지** 적혀 있는가

## 7. 의존성

- **[필수]** 선언한 선행 이슈가 실제로 필요한 계약이나 결과물을 제공하는가
- **[필수]** 역방향 의존이 없는가 (뒤 이슈의 결과물을 앞 이슈가 쓰고 있지 않은가)
- **[필수]** 순환 의존이 없는가
- **[권고]** 독립 실행 가능한 이슈에 불필요한 선행 관계를 만들지 않았는가

### 시퀀스 전체 (이슈 목록을 통째로 볼 때)

- **[필수]** 의존성이 있는 이슈는 선행 결과 → 후행 입력 관계가 성립하는가
- **[필수]** 필요한 선행 이슈가 빠져 실행 불가능한 구간이 없는가
- **[권고]** 서로 독립적인 이슈는 병렬로 진행할 수 있게 표현돼 있는가
- **[권고]** `spec.md`의 Out of Scope 항목이 이슈에 슬쩍 들어가 있지 않은가

## 출력 형식

이슈별로 검토한 뒤 **반드시 세 섹션**으로 낸다. 이슈가 여러 개면 마지막에 시퀀스 전체를 따로 본다.

```
## 리뷰 결과 — Issue 3: [OAuth] 카카오 로그인

### 🔴 필수 수정
- **AC-1 Then 금지어**: "로그인이 정상적으로 처리된다"는 결과값 없는 서술.
  → `accessToken이 저장되고 /main으로 이동한다` 형태로 수정 필요.
- **수직 슬라이싱 위반**: SDK 연동만 포함되어 있고 UI·저장이 없음.
  이슈 단독으로 관찰 가능한 동작이 없다.

### 🟡 개선 권고
- **AC 범위 레이블 누락**: AC-2에 (범위: 단위/통합)이 없음.
- **Given 추상적**: "로그인 시도 시"보다 `provider: 'kakao'`처럼 구체화 권장.

### ✅ Passed
- 형식(설명/구현 범위/완료 조건) 모두 존재.
- 의존성 순서 올바름 (Issue 2 → Issue 3).
- FSD 배치 적절 (`features/auth-login`).
```

## 하지 않는 것

- ❌ **이슈를 직접 수정** — 문제와 수정 방향만 제시한다
- ❌ **근거 없는 취향 지적** — 체크리스트 항목에 걸리지 않으면 적지 않는다
- ❌ **처리 기준 부풀리기** — `[권고]`를 `필수 수정`에 넣지 않는다. 실행을 막는 근거가 있을 때만 `[필수]`다
- ❌ 코드 작성
